# Independent Audit 2 — zram spec audit (Tester)

- **drivers/block/zram/zram_drv.c:1699-1771, 2895-2900** — **MISSING** — `algorithm_params_store()` accepts post-init writes even though compressor parameters are only consumed during `disksize_store()` backend creation. After initialization the write succeeds but cannot affect the live compressor, so the knob is not actually frozen at init like other layout-defining settings. **[Req: inferred — quality/QUALITY.md Scenario 1; Documentation/admin-guide/blockdev/zram.rst §§96-130] NEEDS REVIEW**
- **drivers/block/zram/zram_drv.c:1712-1748, 1767-1771** — **DIVERGENT** — `algorithm_params_store()` silently ignores unknown keys instead of rejecting them; inputs like `foo=1` fall through to `comp_params_store()` and return success. **[Req: formal — quality/REQUIREMENTS.md REQ-005; Documentation/admin-guide/blockdev/zram.rst §§96-126]**
- **drivers/block/zram/zram_drv.c:1267-1325** — **DIVERGENT** — `writeback_store()` cannot honor `type=` together with `page_index`/`page_indexes`: if `type=` appears first it breaks before parsing selectors, and if selectors appear first they are queued under `mode == 0` before the later `type=` is seen. This violates the documented/required “mode plus page range” path. **[Req: formal — quality/REQUIREMENTS.md REQ-008; Documentation/admin-guide/blockdev/zram.rst §§377-392]**
- **drivers/block/zram/zram_drv.c:1439-1447, 1504-1511, 2718-2746** — **MISSING** — `read_from_bdev_async()` drops allocation failures on the floor: if `kmalloc_obj()` or `bio_alloc()` fails, `read_from_bdev()` still returns success, the parent bio is completed normally, and the read page is left without a guaranteed backing-device payload or I/O error. **[Req: inferred — quality/REQUIREMENTS.md REQ-014; quality/QUALITY.md Scenario 7] NEEDS REVIEW**
- **drivers/block/zram/zram_drv.c:2698-2700, 2715** — **MISSING** — `zram_bio_discard()` returns early for a discard wholly contained in the skipped leading fragment, bypassing the only `bio_endio()` call in the function and leaving the bio uncompleted. **[Req: inferred — quality/REQUIREMENTS.md REQ-015; quality/QUALITY.md Scenario 8] NEEDS REVIEW**
- **drivers/block/zram/zram_drv.c:1237-1335, 2526-2677** — **PHANTOM** — the admin-guide documents `-EAGAIN` for simultaneous recompress/writeback attempts, but these sysfs handlers expose no `-EAGAIN` path; they serialize on `dev_lock` instead. The documented error contract is not implemented in the audited code. **[Req: formal — Documentation/admin-guide/blockdev/zram.rst:41-51]**
