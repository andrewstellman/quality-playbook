  - `compressed_writeback` is pre-init-only (`zram_drv.c:552-569`)

- Known inaccuracies before triage:

## Verification probes

### Probe A — post-init `algorithm_params`
- **Question:** does the code reject post-init parameter writes the same way it rejects post-init compressor/backing writes?
- **Ground truth:** no. `algorithm_params_store()` parses input and calls `comp_params_store()` without any `init_done(zram)` check (`zram_drv.c:1699-1771`), while `__comp_algorithm_store()`, `backing_dev_store()`, and `compressed_writeback_store()` all reject post-init writes.
- **Resolution:** `SA-003` promoted to confirmed real code bug.

### Probe B — invalid recompress `type=`
- **Question:** does an unrecognized recompress mode fail, or does it devolve to "all eligible slots"?
- **Ground truth:** it devolves to mode `0`. The `type=` branch in `recompress_store()` has only positive string matches and no default error path (`zram_drv.c:2550-2557`). `scan_slots_for_recompress()` only filters by mode when the respective bits are set (`2337-2375`), so mode `0` scans all non-WB/non-SAME/non-INCOMPRESSIBLE slots.
- **Resolution:** `SA-004` promoted to confirmed real code bug.
