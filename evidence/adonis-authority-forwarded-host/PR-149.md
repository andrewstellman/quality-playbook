`authority()` is documented as not consulting `X-Forwarded-Host` and as unaffected by `trustProxy`, but it fell back to `host()`, which consults both. This makes it fall back to the raw `Host` header, as the JSDoc says, and adds a test next to the existing forwarded-host test (it fails on 9.x and passes with the fix; 669/669 tests pass).

As we discussed in the private report, this isn't a vulnerability. If you'd rather keep the current behaviour and fix the JSDoc instead, I'm happy to change the PR to do that.
