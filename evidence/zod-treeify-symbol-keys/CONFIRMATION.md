BUG-005: z.treeifyError() files symbol-keyed issues under `items` instead of `properties`. Verdict CONFIRMED.
Claim: for k=Symbol("k"), z.object({[k]: z.string()}).safeParse({[k]:1}) → treeifyError puts the issue on an Array tree.items[k]; tree.properties is undefined. Expected tree.properties[k].errors.
Mechanism: errors.ts:446-467 branches on `typeof el === "string"` → properties, else → items (an Array), so a symbol segment lands on items. The return type $ZodErrorTree<T> (errors.ts:408-419) declares `properties?: { [K in keyof T]?: ... }` and keyof T includes symbols. Siblings flattenError (324-334), formatError, toDotPath (514-528, explicit symbol branch) all treat the symbol as an object key. Symbol keys are a supported feature (object.test.ts:931 describe("symbol keys in object shape")). No treeify test with a symbol path (error-utils.test.ts has symbol cases only for toDotPath, 465-472). Fix: branch on `typeof el === "number"` → items, else properties (one line). Doc: error-formatting.md:81 (tree "mirrors the schema"). No upstream issue (closest #4213, #5572, #4976, #2734). No security angle. Severity LOW.
