# Issue #2059: Gson serializes anonymous inner class instance as 'null'

## Status
**Closed** — Not Planned (intentional behavior)

## Description

When serializing an instance of an anonymous inner class without explicitly providing the base class type to `toJson()`, Gson serializes the object as the JSON literal `"null"` regardless of the object's actual content.

This happens because Gson intentionally excludes anonymous classes from serialization as a design choice. When no explicit type parameter is provided to `toJson()`, Gson attempts to discover the type at runtime, encounters the anonymous class, and rejects it as unserializable.

## Problem Demonstration

```java
class MyClass {
    String name = "test";
}

// Case 1: Anonymous class without explicit type
MyClass anon = new MyClass() {
    @Override
    public String toString() {
        return "Anonymous: " + name;
    }
};

Gson gson = new Gson();
String json = gson.toJson(anon);
// Result: "null"  ✗ WRONG — should serialize the object

// Case 2: Anonymous class with explicit type
String json2 = gson.toJson(anon, MyClass.class);
// Result: {"name":"test"}  ✓ CORRECT
```

## Root Cause

Gson intentionally excludes anonymous classes from serialization. This decision is documented in **Issue #298**. The rationale includes:

1. **Runtime type erasure** — Anonymous classes are generated by the compiler with synthetic names, making them difficult to work with consistently
2. **Scope issues** — Anonymous classes defined in method scope are local to that method and can't be reliably reconstructed
3. **Design intent** — The intent to avoid serializing impl details of concrete subclasses
4. **Simplicity** — Excluding them simplifies the type adapter selection logic

When `toJson(Object)` is called without a type parameter, Gson uses the runtime type of the object. For anonymous classes, Gson's type discovery code detects this and refuses to serialize, returning "null" instead.

## Workarounds

### Workaround 1: Explicitly Specify the Base Type
Always provide the class type as a parameter to `toJson()`:

```java
MyClass anon = new MyClass() { /* ... */ };
String json = gson.toJson(anon, MyClass.class);  // ✓ Works
```

This is the recommended approach and aligns with Gson's design philosophy of preferring explicit types.

### Workaround 2: Use a Custom TypeAdapter
Register a TypeAdapter that handles the specific anonymous class or interface:

```java
new GsonBuilder()
    .registerTypeAdapter(MyClass.class, new TypeAdapter<MyClass>() {
        @Override
        public void write(JsonWriter out, MyClass value) throws IOException {
            out.beginObject();
            out.name("name").value(value.name);
            out.endObject();
        }

        @Override
        public MyClass read(JsonReader in) throws IOException {
            // deserialization logic
        }
    })
    .create()
```

### Workaround 3: Extract Data to Non-Anonymous Class
Move the data to a regular class before serialization:

```java
class DataHolder {
    String name;
}

MyClass anon = new MyClass() { /* ... */ };

// Extract data
DataHolder data = new DataHolder();
data.name = anon.name;

// Serialize the holder
String json = gson.toJson(data);  // ✓ Works
```

## Edge Case: Double Brace Initialization

Anonymous classes are created implicitly when using "double brace initialization" pattern:

```java
Map<String, String> config = new HashMap<String, String>() {{
    put("key", "value");
}};

String json = gson.toJson(config);
// Result: "null"  ✗ WRONG

// Workaround:
String json = gson.toJson(config, HashMap.class);  // ✓ Works
```

The anonymous class is created as a subclass of HashMap to initialize the contents in the initializer block.

## Exception: Local Record Classes (Java 16+)

Local record classes are NOT affected by this limitation. They can be serialized without explicitly specifying the type:

```java
record LocalRecord(String name, int age) {}

LocalRecord record = new LocalRecord("Alice", 30);
String json = gson.toJson(record);
// Result: {"name":"Alice","age":30}  ✓ WORKS

// Even without explicit type:
String json = gson.toJson(record);  // Still works for records
```

Record classes have special handling in Gson that distinguishes them from anonymous inner classes.

## Design Philosophy

This behavior reflects Gson's design principle: **explicit type information is more reliable than runtime type discovery for polymorphic types**. The library assumes that developers who need to serialize instances of dynamically-typed objects will provide the necessary type information.

## Impact on Code

Developers using anonymous classes for serialization should:
1. Always provide explicit type parameters to `toJson()`
2. Avoid anonymous classes when serialization is needed
3. Consider using records (Java 16+) or static inner classes instead
4. Register custom TypeAdapters for frequently-serialized anonymous types

## Related Issues

## Migration Path

For code that previously serialized anonymous classes (before the fix was enforced):
1. Identify all uses of `toJson(anonymousInstance)`
2. Replace with `toJson(anonymousInstance, BaseClass.class)`
3. Or refactor to use non-anonymous classes
4. Or implement custom TypeAdapters if serialization is critical

## Version History

This behavior has been consistent across Gson versions due to the explicit design decision. The issue was closed as "Not Planned" because the Gson team considers this the correct behavior for the library's use cases.
