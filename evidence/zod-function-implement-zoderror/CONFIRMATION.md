BUG-015: z.function().implement() and .implementAsync() throw the core $ZodError, not the classic z.ZodError. Verdict CONFIRMED.
Claim: calling an implemented z.function({input:[z.string()],output:z.number()}) with 1 throws an error whose constructor.name is "$ZodError", `instanceof z.ZodError` is false, and .flatten()/.format() are missing; schema.parse throws the classic ZodError. Same for implementAsync.
Mechanism: core/schemas.ts:8 imports parse, parseAsync from core/parse.js, which bind errors.$ZodRealError (core/parse.ts:39,63); implement/implementAsync (core/schemas.ts:4890-4925) call those. Classic ZodFunction (classic/schemas.ts:2741-2748) only calls core.$ZodFunction.init + ZodType.init and never substitutes the classic ZodRealError that classic/parse.ts:13,20 uses for schema.parse. Docs: packages_docs_content_api.md:3444 "This function will throw a `ZodError` if the input is invalid"; changelog lines 215-216 "z.function throws ZodError directly". Tests: function.test.ts:21,27 only assert .toThrow() with no class. Fix options: classic ZodFunction overrides implement/implementAsync to use classic parse/parseAsync, or core accepts an error class in init. Must cover both implement and implementAsync. zod/mini would still get $ZodError, which is fine. No upstream issue (closest #4143, #4334). No security angle.
