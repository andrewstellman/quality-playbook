BUG-022: A constant .catch() value is returned by reference, so mutating one fallback result changes every later one. Verdict CONFIRMED.
Claim: const arr = z.array(z.string()).catch([]); arr.parse(1).push("leak"); arr.parse(1) → ["leak"] (same reference; Map likewise; compiled path likewise). .default([]) returns a fresh clone each parse.
Mechanism: util.ts:1276-1280 constantCatch wraps the constant in a thunk `() => value` tagged CONSTANT_CATCH (comment at 1272 explains the tag distinguishes a constant from a user callback that reads ctx.error; says nothing about cloning). .default() shallow-clones on every read (api.ts:1527, classic/schemas.ts:2406) — established by merged PRs #5173 ("ensure array defaults are shallow-cloned") and #5855 ("clone Map and Set in shallowClone to prevent shared state across .default() parses"); neither mentions .catch(). Tests: default.test.ts:315-375 pins clone-on-read for default (object, array, Map, Set); catch.test.ts has no identity test. Fix: constantCatch's thunk returns util.shallowClone(value) while keeping the CONSTANT_CATCH tag; must not alter the user-callback path. Check compile.ts for a separate constant-catch path. Doc: api.md:3225 only. No upstream issue (all about .default(): #5826, #5173, #5855, #3988). No security angle.
