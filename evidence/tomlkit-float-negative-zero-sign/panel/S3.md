2. The Summary is about twice as long as the change needs. Five paragraphs plus a code block for a one-clause fix. Cut the paragraph "The trigger is narrow..." down to one sentence, and cut the "Cause:" paragraph's restatement of the diff ("Fix: add the `+` only when..." is the diff again; the commit and code comment say it a third time). Suggested body (about 12 lines instead of 25):

   ```
   ## Summary

   Arithmetic on a float written with an explicit sign renders `+-0.0` when the result is negative zero, and tomlkit cannot parse its own output.

   ```python
   import tomlkit

   doc = tomlkit.parse("x = +0.0")
   doc["x"] *= -1
   print(doc.as_string())          # x = +-0.0, expected x = -0.0
   tomlkit.parse(doc.as_string())  # InvalidNumberError: Invalid number at line 1 col 9
   ```

   `Float._new` adds `+` when `self._sign and result >= 0`, and `-0.0 >= 0` is `True` while `str(-0.0)` is already `"-0.0"`. A signed integer reaches the same line through true division (`n = +0`, then `n /= -1`). This is the line #345 changed for #341; negative zero was not covered there. The fix skips the `+` when `str(result)` already starts with `-`.

   TOML 1.1.0 says "Float values `-0.0` and `+0.0` are valid and should map according to IEEE 754", and the ABNF allows one optional sign (`dec-int = [ minus / plus ] unsigned-dec-int`).
   ```
