## Findings

1. Test does not assert the actual symptom (round-trip). Medium. The bug that matters is that tomlkit cannot parse its own output (PR.md: `InvalidNumberError`). The test only compares strings. A regression that wrote some other unparsable string for negative zero (say `-+0.0`) would fail the string check too, so this is not a coverage hole today. But the PR text leads with the parse failure and the test never exercises it. Add one line after the first assertion, in the same style as the file:
   `assert parse(doc.as_string())["a"].as_string() == "-0.0"`
   Optional: the string assertion alone is sufficient to catch a revert. I would add the parse line because it proves the user-visible failure.

2. The comment states the old behaviour in the past tense ("used to render"). tests/test_items.py:1455. Neighbouring tests (`test_no_extra_minus_sign`, 1438) carry no comment, and the surrounding file uses docstrings (`"""Test custom encoders..."""`, line 1403) when it explains. A "used to" comment goes stale the moment the fix lands. Replace with a present-tense reason or delete. Exact replacement:
   `# -0.0 >= 0 is True, so a signed float must not get a "+" prefix.`
   That is the same fact as the source comment at items.py:879, so the cheaper option is to delete the test comment and rely on the test name plus the source comment.

3. (Required, either form.) Three scenarios in one function, and the third is a different code path with no marker. Lines 1459-1463: Float `*=` (via `Float._new` from `Float.__mul__`), the flip back to `+0.0`, and an Integer `/=` (via `Integer.__truediv__`, items.py:832-836, which calls `Float._new(self, result)` on an Integer). A reader sees `parse("a = +0")` and does not know why `+0` and `/=` are chosen. Either add a short comment, `# Integer true division also goes through Float._new.`, or split it into `test_no_extra_plus_sign_on_negative_zero` (Float) and a second small test for Integer. Splitting also fixes the red-log gap noted above: with a split, red.log shows both paths failing on base. This is the one I would require, in one form or the other.

4. The flip back to `+0.0` (lines 1459-1460) is the best part. It checks that the "sign was explicit" memory survives (`raw` "-0.0" still has `_sign` True, so the new `not raw.startswith("-")` guard does not suppress the `+` for a positive result). Keep it. It is the only assertion in the test that protects against over-correcting (for example someone "fixing" this by dropping the `+` rule entirely). Consider saying so in the test with nothing more than the existing assertion order; no change needed.

5. Missing cases a regression test could cheaply include, none required: unsigned source (`a = 0.0`, `-x` gives `-0.0`; this passes on base, so it is a pin, not a regression test), and `-0.0 * 1` from a minus-signed source (CONFIRMATION lists it as a failing case on base: `'x = -0.0' x * 1 -> 'x = +-0.0'`). That last one is a different entry route (source already negative zero, result negative zero, no sign flip), and the test never builds it. If only one extra case is added, add this one:
   `doc = parse("a = -0.0")`
   `doc["a"] *= 1`
   `assert doc.as_string() == "a = -0.0"`

6. Naming and placement are fine. The name matches `test_no_extra_minus_sign` directly above it, the new test sits right after it, and `parse` and `-> None` follow the file's idiom. `ruff` was not run by me; lint.log exists in the packet and I did not read it.
