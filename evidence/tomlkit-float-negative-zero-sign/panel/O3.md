### Findings

1. The fix is correct and minimal (`tomlkit/items.py:880`). The three clauses are each needed. `result >= 0` keeps a NaN
   result on a signed source as `nan` (dropping it would give `+nan`, a behaviour change). `not raw.startswith("-")` is
   false only for `-0.0` once `result >= 0` holds, so nothing else can change. The PR's five "renders as before" claims
   and both `+-0.0` examples reproduce exactly (rows `pr` above; `InvalidNumberError: Invalid number at line 1 col 9`
   matches the PR comment). No change required.

2. Residual, NOT in scope, do not fold in. `Integer._new` (`tomlkit/items.py:655`, `if self._sign and result >= 0:`)
   has the same condition and still writes `+-0.0` on the fixed tree for `a = -2` then `doc["a"] **= -1075`, and for
   `a = -10` then `**= -325` (rows `o3 int`). The cause there is different: `Integer.__pow__` with a negative exponent
   gets a float back from `int.__pow__` and hands it to `Integer._new`, which builds an `Integer` item holding a float
   raw (`a = +2` then `**= -1` gives `a = +0.5` with `type=Integer`, same on base). The right fix is in `__pow__`, not a
   second `startswith` guard, and it needs an odd negative exponent large enough to underflow, so it is not worth a line
   in this PR. Nothing in PR.md or the commit message claims every `+-` is gone (both name `Float._new`), so no text
   change is required. If the operator wants to pre-empt a reviewer who finds it, do not add anything; answer in review.

3. Optional text change, PR.md "The trigger is narrow. The source value must carry an explicit `+` or `-`, and the
   result must be negative zero." True as written, but the only example is `+0.0` times `-1`, which reads as contrived.
   Every negative literal carries an explicit sign, so `x = -1.5` times `0` and `x = -0.0` times `1` are triggers too
   (both run above, base `+-0.0`, fixed `-0.0`). Replacement for those two sentences:

   > The source value must carry an explicit `+` or `-`, and the result must be negative zero. Every negative literal qualifies, so `x = -1.5` followed by `doc["x"] *= 0` gives `+-0.0` as well.

   This drops "The trigger is narrow." and adds no length. Not blocking.

4. Test (`tests/test_items.py:1454-1464`). The second assertion (`-0.0` times `-1` must give `+0.0`) is the useful
   guard: it fails if someone "simplifies" the condition to `result > 0`, which would lose the sign on positive zero.
   The third block pins the Integer true-division entry. Not built by the test: a `-0.0` source kept negative
   (`-0.0 * 1`), `round()`, underflow, reflected operators, array elements. All go through the same line and all pass
   in my sweep, so I do not ask for more test lines.

### Side-effect rule

No user who relied on the old output can exist in a working state: the old output for the changed cases was `+-0.0`,
which tomlkit and the TOML grammar reject. In-memory values are unchanged (the float was already `-0.0`); only the raw
text changes. Nothing to drop.
