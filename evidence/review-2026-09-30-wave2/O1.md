### pyd-033
Verdict: FIX-REQUIRED
Confidence: medium
Findings:
1. Behaviour change not stated. `_generate_schema.py:1424-1429` pushes the TypedDict's own config, which replaces the parent's (`ConfigWrapperStack.push`). Take a model with `ser_json_bytes='hex'` and a TypedDict field that has its own config (say only `str_to_lower`): after this patch, that field's bytes serialize as utf8, not hex. The validator (`validators/typed_dict.rs:56-58`) and `serializers/.../dataclass.rs:102-103` ignore the parent config entirely, while this patch falls back with `.or(config)`. Either mirror them (`let config = schema.get_as(...)?; config.as_ref()`, with the same comment as dataclass.rs) or reword to "uses the schema's config when present". I'd mirror. It's one fewer concept, and generated schemas always carry `config`.

After reading CONFIRMATION: the fixer says "own config REPLACES the parent (QPB patch merged them)". The code does `.or()`, which also replaces when own config exists, so finding 2 is about wording/consistency, not correctness. Finding 1 stands.

### jav-011
Verdict: REJECT (as a code change; resubmit as a docs fix or ask the maintainer first)
Confidence: high
Findings:
1. #2616 (2026-07-31) is a user who copied `staticFileConfig.precompressMaxSize = 0;` from the docs and served huge download files, which caused an OutOfMemoryError. tipsy fixed it in #2618 by streaming. 2. Better submission: a PR to the javalin.io docs repo. Change the example to `-1` (or a real size), and change the comment to "(-1 to disable)". Or open a short issue asking which one tipsy wants.
3. If the code route is kept anyway, the PR must state the memory consequence (every file is cached in heap regardless of size) and link #2616/#2618.
After reading CONFIRMATION: the confirmer could NOT reproduce "chunked, no Content-Length" (a 216 KB file got a Content-Length). The PR text still claims it, so it must be removed in any version.
