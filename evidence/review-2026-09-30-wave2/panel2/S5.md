### st-024 (side-effect check)
Verdict: DROP (side effect), medium confidence; SHIP is arguable.
Measured (fake project: src/pkg 100 .py, tests 50 .py, venv/ 300 .py, node_modules/ 300 .js, .tox/.venv/.git/ 300 files each, .hidden/secrets.py, docs/_build; setup.py sdist, base vs fixed):
- MANIFEST.in `include **/*.py`: base sdist 115 entries, 4 KB; fixed 469 entries, 12 KB; 305 of the new entries are venv/ files, plus `.hidden/secrets.py`. Time 0.23s -> 0.32s (2.5k files; walk cost is minor at this size).
- `include src/**/*.py` + `include **/*.js`: base 62 entries (warning: no files found matching '**/*.js'); fixed 417, 304 under node_modules/.
- .tox/, .venv/, .git/ files did NOT land in the sdist in my run although glob returns them (not investigated why; do not count on it).
Side effects:
- Who: any project whose MANIFEST.in has `include` with `**` that today matches little (documented as recursive, so silently under-matches). If they never noticed (files shipped another way) the next upgrade makes sdists include venv/, node_modules/, any hidden dir content, and for `include **` anything (.env, keys). No error, no warning; the user finds out from sdist size, a PyPI 100 MB rejection, or a leak.
- Likelihood: low to moderate. Pattern must exist and be misbehaving today. Impact when it hits: high (secret/data leak in a published sdist), silent, and discovered after release. The newsfragment warning only helps people who read it before upgrading.
- Benefit side: small; recursive-include/global-include already do the job. Docs line 113 does say `**` crosses slashes, so the fix matches docs, but setuptools has historically treated bug-compat as binding (the #4183 Hyrum's law thread).
Findings: 1. test_manifest passes with the change (S5 first panel: 70 passed). 2. If Andrew decides to keep it, make it opt-in or land it in a major/ with an egg_info warning; the current PR/newsfragment text is accurate on the risk.
