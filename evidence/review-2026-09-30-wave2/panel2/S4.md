### addr-032
Verdict: SHIP (side effect borderline, acceptable only because disclosed)
Side effects:
- `{+v}` / `{#v}` (also `{+v*}`, lists, hashes, partial_expand) now pass `%XX` triplets through: `%20a%2Fb` was `%2520a%252Fb`. Who: callers who feed already-encoded values (they were getting double encoding: bug fixed for them). Hurt: callers who pass raw text that happens to contain `%` + 2 hex digits ("a%0d%0ab", "%00", "100%AB") and relied on it being neutralised; now `%0d%0a`/`%00` reach the URL. - `extract(expand(v))` no longer round-trips for pre-encoded v (`%20a%2Fb` -> `" a/b"`). Disclosed. acceptable
- Plain `{v}` unchanged; lone `%` still `%25` (verified `%`, `100%`, `%4`, `%4G`, `%%41`, `%41%`, multibyte, empty).
Findings:
1. Red: 4 failures on base ({+pct}, {+badpct}, {+pctlist*}, {#pct}); green: template_spec 330/0, full rspec 1437/0 (5 pending).
2. Edge diff base vs fixed (16 values x 8 operators): only `+`/`#` rows change, all as described; `{;v}`, `{/v}`, `{?v}`, `{.v}`, `{v}` identical.
3. PR text could add one clause: also applies to lists/hashes and partial_expand. Not blocking.

### st-024 (side-effect check only)
Verdict: DROP (side effect) -- lean, arguable
Side effects:
- Measured on a realistic layout (pkg/, tests/, docs/, `.github/`, `venv/` 600 files, `node_modules/` 200 files, `.tox/`, `.git/`; MANIFEST.in = `include **/*.md` + `include **/*.txt`; `setup.py egg_info`): base SOURCES.txt 11 lines, fixed 813; 801 of those under venv/ and node_modules/. Hidden dirs: `.github/workflows/ci.md` and (in a second probe) `.hid/n.txt` are now included; `.git` and `.tox` stayed out of SOURCES.txt even though setuptools.glob returns their files (cause not investigated).
- `include **` (bare) and `include dir/**` now mean the whole tree (`a/**`: base [a/b, a/y], recursive [a/, a/b, a/b/z, a/y]).
- Who: anyone whose existing MANIFEST.in has a `**` include line and who builds an sdist from a working tree with venv/, node_modules/, or hidden dirs (typical for frontend-bundling projects, local `python -m build`, release scripts). What happens: silently larger sdist, possibly publishing unintended files (hidden config, .env-style files matching the pattern) to PyPI, or a PyPI size rejection at release time; no error or warning. Fresh-clone CI builds are mostly unaffected. Likelihood: low to moderate; people with such lines are exactly those happy with the old shallow behaviour. Impact on the unlucky: a bad published artifact is hard to undo. No opt-out.
- The newsfragment/PR warning discloses it but does not protect users who do not read it before upgrading.
Findings:
1. Code is correct per docs and exclude; test_manifest.py 70 passed; base fails only the new test. Not a bug-fix problem, purely the rule.
2. If Andrew wants to keep it: it would need to ship as an opt-in or in a release the maintainers mark as behaviour-changing; as a plain bugfix newsfragment I would drop it under his rule.
