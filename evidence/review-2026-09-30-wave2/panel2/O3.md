### addr-032
Verdict: SHIP
Side effects:
- `{+v}`/`{#v}` values that contain `%XX` (including in list items and hash keys/values) now pass through instead of becoming `%25XX`. Who is hurt: anyone who puts literal text containing `%XX` into reserved expansion, for example a storage key literally named `report%20final`. The URL changes silently (to `%20`), which can lead to a 404 or the wrong resource. Likelihood: low. `{+}` already passes `?`, `#` and `/` raw, so such callers are already outside its contract. RFC 6570 requires this behaviour. Acceptable, but this is the most user-visible change of the four code fixes, and the PR line should keep stating it.

Invalid UTF-8 raises ArgumentError on both (not new).
2. `{+v:2}` of `%20ab` → `%252` on both. The prefix splits the triplet before encoding. Not a regression.

### st-024
Verdict: DROP (side effect). Confidence: medium. This is a judgement under Andrew's rule, not a correctness defect.
Side effects (measured): I built a realistic project with src layout, tests/, docs/, .git/, `.venv/` and `venv/` (200 .py each), `env/`, `node_modules/left-pad` (50 json, 50 md), .tox, .mypy_cache, .pytest_cache, .eggs and build/. I ran `setup.py sdist` and diffed the tarball contents:
- `include **/*.py`: 13 → 264 files (+200 venv/, +50 env/, +1 .eggs/)
- `include **/*.json`: 12 → 66 (+51 node_modules/, +1 .mypy_cache/, +2 wanted src/)
- `include **/*.md`: 12 → 65 (+50 node_modules/, +1 .pytest_cache/, +1 .github/, +1 wanted docs/api)
- `include **/*.txt`, `include **/py.typed`: unchanged. `include src/**/*.json`: +1, which is the wanted file.
sdist prunes only root `.venv/.tox/.nox`, build/ and VCS dirs (sdist.py:165-169, distutils sdist.py:388-400). `venv/`, `env/`, `node_modules/` and cache dirs go in.
Who is affected: these patterns exist in real projects. grep.app finds 19 MANIFEST.in hits for `include **/`, e.g. `include **/*.json` + `include **/*.md` (redhog/pieshell), `include **/*.cpp`/`*.cu` (primeqa), `include **/*.h` + `include **/**/*.h` (rabbitizer), `include **/*.pth` (rdiff-backup). The rabbitizer line shows users know `**` is one level today and have written around it. The `*.pth` and `*.h` patterns would pick up venv contents, since site-packages ships `.pth` files and numpy ships `.h` headers. Harm happens only when untracked deep dirs sit in the tree at sdist time: local maintainer builds, or CI that creates `venv/` in the checkout.
Why drop: the harm is silent (the newsfragment is the only signal) and irreversible once uploaded. A PyPI version cannot be replaced, and unwanted files such as a secrets json in a deep ignored dir would be public. A huge venv would hit the upload limit and get noticed; a few stray files would not. The upside is small: the users who wanted recursion already use `recursive-include`/`graft` or `**/**`. Less risky alternative: a docs PR or an issue that makes the docs say `include` `**` matches one level, and lets the maintainers choose.
Findings:
1. The code is correct per the docs. I confirmed this last round, and test_manifest passes 70/70.
