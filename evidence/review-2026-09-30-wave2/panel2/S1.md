### st-024
Verdict: DROP (side effect)
Side effects: measured. Layout: src/pkg/b.txt, docs/c.txt, tests/t.txt, README.txt, venv/.../foo/{LICENSE,x}.txt, node_modules/x/{y,docs/readme}.txt, .tox/py/lib/z.txt, build/lib/q.txt, .git/hooks/h.txt; MANIFEST.in = `include **/*.txt` + `include docs/**/*.rst`. Ran FileList.process_template_line on base vs fix tree (st-venv, PYTHONPATH=tree):
  BASE : ['docs/c.txt', 'tests/t.txt']  (+ "warning: no files found matching 'docs/**/*.rst'")
  FIXED: ['.git/hooks/h.txt', '.tox/py/lib/z.txt', 'README.txt', 'build/lib/q.txt', 'docs/c.txt', 'docs/index.rst', 'node_modules/x/docs/readme.txt', 'node_modules/x/y.txt', 'src/pkg/b.txt', 'tests/t.txt', 'venv/lib/python3.12/site-packages/foo/LICENSE.txt', 'venv/lib/python3.12/site-packages/foo/x.txt']
  So an existing, silently-working `include **/*.txt` goes from 2 files to 12, pulling .git, .tox, build/, venv/, node_modules/ into the sdist on the next upgrade with no error. Bad: bloated sdists (a project-local venv is common), possible upload of files the author never meant to ship (hidden dirs, vendored licences/secrets in txt/json/cfg patterns), and no warning other than a newsfragment most users never read. Affected: anyone with `**` in an `include` line AND untracked trees in the project dir; moderate-low likelihood, high surprise, hard to notice.
  Counter-point: those users wrote `**` expecting recursion, and the docs say so; but the old behaviour was bounded and the new one is not, and `prune` is the only guard. Under Andrew's rule (correct per spec but hurts existing users unexpectedly) this is a drop; if Andrew prefers to keep it, it needs at least hidden/venv skipping, which is a larger change than the 1-line fix.
Findings:
1. egg_info.py:448 one-line change itself reads fine; the issue is behavioural, not readability.
2. Disclosure in newsfragment/PR is good but does not mitigate the silent change.
