### addr-032
Verdict: DROP (side effect). Andrew's call; my confidence is medium.
Side effects (scratch, GitHub's `contents_url` template `.../contents/{+path}`):
- A value with a literal `%XX` changes meaning silently. `"docs/a%20b.md"` gives base `.../a%2520b.md` (the right file) and fixed `.../a%20b.md` (a different file, `a b.md`). Who: callers that pass raw strings into `{+}`/`{#}`. That includes Sawyer, which expands every hypermedia relation with `Addressable::Template` (sawyer relation.rb:112, :244). Octokit's own `contents` uses string interpolation, so it is not affected. Rare per call, but addressable is a near-universal dependency, and nothing errors. → bad
- An encoded dot-segment now survives. `"x/%2e%2e/secret"` gives base `.../x/%252e%252e/secret` and fixed `.../x/%2e%2e/secret`, and `Addressable::URI#normalize` turns the fixed URL into `.../contents/secret`. An app that filters `..` but not `%2e%2e` was protected by the double encoding and is not after this change. `{+}` already passes a raw `../`, so this is not a new capability in general, but it is a new hole for that filter pattern. → bad
- Users who pre-encode get correct URLs (the intended fix). Anyone who worked around the bug by passing decoded values is unaffected.
Findings:
1. The code revision is fine (constant, hex class, specs). The problem is the class of user who would not expect a minor release to change their URLs. "Correct per RFC 6570 §3.2.1, can hurt existing users in a way they would not expect" is exactly the rule's drop case.
2. If Andrew keeps it anyway, the PR "Behaviour change" line must also name the literal-`%XX` case and the `%2e%2e` case, not just round-trip extract. A better route is an issue asking sporkmonger whether he wants it in a major release.

### st-024
Verdict: DROP (side effect)
Measured: a realistic project with src/ layout, tests/, docs/, `venv/` (`python -m venv --without-pip`, plus _pytest and pluggy copied in), `frontend/node_modules/`, `.mypy_cache/`, `.idea/`, `.pytest_cache/`. sdist built with the tree's setuptools, base vs fixed:
| MANIFEST.in | base files | fixed files | added |
|---|---|---|---|
| `include **/*.json` | 14 | 19 | 3 node_modules files, `.mypy_cache/3.11/…json`, `src/mypkg/data/a.json` (the only intended one) |
| `include src/**/*.css` | 12 | 13 | `src/mypkg/static/css/s.css` (intended) |
| `include **/*.py` | 12 | 184 | 172 venv files: `lib/` **and** `lib64/` (Linux venv symlink, so each file twice) |
| `include **/*.txt` | 13 | 14 | `log.txt`: a stray root file that base also skipped, because base's `**/*.txt` = `*/*.txt` |
For scale, a normal venv (st-venv) holds 3002 `.py` files, so roughly 6000 sdist entries with the lib64 duplication. `sdist.prune_file_list` (sdist.py:169) prunes only root `.tox|.nox|.venv`, not `venv/`, `env/`, `node_modules/` or caches.
Side effects:
- Projects with an `include` line using `**` and any `venv/`, `node_modules/` or cache dir in the tree: on a setuptools upgrade, the sdist silently grows by hundreds to thousands of files, possibly including local junk or secrets in hidden dirs. Once uploaded to PyPI it cannot be undone. Usage of `include **` is probably uncommon, but the trigger dirs are common in local builds, and in CI that runs `npm ci` before `python -m build`. → bad
- The narrow form (`include src/**/*.css`) only gains intended files. → acceptable on its own, but the patch cannot tell the two apart.
Findings:
1. The newsfragment's disclosure is honest, but users do not read setuptools changelogs before a routine upgrade, and abravalheri's own stated stance (#4183, "Hyrum's law ... backlash") predicts this objection.
2. No upstream issue asks for this change (searched). Open docs PRs #5261 and #5313 are adding MANIFEST.in pitfall docs. A safer route is a docs note there ("in `include`, `**` matches one level; use `recursive-include` or `graft`"), which changes no sdist.

## Overall
SHIP: cobra-016, st-004, addr-011. DROP under Andrew's rule: st-024 (measured silent sdist growth, 12 → 184 files with a small venv) and addr-032 (a literal `%XX` silently becomes a different URL; `%2e%2e` gets past `..` filters). addr-032 is the closer call.
