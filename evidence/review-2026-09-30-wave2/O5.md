### addr-011
Verdict: FIX-REQUIRED
Confidence: high
Findings:
1. **The fix introduces a new exception.** I ran this in a scratch clone:
   `URI.parse("http://example.com/a:b").route_from("http://example.com/a:b?x=1")`
   - fixed tree: `InvalidURIError: Cannot assemble URI string with ambiguous path: 'a:b'` (uri.rb:2348, raised from route_from at :2133)
   - base: `""`
   A last segment that contains `:` must be emitted as `./a:b` (RFC 3986 §4.2). Fix it, for example with `"./" + seg if seg.empty? || seg.include?(":")`, and add a spec for it.
2. The new `'./'` spec uses `.to_s` / `eq("./")`, while its neighbours use `eq(Addressable::URI.parse(...))`. That's probably deliberate, because a normalized `./` may compare equal to `""`. If so, the inconsistency is justified, but a reviewer will ask. Be ready to answer.
3. The text is proportionate. The #126 quote (per CONFIRMATION) supports the round-trip claim.
