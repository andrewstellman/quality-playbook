## Side-effect check

The new line runs only when fromISO, fromRFC2822, fromSQL and the fromFormat pattern all returned invalid. Before the fix those inputs threw `CronDate: unhandled timestamp`. So the change can only turn a thrown error into a date. Affected: callers who pass a string that is neither ISO, RFC 2822, SQL nor `EEE, d MMM yyyy HH:mm:ss` but is valid HTTP (RFC 850, asctime, and any other string fromHTTP accepts). If someone relied on the throw to reject such strings as input validation, they now get a date. Likelihood: very low; these are obsolete formats. The asctime form is read as GMT even with a `tz` option (PR.md says so and asks the maintainer). Not a drop reason.
