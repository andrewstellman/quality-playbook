BUG-003: Intersection throws from safeParse when both operands pass the same NaN through. Verdict CONFIRMED.
Claim: z.intersection(A,B).safeParse(v) where both sides emit the same NaN (looseObject∩looseObject with extra c: NaN; z.unknown().and(z.unknown()).safeParse(NaN); z.nan().and(z.nan()).safeParse(NaN)) throws "Unmergable intersection"; expected success with NaN carried through.
Mechanism: mergeValues (packages/zod/src/v4/core/schemas.ts:2833) uses `if (a === b)`; NaN !== NaN. Same in v3 (v3/types.ts:3245). v4 changelog (packages_docs_content_v4_changelog.md:735-737) says unmergable results throw because "an intersection of two incompatible types" — that rationale does not hold for identical NaN. Fix: Object.is(a, b) (or a===b || (a!==a && b!==b)). No test exercises NaN through an intersection (intersection.test.ts:158-160 pins the throw only for genuinely conflicting values). Frame the PR as "identical NaN is wrongly classified as unmergable", not "safeParse should never throw". No upstream issue (closest #5133, #3196). No security angle. Severity LOW; z.nan().and(z.nan()) being unsatisfiable is the sharpest form.
