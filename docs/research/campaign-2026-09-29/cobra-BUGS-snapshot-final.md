### BUG-001: Value of a shorthand cluster's last flag is taken as a subcommand name

- Source: Code Review (Phase 3); Traverse site added by Spec Audit (Phase 4)
- Severity: MEDIUM
- Challenge gate: CONFIRMED — quality/challenge/BUG-001-challenge.md
- Primary requirement: REQ-001
- File:line: `command.go:695-703` (related sites: command.go:695-703 (stripFlags), command.go:731-735 (argsMinusFirstX), command.go:757-779 (Find), command.go:834 (Traverse short-flag rule; added by the Phase 4 spec audit, auditor gpt-5.5))
- Divergence type: code-spec · Disposition: code-fix · Fix type: code
- Spec basis: README (background): "Fully POSIX-compliant flags (including short & long versions)"; POSIX Utility Syntax Guideline 5 lets the last option of a group take the next argument. REQ-001.
- Documented intent: Command lookup must skip the word consumed by the last value-taking flag of a shorthand cluster, as pflag does, so `root -vf x.txt sub` runs `sub` with --file=x.txt.
- Code behavior: `stripFlags` only treats a token as consuming the next word when `len(s) == 2` (command.go:695); `-vf` (len 3) consumes nothing, so `x.txt` becomes the first command word and Find (command.go:761-771) fails to find it; `legacyArgs` then reports `unknown command "x.txt" for "root"` (args.go:35-36). Traverse applies the same two-character rule (command.go:834), so with TraverseChildren `root -vf x.txt sub` stays at the root (auditor gpt-5.5, confirmed by triage probe).
- Reproduction: root has persistent bool -v and string -f, subcommand sub: `root -vf x.txt sub`
- Expected: sub runs with --file=x.txt
- Actual: Error: unknown command "x.txt" for "root"
- Reachability: No guard: stripFlags is called unconditionally by Find (command.go:761) for every Execute without TraverseChildren, and the len(s)==2 test at command.go:695 is the only value-consumption rule for single-dash words; nothing upstream normalizes clusters.
- Regression test: `TestBug001_ShorthandClusterValueIsNotASubcommand` in quality/patches/BUG-001-regression-test.patch (mirror: `quality/test_regression.go`, subtest `TestRegressions/BUG-001`)
- Fix patch: quality/patches/BUG-001-fix.patch — Add shortFlagsConsumeNextArg, which walks the cluster and reports whether the first value-taking flag is the last letter; use it in stripFlags, argsMinusFirstX and Traverse (and drop the now-unused shortHasNoOptDefVal).
- Writeup: quality/writeups/BUG-001.md
- Closure status: TDD verified (FAIL→PASS)

### BUG-002: With TraverseChildren, a subcommand name after `--` is still executed

- Source: Code Review (Phase 3)
- Severity: MEDIUM
- Challenge gate: CONFIRMED — quality/challenge/BUG-002-challenge.md
- Primary requirement: REQ-002
- File:line: `command.go:828-832` (related sites: command.go:821-860 (Traverse))
- Divergence type: code-spec · Disposition: code-fix · Fix type: code
- Spec basis: Find treats `--` as the end of flags (command.go:688-690); POSIX/pflag: arguments after `--` are operands. REQ-002.
- Documented intent: Traverse must stop at `--` so that routing selects the same command as Find for the same argv.
- Code behavior: Traverse has no `--` case: `--` matches `strings.HasPrefix(arg, "--")` with name "" so `inFlag` becomes true (command.go:828-832), the next word is swallowed as a flag value and a later word is looked up as a subcommand.
- Reproduction: root `app` (TraverseChildren, Run) with subcommand `sub`: `app -- x sub`
- Expected: app runs with args [x sub]
- Actual: sub runs with args [] — `x` is silently dropped
- Reachability: No guard: ExecuteC calls Traverse for every execution when TraverseChildren is set (command.go:1120-1121); no earlier step strips or special-cases `--`.
- Regression test: `TestBug002_TraverseStopsAtDoubleDash` in quality/patches/BUG-002-regression-test.patch (mirror: `quality/test_regression.go`, subtest `TestRegressions/BUG-002`)
- Fix patch: quality/patches/BUG-002-fix.patch — Return from Traverse at `--`, leaving all remaining args to the current command.
- Writeup: quality/writeups/BUG-002.md
- Closure status: TDD verified (FAIL→PASS)
