## Candidate detail

### 1–5, 9. expressjs/express (v5.2.1 quality run → current `master`)

- **Upstream:** https://github.com/expressjs/express
- **Historical path:** `/sessions/kind-zealous-edison/mnt/QPB/repos/express-1.5.8/quality/BUGS.md` (6 bugs; run dated 2026-06-19, Phase 3 code review, `lib/` source boundary)
- **Historical verification level:** source-only code review with `it.skip(...)` regression-test stubs in `quality/test_regression.js` (not executed against a running server in the historical run) plus fix/regression `.patch` files. No claim of prior execution.
- **Fresh currency check:** `git clone --depth 1 https://github.com/expressjs/express.git` → HEAD `9a34acf03cb818ff3f8bc40e44176e277a25cbb9`, committed 2026-09-15. `package.json` version `5.2.1` — same release the historical run audited.
- **Per-bug file:line and expected-vs-actual** (all confirmed byte-for-byte against fresh HEAD, though absolute line numbers drift slightly from the historical citation because of unrelated master commits):
  - **BUG-001** — `lib/request.js`, `protocol` getter: `var index = header.indexOf(',')` then `index !== -1 ? header.substring(0, index).trim() : header.trim()`. For a trusted `X-Forwarded-Proto: ", https"`, this returns `''`, and `req.secure` (`return this.protocol === 'https'`) reads `false` for a genuinely secure request. Expected behavior rests on the getter's own doc comment ("this is to be safe") plus the implicit contract that `protocol` ∈ {`http`,`https`}.
  - **BUG-006** — `lib/request.js`, `host` getter: same shape — `val.substring(0, val.indexOf(',')).trimEnd()` is `''` for a leading comma, and `return val || undefined` turns that into `undefined`; `hostname`/`subdomains` cascade to `undefined`/`[]`.
  - **BUG-005** — `lib/utils.js`, `acceptParams`: `str.indexOf('=' / ';')` has no quoted-string awareness (`text/html;x="a;b";q=0.5` truncates the quoted value at the inner `;`), and `ret.quality = parseFloat(value)` is unclamped (`q=5` survives as `quality: 5`). RFC 7231 §3.1.1.1 (media-type parameter grammar) and §5.3.1 (`q` range) are the spec basis.
  - **BUG-002** — `lib/response.js`, `res.cookie`: `opts.maxAge = Math.floor(maxAge / 1000)` floors any `0 < maxAge < 1000` to `0` while `opts.expires` is set to a future `Date`; browsers preferring `Max-Age` delete the cookie immediately instead of honoring the sub-second lifetime.
  - **BUG-003** — `lib/response.js`, `res.redirect`: builds body/title from `statuses.message[status]`, which is `undefined` for an in-range but unassigned status (e.g. 218, 310, 419) that `res.status`'s own range guard (100–999) otherwise accepts — produces literal `"undefined. Redirecting to …"` text and `<title>undefined</title>`.
  - **BUG-004** — `lib/response.js` `res.send` (string branch calls `setCharset(type, 'utf-8')`, forcing an overwrite) vs the Buffer branch and `res.set`/`res.header` (only add a charset via `mime.contentType()` when absent, never overwrite) — confirmed both code shapes unchanged in `lib/response.js` and `lib/utils.js`'s `setCharset`. This one is real but more a documented-intent gap than an unambiguous defect (no `History.md` line says the two paths must agree) — hence rank 9, not top-5.
- **Quick-merge signals:** repo is very active (commit merged 2026-09-15, 12 days before this scan); `.github/CONTRIBUTING.md` exists and expects tests. No PR-collision search was done for any of the 6 IDs — that's the next step before drafting a PR, not done here.

### 6. psf/requests — BUG-001 status-code alias collision

- **Upstream:** https://github.com/psf/requests
- **Historical path:** `/sessions/kind-zealous-edison/mnt/QPB/repos/secbench2_widenet/wn-py-10-requests/quality/BUGS.md` (run dated 2026-06-22, Phase 3 code-only review)
- **Historical verification level:** the historical writeup claims direct execution (`python3 -c "import requests; print(requests.codes.uri_too_long)"` → `414`) plus a TDD RED→GREEN cycle in a disposable worktree with `pytest --runxfail`.
- **File:line:** `src/requests/status_codes.py` — the `_codes` dict registers `122: ("uri_too_long", "request_uri_too_long")` and, later in iteration order, `414: ("request_uri_too_large", "uri_too_long")`. `_init()` does `setattr(codes, title, code)` for every title in dict-insertion order, so the later (414) binding of `uri_too_long` wins over the earlier (122) one.
- **Expected behavior rests on:** the canonical public `requests.codes` contract (each alias token should resolve to exactly one status; `uri_too_long` is documented/expected to mean HTTP 122, the obscure "legacy" WebDAV-adjacent code, not 414).
- **Fresh currency check:** cloned `https://github.com/psf/requests.git` → HEAD `611c6162cbc4ac2020a2f91c7cfa4f3abf9bbb60`, committed 2026-09-21. Confirmed the same two dict entries verbatim, then **executed** inside the fresh checkout:
  ```
  python3 -c "import sys; sys.path.insert(0,'src'); import requests; print(requests.codes.uri_too_long)"
  # -> 414
  ```
  This is the one candidate in this batch independently re-executed, not just source-diffed.
- **Quick-merge signals:** repo has ongoing dependency-bump commits (most recent commit at clone time was a Dependabot actions bump), so it's maintained, but no evidence of how actively feature/bugfix PRs get triaged; no `CONTRIBUTING.md` found at repo root in a quick `find`. Severity is genuinely low-impact (rarely-used alias), which may affect a maintainer's appetite — worth flagging honestly rather than oversell.

### 7–8, 10. open-telemetry/opentelemetry-java-instrumentation — semconv host/authority parsing

- **Upstream:** https://github.com/open-telemetry/opentelemetry-java-instrumentation
- **Historical path:** `/sessions/kind-zealous-edison/mnt/QPB/repos/secbench2_widenet/wn-jvm-02-opentelemetry-java-instrumentation/quality/BUGS.md` (run dated 2026-06-23, Phase 3 code-only review, "code-only, firewalled" — no CVE basis claimed for any of the 4 findings)
- **Historical verification level:** source-only code review with `test_regression.java` regression tests described but not shown as executed in this run (no red/green log referenced in the summary the way the `requests` or chi reports have one).
- **Fresh currency check:** cloned `https://github.com/open-telemetry/opentelemetry-java-instrumentation.git` → HEAD `78d71b585a77d7f2312c1b8751ff6c95a72722d7`, committed **2026-09-27 (today)** — this is as current as it gets.

  **BUG-003 (rank 7):** `instrumentation-api/.../http/HttpServerAddressAndPortExtractor.java:46`, `ForwardedHostAddressAndPortExtractor.java:55`, `ForwardedUrlSchemeProvider.java:45` — all three still do `forwarded.toLowerCase(Locale.ROOT).indexOf("for="/"host="/"proto=")` with zero token-boundary check (confirmed via `grep` — identical three call sites, same line numbers as the historical report). For `Forwarded: by=x;myfor=evil.example`, the substring `for=` inside `myfor=` is matched and `evil.example` is extracted as `client.address`. Expected behavior rests on RFC 7239's directive-token grammar (`for=`/`host=`/`proto=` are tokens delimited by `;`/`,`, not arbitrary substrings).

  **BUG-002 (rank 8):** `instrumentation-api-incubator/.../net/internal/UrlParser.java` (`getHostEndIndexExclusive`, confirmed unchanged — breaks on the first `:` with no bracket-skip) and the verbatim-copied `reactor-netty/.../UrlParser.java` (same shape, confirmed unchanged at its own line numbers). `getHost("http://[2001:db8::1]:8080/")` returns `"[2001"` instead of the IPv6 literal. Expected behavior: the sibling `JdbcConnectionUrlParser` in the same tree already special-cases brackets, so this is an internal-consistency ("cross-source") defect, not just a missing feature.

  **BUG-001 (rank 10, partial/superseded):** the historical finding bundled two call sites under one fix shape:
  - `instrumentation-api/.../http/internal/HostAddressAndPortExtractor.java` — **this site is now fixed upstream.** Current source explicitly branches on `host.startsWith("[")`, extracts the bracketed address, and parses the port after `]:`. This did not exist at the time of the historical run (or the run mis-cited this file — either way, it's current-correct now).
  - `instrumentation-api/.../http/ForwardedHostAddressAndPortExtractor.java` (`extractHost`, the historical report's "primary" citation) — **still buggy.** Current `extractHost` checks for a leading `"` (quoted value) but has no `[`-bracket branch; `host.indexOf(':', start)` finds the first colon inside the brackets. For `[2001:db8::1]:8080` this yields address `"[2001"` (not exactly the literal `"["` the historical writeup's example produced, which suggests the writeup's repro used a slightly different input than the one traced here — the underlying missing-bracket-handling defect is the same, but the specific "becomes `[`" output could not be reproduced from reading this exact file/method and would need to be re-verified against the getter chain (`x-forwarded-host`/`:authority`/`host` header path) before filing).
  - **Because one of the two sites is already fixed, any PR for BUG-001 needs to be rescoped to `ForwardedHostAddressAndPortExtractor` only** — filing the original two-site framing would be stale on arrival.

- **Quick-merge signals:** extremely active repo (HEAD commit is from today); has `CONTRIBUTING.md`. No PR-collision search performed for any of these three IDs — do that before drafting.
