Checkout: `3d1777a1ef8881f7d1da0b02c76ca8f0a29cd2bc`. Scope: `middleware/`. No checkout files were modified. I reproduced the four cases below with a standalone program in `/private/tmp/qpb-control/sol-chi-run02/repro.go`, run with `GOPROXY=off` and `GOSUMDB=off`.

1. **Host-based routes do not match ordinary HTTP requests** — `middleware/route_headers.go:87` — **medium**. `HeaderRouter.Handler` always reads `r.Header.Get(header)`. Go's HTTP server stores the request Host in `r.Host`, leaving `r.Header["Host"]` empty for a normal incoming request. The documented `Route("Host", "example.com", ...)` example therefore falls through to the default or next handler even when the request is sent to `example.com`. The existing test manually adds `Header.Set("Host", ...)`, masking this behavior. Reproduction: `httptest.NewRequest("GET", "http://example.com/", nil)` with a Host route produced the next handler's 200 response rather than the route's 201. **Fix:** special-case Host by reading `r.Host`; use `r.Header.Get` for other headers.

2. **Allowed stacked content encodings are rejected** — `middleware/content_encoding.go:17-25` — **medium**. `AllowContentEncoding("gzip", "deflate")` treats each raw header *line* as one encoding instead of splitting comma-separated coding lists. `Content-Encoding: gzip, deflate` therefore returns 415 although both codings are allowed. The code comment says “All encodings in the request must be allowed,” and the package test explicitly lists `Content-Encoding: gzip, deflate` as supported; its test uses `Header.Set` repeatedly, replacing rather than combining the values. Reproduction with a nonempty body and that single header returned 415. **Fix:** split every header value on commas, trim each coding, and check each token against the allowlist.

3. **Compressor ignores `q=0` and can send an explicitly refused encoding** — `middleware/compress.go:260-266` — **medium**. `matchAcceptEncoding` accepts an encoding whenever its name is a substring of any comma-separated item. With `Accept-Encoding: gzip;q=0`, a compressible `text/plain` response is sent with `Content-Encoding: gzip`. This contradicts `Compress`'s documented purpose of selecting a format based on the request's `Accept-Encoding` header: quality zero means that encoding is unacceptable. The same substring check can accept unrelated tokens such as `xgzip`. **Fix:** parse each coding token and optional quality value, match names exactly, reject zero quality, and honor wildcard/identity semantics where applicable.

4. **Valid quoted charset values are rejected** — `middleware/content_charset.go:35-39` — **low**. `ContentCharset("UTF-8")` rejects a nonempty request with `Content-Type: text/plain; charset="UTF-8"`, returning 415. A quoted parameter value is valid Content-Type syntax and denotes the same charset; the middleware's comment says it accepts requests whose charset matches the configured list. The parser compares the literal quotes against `utf-8`. **Fix:** parse the media type and parameters with `mime.ParseMediaType`, then compare the decoded charset case-insensitively.
