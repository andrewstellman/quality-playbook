Checkout: `11701476b005ca7bc489df924a398b8f12453f0b`. I found four defects in the requested scope. 1. **Medium — packed lengths disagree with the packed tokens when input features already contain padding.** In `models/esm2/collator.py:166-170`, `DataCollatorWithFlattening` derives cumulative sequence lengths from the raw `features` but builds its final `input_ids` by selecting only positions where the wrapped collator's attention mask is true. `_pt_flatten_collate` uses `len(sample["input_ids"])` at line 707, including padding. For features with IDs `[a,b,pad]`, mask `[1,1,0]`, followed by `[c,d]`, the metadata ends at 5 while the packed tensor has 4 tokens; the second sequence boundary is also shifted. This contradicts the collator's documented promise that cumulative lengths describe the packed tensor and breaks THD attention/padding. Derive lengths, boundaries, position IDs, and any retained mask from the same selected tokens, or reject pre-padded features explicitly.

2. **Medium — token dropout counts masked tokens in the wrong sequences after per-sequence THD padding.** In `models/esm2/modeling_esm_te.py:741`, `_apply_token_dropout_thd` segments the *padded* `input_ids` with the *unpadded* `cu_seq_lens_q` offsets, even though lines 735-736 recognize the separate padded offsets and the preceding comment says to count masks in the padded batch. With two three-token sequences padded to four tokens each, offsets `[0,3,6]` group the first padding token with sequence two and omit its final token. The resulting scale factors are wrong and change ESM's mask-dropout behavior. Segment `is_masked` using `cu_seq_lens_q_padded` when present, then divide by the original unpadded lengths as intended.

3. **Medium — context-parallel THD shards retain global mask-dropout offsets.** In `models/esm2/collator.py:424-425`, `DataCollatorForContextParallel` replaces `input_ids` with a CP shard but copies the original `cu_seq_lens_q` and `cu_seq_lens_q_padded` into every shard. `NVEsmEmbeddings._apply_token_dropout_thd` uses those offsets against each shard's local `input_ids` (`models/esm2/modeling_esm_te.py:734-745`). For one eight-token sequence with two CP ranks, each shard has four tokens but the jagged offset still ends at eight, so token-dropout counting is invalid (and may fail in `nested_tensor_from_jagged`). The collator explicitly promises per-rank shards, and the embedding function promises per-sequence mask ratios. Calculate each sequence's masked-token count from local CP slices and aggregate counts across ranks, or supply local offsets for the embedding calculation while preserving TE's global attention metadata.

4. **Low — AMPLIFY conversion fails for non-CPU or non-float32 source weights.** In `models/amplify/src/amplify/state_dict_convert.py:90-91`, `_pad_weights` creates the extra embedding/decoder rows with default CPU `float32` tensors. A CUDA model fails at `torch.cat` due to mixed devices, and a half/bfloat16 model may have its converted weights promoted to float32, failing the conversion's dtype check in `amplify.state.apply_transforms`. The function documents conversion of an arbitrary Hugging Face model and is also used for the decoder weight. Create padding with `source_embed.new_zeros(num_padding_rows, source_embed.size(1))`.
