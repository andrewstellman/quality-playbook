# Code review: OpenTelemetry Java instrumentation (`78d71b585a77d7f2312c1b8751ff6c95a72722d7`)

## Findings

1. **Medium — A reused Reactor Netty publisher retains the first subscriber's parent context.** `instrumentation/reactor/reactor-netty/reactor-netty-1.0/javaagent/src/main/java/io/opentelemetry/javaagent/instrumentation/reactornetty/v1_0/InstrumentationContexts.java:38-43` initializes `parentContext` only once using compare-and-set. `HttpResponseReceiverInstrumenter.instrument()` creates one `InstrumentationContexts` for the returned response publisher (lines 30-48), and `CaptureParentContext.apply()` calls `initialize(Context.current())` inside `Mono.defer` for each subscription (lines 68-80). If the same response `Mono` or `Flux` is subscribed twice under different parent spans, the second request's span is parented to the first subscriber; concurrent subscriptions also share the same `clientContexts` queue, so one subscription can end the other's span. The comment at lines 70-75 explicitly says the parent context is captured on subscription. **Fix:** create a separate `InstrumentationContexts` per subscription and bind all request/response callbacks for that subscription to it; do not store per-subscription state in the single listener instance attached when the publisher is assembled.

2. **Medium — IPv6 authorities are truncated in forwarded server host extraction.** `instrumentation-api/src/main/java/io/opentelemetry/instrumentation/api/semconv/http/ForwardedHostAddressAndPortExtractor.java:87-92` treats the first colon as a port delimiter. For `Host: [2001:db8::1]:8080`, `:authority: [2001:db8::1]:8080`, or `Forwarded: host="[2001:db8::1]:8080"`, it records server address `[` and no port. The class is the default server-address extractor in `HttpServerAttributesExtractorBuilder.java:53-56`; the adjacent `internal/HostAddressAndPortExtractor.java:35-44` demonstrates the intended bracket-aware handling. **Fix:** recognize bracketed IPv6 literals, extract the address through `]`, and parse a port only after the closing bracket.

3. **Medium — A comma-separated `Forwarded` header contaminates the host value.** `instrumentation-api/src/main/java/io/opentelemetry/instrumentation/api/semconv/http/ForwardedHostAddressAndPortExtractor.java:63-68` ends a `host=` value only at `;`. For `Forwarded: for=192.0.2.1;host=first.example, for=198.51.100.1;host=second.example`, it records `first.example, for=198.51.100.1` as the server address. This contradicts the method's purpose of extracting the forwarded host and the `Forwarded` header's comma-separated element syntax; the nearby scheme parser explicitly terminates values at a comma (`ForwardedUrlSchemeProvider.java:70-77`). **Fix:** terminate an unquoted host value at the first comma or semicolon, while respecting quoted values.

4. **Medium — IPv6 URL hosts cannot be parsed by the incubator parser.** `instrumentation-api-incubator/src/main/java/io/opentelemetry/instrumentation/api/incubator/semconv/net/internal/UrlParser.java:105-110` stops the host at the first colon, including colons inside `[2001:db8::1]`. Thus `getHost("https://[2001:db8::1]:8443/p")` returns `"[2001"` and `getPort()` returns `null`. `ServicePeerResolver.java:90-106` uses these results to index configured service peers, and `HttpClientServicePeerAttributesExtractor.java:82-96` uses the parser to resolve requests; IPv6 endpoint mappings cannot match. **Fix:** when the authority begins with `[`, scan through the matching `]` before looking for the optional port delimiter.

5. **Low — A slash in a query or fragment is mistaken for a URL path.** `instrumentation-api-incubator/src/main/java/io/opentelemetry/instrumentation/api/incubator/semconv/net/internal/UrlParser.java:73-83` searches for `/` from the end of the host without stopping at `?` or `#`. `getPath("https://example.com?redirect=/login")` therefore returns `"/login"`, although this URL has no path; a fragment such as `#section/part` has the same problem. The parser's own comment at lines 119-122 says `?` and `#` end the path, and its tests expect no path for URLs consisting of a host and query. This can make service-peer path matching use a value from query data. **Fix:** find the authority's first `/`, `?`, or `#`; return `null` if `?` or `#` occurs before any slash.

6. **Medium — Reactor Netty URL attributes misreport IPv6 hosts and ports.** `instrumentation/reactor/reactor-netty/reactor-netty-1.0/javaagent/src/main/java/io/opentelemetry/javaagent/instrumentation/reactornetty/v1_0/UrlParser.java:74-86` also stops at the first colon inside a bracketed IPv6 literal. For `https://[2001:db8::1]:8443/`, `getHost()` returns `"[2001"` and `getPort()` returns `null`. `ReactorNettyHttpClientAttributesGetter.java:90-114` feeds these values into HTTP client network attributes and falls back to port 443 when parsing fails, so requests to this IPv6 host report an incorrect server address and port 443 instead of 8443. **Fix:** parse bracketed host literals as a unit and recognize a port only after `]`.
