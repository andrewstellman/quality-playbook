# Code review request

You are an experienced software engineer reviewing part of an open-source project for defects.

Review the code in the scope given below. Look for defects: logic errors, incorrect handling of edge cases and unusual inputs, behaviour that contradicts the code's own documentation or comments or the standards it implements, error-handling mistakes, concurrency problems, and API misuse. You may read any other file in the repository for context, and you may run small snippets or the project's existing tests to check a suspicion.

Do not report style issues, missing documentation, or speculative concerns. Report only defects you are confident are real.

For each defect, give:
- file and line
- what goes wrong, and on what input or in what situation
- why it is wrong (cite the code, comment or documentation that establishes the intended behaviour)
- severity: high, medium or low
- a suggested fix

If you find nothing you are confident in, say so. Work only from the repository checkout you are given. Do not search the web, the project's issue tracker, or any other directory on this machine.

At the end, list which files you actually read.
