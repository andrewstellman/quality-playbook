### The bypass, demonstrated

```markdown

### REQ-002: B contract about errors

```

→ **`FAIL=0 WARN=0`**, ten PASS lines. No Actors, no Cross-cutting concerns, no Use cases, no
Traceability appendix, and every REQ in one undifferentiated bucket. This is the "flat list, not a
coherent document" shape §5.2 exists to reject, and the contract certifies it clean.

The worker's fix only closed the sub-case where the flat section *lacks* intro prose. Add 40
characters of intro prose — which any renderer will — and the document becomes a single functional
section: intro prose passes, no singleton (>1 REQ), and the cross-cutting mandate is skipped because
`len(functional) > 1` is false.

### R-2 — F-1 scoping now misses legitimate gaps-statement placements (P2, WARN-only)

The P2-5 fix slices the Overview and searches only inside it. Two placements that a reasonable
renderer would choose now WARN:

- gaps statement under a dedicated `## Coverage and gaps` level-2 section → **WARN**
- gaps statement in the document preamble above `## Overview` → **WARN**

`## Project overview` is handled correctly. Advisory-only, so blast radius is small and this matches
the severity Panelist A assigned. Consider accepting a `## Coverage and gaps` section as a valid
location. (The phrase-list brittleness — `Out of scope:` and positive forms like "nothing was left
uncovered" both WARN — is pre-existing, not this round's.)

### R-3 — the C-5 fenced-code exemption is abusable, and P2-4 is only half-closed (P2)

- **Panelist A's exact P2-4 demonstrated false positive is NOT closed.** Panelist A asked to "skip
  fenced code blocks **and inline-code spans**" / "exempt `<!--` that appears inside backticks".
  Only fenced blocks were done. The demonstrated case still fires:
  `` - Conditions: `<!-- keep -->` survives minification `` → **`FAIL=1`, "HTML comment at line 18"**.
  For a template-engine or sanitizer target — and Express's view-engine layer is a benchmark target —
  a REQ about comment handling still cannot state its own contract.
- Indented (4-space) code blocks and blockquoted examples are also unexempted, so the exemption is
  inconsistent across the three ways Markdown quotes material.
- **Abuse direction:** wrapping internals in a fence pair hides them entirely — a document with
  `<!-- cluster: heterogeneous -->`, `Asymmetry-promotion` and `REQUIREMENTS_pre_narrative` inside one
  fence scores `FAIL=0 WARN=0`. This requires deliberate evasion rather than ordinary renderer drift,
  so I rate it P2, but it does mean C-5 is now advisory against any generator willing to emit a fence.

None of R-1..R-3 is blocking on its own; all three are the same "edges the spec did not describe"
