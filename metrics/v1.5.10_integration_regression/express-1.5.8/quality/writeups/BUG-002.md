# BUG-002 — `res.cookie` sub-second `maxAge` emits `Max-Age=0` with a future `Expires`

- **Severity:** HIGH · **divergence_type:** code-spec · **Requirement:** REQ-002 (C-3, UC-02)
- **Site:** `lib/response.js:759-766`

## What's wrong
```js
opts.expires = new Date(Date.now() + maxAge)
opts.maxAge = Math.floor(maxAge / 1000)
```
For `maxAge` in (0,1000) ms, `Math.floor(maxAge/1000)` is `0`, so the cookie carries `Max-Age=0` (delete-now) alongside a future `Expires`. UAs that prefer `Max-Age` drop the cookie immediately — a 500ms flash/CSRF cookie never arrives.

## Reachability
No guard. The floor is reached unconditionally inside `if (!isNaN(maxAge))` for any numeric `maxAge`; there is no minimum, round-up, or Max-Age/Expires reconciliation. `res.clearCookie` is supposed to be the only immediate-expiry path.

## Expected vs actual
- Expected: `Expires` and `Max-Age` describe the same lifetime.
- Actual: `Max-Age=0` contradicting a future `Expires`.

## Fix
`quality/patches/BUG-002-fix.patch` — round positive sub-second `maxAge` up to at least 1 second so `Max-Age` agrees with `Expires`.

## Regression test
`quality/patches/BUG-002-regression-test.patch` (`it.skip("BUG-002: …")`): `res.cookie('flash','1',{maxAge:500})` → `Set-Cookie` must not contain `Max-Age=0`.
