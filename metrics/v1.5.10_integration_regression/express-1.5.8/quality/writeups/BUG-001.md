# BUG-001 — `req.protocol` collapses to `''` for a leading-empty `X-Forwarded-Proto`

- **Severity:** HIGH · **divergence_type:** code-spec · **Requirement:** REQ-001 (C-1, UC-01)
- **Site:** `lib/request.js:309-314` (`protocol`), `lib/request.js:326-328` (`secure`)

## What's wrong
With trust proxy enabled, `req.protocol` does:
```js
var header = this.get('X-Forwarded-Proto') || proto
var index = header.indexOf(',')
return index !== -1 ? header.substring(0, index).trim() : header.trim()
```
For `", https"` the first comma is at index 0, so `substring(0, 0).trim()` is `''`. `req.secure` (`protocol === 'https'`) is then **false for a genuinely-secure request**, so HTTPS-only middleware misbehaves.

## Reachability
No guard. The `index !== -1` branch is reached unconditionally once trust passes and the header contains a comma; there is no non-empty-token selection nor fallback to the socket scheme when the leading element is empty. Defect reached for any trusted comma-led XFP value.

## Expected vs actual
- Expected: first **non-empty** trimmed element, else socket scheme; always ∈ {http, https}.
- Actual: `''` for `", https"` / `","`.

## Fix
`quality/patches/BUG-001-fix.patch` — iterate comma-separated elements and return the first non-empty trimmed one, else `proto`.

## Regression test
`quality/patches/BUG-001-regression-test.patch` (`it.skip("BUG-001: …")`): trusted `X-Forwarded-Proto: ", https"` must yield `protocol==='https'`, `secure===true`.
