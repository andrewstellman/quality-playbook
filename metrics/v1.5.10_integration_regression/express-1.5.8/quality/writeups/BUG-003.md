# BUG-003 — `res.redirect` emits literal `undefined` for an in-range unassigned status

- **Severity:** MEDIUM · **divergence_type:** cross-source · **Requirement:** REQ-003 (C-4, UC-03)
- **Site:** `lib/response.js:841`, `:846-847`

## What's wrong
The redirect body is built from `statuses.message[status]`:
```js
body = statuses.message[status] + '. Redirecting to ' + address
... '<title>' + statuses.message[status] + '</title>' ...
```
`res.status` (`response.js:70`) admits any integer 100–999, but `statuses.message` is keyed only by assigned codes. An in-range unassigned 3xx (e.g. 310) makes `statuses.message[310]` `undefined`, so the body reads `"undefined. Redirecting to …"` and `<title>undefined</title>`.

## Reachability
No guard. The range guard admits a strictly larger set than the message map covers, and the body builder reads the map with no fallback. Cross-source: two independent domains (range guard vs message map) disagree.

## Expected vs actual
- Expected: human-readable body/title for every accepted status.
- Actual: the literal `undefined`.

## Fix
`quality/patches/BUG-003-fix.patch` — compute `var message = statuses.message[status] || String(status)` and use it in both the text and html branches.

## Regression test
`quality/patches/BUG-003-regression-test.patch` (`it.skip("BUG-003: …")`): `res.redirect(310, '/x')` body must not contain the literal `"undefined"`.
