# BUG-005 — `acceptParams` splits quoted values on inner `;` and does not clamp `q`

- **Severity:** MEDIUM · **divergence_type:** code-spec · **Requirement:** REQ-005 (C-7, UC-05)
- **Site:** `lib/utils.js:89-120` (`:99-108`, `:110-111`)

## What's wrong
The hand-rolled scan finds `;`/`=` boundaries with `str.indexOf` and has **no quoted-string awareness**. For `text/html;x="a;b";q=0.5`, `endIndex` lands on the `;` inside the quotes, so the value is truncated to `"a` and the scan desyncs. Separately, `q` is `parseFloat(value)` (`:111`) with no clamp, so `q=5` becomes `quality: 5`.

## Reachability
No guard. Reached unconditionally via `normalizeType` (`utils.js:61-64`) for any `Accept`/`res.format`/`res.type` media-type string containing a quoted `;` or out-of-range `q`.

## Executable evidence (RED → GREEN, isolated pure function)
- Current code: `params.x = '"a'`, `quality = 5`.
- After `BUG-005-fix.patch`: `params.x = 'a;b'`, `quality = 1` (clamped).

## Spec basis
RFC 7231 §3.1.1.1 (quoted-string parameter values) and §5.3.1 (`q` range `[0,1]`).

## Fix
`quality/patches/BUG-005-fix.patch` — add `indexOfUnquoted`/`unquote` helpers: find the next `;` that is not inside a quoted string, strip surrounding quotes from values, and clamp `q` to `[0,1]`.

## Regression test
`quality/patches/BUG-005-regression-test.patch` (`it.skip("BUG-005: …")`): `normalizeType('text/html;x="a;b";q=0.5').params.x === 'a;b'` and `q=5` clamps to `<= 1`.
