# BUG-004 — Charset asymmetry between string and Buffer `res.send` bodies

- **Severity:** MEDIUM · **divergence_type:** internal-prose · **Requirement:** REQ-006 (parity, C-6, UC-06.a/b/c)
- **Covers:** REQ-006/cell-CHARSET_INJECTION-STRING_SEND, -BUFFER_SEND, -RES_SET
- **Site:** `lib/response.js:137-143` (string), `:150-153` (Buffer), `:664-686` (`res.set`), `lib/utils.js:225-238` (`setCharset`)

## What's wrong
String bodies overwrite the charset to utf-8:
```js
this.set('Content-Type', setCharset(type, 'utf-8'));   // :140
```
Buffer/typed-array bodies only set a default `bin` type when Content-Type is absent (`:151-152`) and otherwise **preserve** the caller's charset. `res.set` injects via `mime.contentType`, which only adds a charset when none is present and never overwrites. For `text/plain; charset=iso-8859-1`: string `send` → `charset=utf-8`; Buffer `send` / `res.set` → `charset=iso-8859-1`. The same handler advertises different charsets by body type.

## Reachability
No guard. The string and Buffer branches are mutually exclusive arms of `switch (typeof chunk)`, each reached unconditionally for its body type when a charset is pre-set; nothing reconciles them before flush.

## Spec basis
`History.md:15` documents the v5 perf change introducing the string-only `setCharset` rewrite ("Avoid duplicate Content-Type header processing in `res.send()`") with no statement that the Buffer path should diverge — an internal-prose gap.

## Fix
`quality/patches/BUG-004-fix.patch` — when a Buffer body has a pre-set string Content-Type, normalize its charset via `setCharset(type, 'utf-8')`, matching the string branch. Consolidated single fix closes all three cells (string/Buffer/set parity at send time).

## Regression test
`quality/patches/BUG-004-regression-test.patch` (`it.skip("BUG-004: …")`): a pre-set `text/plain; charset=iso-8859-1` sent as a string vs as a Buffer must advertise the same final `Content-Type`.
