# Behavioral Contracts — Express v5.2.1

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.8 — Andrew Stellman
> Date: 2026-06-19 · Project: Express (v5.2.1)

A behavioral contract states, for a single function or interaction, the **inputs**, the
**guarantees** the code must uphold, and the **observable failure** if it does not. Contracts
are derived from `quality/EXPLORATION.md` and map to REQs. Tier 3 (code-is-the-spec): the
contract is what the code's own structure and `History.md` imply, not an external standard.

The routing/mounting layer lives in `router@2.2.0` (not in `lib/`, not in `node_modules` this
run) and is treated as a behavioral boundary — contracts cite the call sites in `lib/`, not
router internals.

---

## C-1 — `req.protocol` / `req.secure` (REQ-001, UC-01)

- **Site:** `lib/request.js:297-315` (`protocol`), `lib/request.js:326-328` (`secure`).
- **Inputs:** the incoming socket's encrypted state; the `X-Forwarded-Proto` header; the
  compiled `trust proxy` function.
- **Guarantee:** when the immediate peer is trusted, `protocol` is the first non-empty,
  trimmed, comma-separated element of `X-Forwarded-Proto`, falling back to the socket scheme
  when the header is absent or yields no usable token; the result is always a member of
  `{http, https}`. `secure` is `protocol === 'https'`.
- **Observable failure:** a value of `", https"` returns `''`, making `secure` false for a
  genuinely-secure request (Scenario 1). Any non-`{http,https}` protocol string is a contract
  break.

## C-2 — `req.host` / `req.hostname` / `req.subdomains` (REQ-007, UC-07.a/b/c)

- **Site:** `lib/request.js:418-431` (`host`), `:444-458` (`hostname`), `:383-394`
  (`subdomains`).
- **Inputs:** `X-Forwarded-Host`, `Host`, `:authority`; the compiled `trust proxy` function;
  the `subdomain offset` setting.
- **Guarantee:** for a trusted peer, `host` is the leading authority of `X-Forwarded-Host`
  (comma-trimmed), else `Host`. `hostname` is `host` with any port (or `[...]:port` IPv6
  bracket form) stripped. `subdomains` splits `hostname` on `.` minus the offset. For any
  syntactically present authority, `hostname` is never `undefined`.
- **Observable failure:** `",a.com"` yields `host === ''` → `hostname === undefined` →
  `subdomains === []` (Scenario 6). Disagreement with C-1's split discipline is the
  cross-implementation drift.

## C-3 — `res.cookie` serialization (REQ-002, UC-02)

- **Site:** `lib/response.js:742-775`, specifically `:759-766`.
- **Inputs:** cookie name/value, `options.maxAge` (ms), `options.expires`, signing key.
- **Guarantee:** when `maxAge` is given, `expires` and `Max-Age` describe the *same* lifetime.
  An immediate-expiry cookie is produced only by `res.clearCookie`.
- **Observable failure:** `maxAge < 1000` floors `Max-Age` to `0` while `expires` is in the
  future — contradictory directives that drop the cookie on UAs preferring `Max-Age`
  (Scenario 2).

## C-4 — `res.redirect` body (REQ-003, UC-03)

- **Site:** `lib/response.js:812-864`, body from `statuses.message[status]` at `:841`,
  `:846-847`.
- **Inputs:** `status` (any number passing the 100–999 guard at `:70`), `url`, the `Accept`
  header (drives text vs HTML via `res.format`).
- **Guarantee:** the emitted body and HTML `<title>` are human-readable for *every* accepted
  status, including codes absent from `statuses.message`.
- **Observable failure:** an unassigned code (e.g. 310) yields `"undefined. Redirecting to
  …"` and `<title>undefined</title>` (Scenario 3).

## C-5 — `res.jsonp` callback (REQ-004, UC-04)

- **Site:** `lib/response.js:260-304`, filter at `:286`, body at `:300`, headers at `:271,282`.
- **Inputs:** the `?callback=` query value, the JSON body, the `jsonp callback name` setting.
- **Guarantee:** the callback reflected into the `text/javascript` body is constrained to the
  intended grammar; `X-Content-Type-Options: nosniff` is set; non-function callbacks are
  guarded by `typeof … === 'function'`.
- **Observable failure:** `a.constructor.constructor` survives the `/[^\[\]\w$.]/g` filter and
  is reflected into an executable content type (Scenario 4).

## C-6 — Charset across response surfaces (REQ-006, UC-06.a/b/c)

- **Site:** `lib/response.js:137-143` (string `send`), `:150-153` (Buffer `send`), `:664-686`
  (`res.set`), `lib/utils.js:225-238` (`setCharset`).
- **Inputs:** a pre-set or implied Content-Type with a charset; the body's JS type (String vs
  Buffer/typed-array); the surface used (`send`/`json`/`jsonp`/`set`/`type`).
- **Guarantee:** the charset advertised in the final Content-Type is a function of the app's
  *intent*, consistent across body type and across the `setCharset`-vs-`mime.contentType`
  injection paths, or the divergence is explicitly specified.
- **Observable failure:** a string body forces `charset=utf-8` while a Buffer body preserves
  `charset=iso-8859-1` for the identical handler (Scenario 5).

## C-7 — `acceptParams` media-type parsing (REQ-005, UC-05)

- **Site:** `lib/utils.js:89-120`, helpers at `:61-77`.
- **Inputs:** a `type/subtype;q=…;key=val` string from `Accept` / `res.format`.
- **Guarantee:** parameters are parsed per RFC 7231 §3.1.1.1 — quoted values containing `;`
  are not split mid-value, `q` is parsed and clamped to `[0,1]`, and the `splitIndex >
  endIndex` recovery branch does not drop valid params.
- **Observable failure:** `text/html;x="a;b";q=0.5` splits at the inner `;`; `q=5` flows
  through unclamped.

## C-8 — Settings compilation fail-fast (REQ-008)

- **Site:** `lib/application.js:363-380`, `lib/utils.js:130-214`.
- **Inputs:** `app.set('etag'|'query parser'|'trust proxy', value)`.
- **Guarantee:** an invalid value throws a `TypeError` at `app.set` time.
- **Observable failure:** a config error that surfaces on the first request instead of at boot.

## Artifact-layout contracts (REQ-009..016)

These constrain the playbook's own output, not Express source. The Phase 6 gate enforces
`quality/writeups/BUG-<id>.md`, `quality/patches/BUG-<id>-{fix,regression-test}.patch`,
`quality/code_reviews/`, `quality/spec_audits/`, `quality/results/*.json`,
`quality/mechanical/`, and the **forbidden** `quality/workspace/` tree. See REQ-009 through
REQ-016 in `REQUIREMENTS.md` for the testable conditions.
