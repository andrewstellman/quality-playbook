# TDD Verification Protocol: Express v5.2.1

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.8 — Andrew Stellman
> Date: 2026-06-19 · Project: Express (v5.2.1)

Executed after the code review and spec audit confirm bugs and generate fix patches. Runs the
red-green cycle for each confirmed bug: the regression test fails on unpatched code, the fix
patch makes it pass.

## Framework adaptation

Express has full test infrastructure: **Mocha + supertest**, import via `require('..')`.
Regression tests live in `quality/test_regression.js`, mirroring `quality/test_functional.js`.
Guard every regression test with `it.skip("BUG-NNN: …")` (the earliest syntactic guard for
Mocha) until a fix lands.

**Probe the runner first (mandatory).** Capture to `quality/results/phase5_env.log`:

```bash
{ node --version; npx mocha --version; test -d node_modules && echo "node_modules: present" || echo "node_modules: ABSENT"; } \
  > quality/results/phase5_env.log 2>&1
```

This checkout ships **without `node_modules`** — Mocha/supertest/Express runtime deps are not
installed. The Bash tool runs on the operator's real machine: run `npm install` (online,
default registry) before recording any verdict. Retry once online before concluding `NOT_RUN`.
Record `NOT_RUN` **only if** the online probe/install itself exits non-zero, and quote that
failing output in `phase5_env.log`. "By inspection" / "assumed unavailable" is not acceptable
evidence — if the probe succeeds you MUST run the tests for real.

## Spec-grounded test requirements

For each confirmed BUG-NNN: read its `spec_basis`, write assertions using the spec's language
(this run: `History.md` line numbers and REQ identifiers, since there are no Tier-1/2 docs),
and include a comment block citing the REQ id, the BUG id, and a ≤15-word behavioral-contract
quote.

## Red-green execution (per bug with a fix patch)

```bash
# ── Red: revert fix, run test, expect FAIL ──
git apply -R quality/patches/BUG-NNN-fix.patch 2>/dev/null
TEST_CMD="npx mocha quality/test_regression.js --grep 'BUG-NNN'"
OUTPUT=$($TEST_CMD 2>&1); EXIT=$?
printf 'RED\n--- Test output for BUG-NNN red phase ---\nCommand: %s\nExit code: %d\n%s\n' \
  "$TEST_CMD" "$EXIT" "$OUTPUT" > quality/results/BUG-NNN.red.log

# ── Green: apply fix, run test, expect PASS ──
git apply quality/patches/BUG-NNN-fix.patch
OUTPUT=$($TEST_CMD 2>&1); EXIT=$?
printf 'GREEN\n--- Test output for BUG-NNN green phase ---\nCommand: %s\nExit code: %d\n%s\n' \
  "$TEST_CMD" "$EXIT" "$OUTPUT" > quality/results/BUG-NNN.green.log
```

The first line of each log is a machine-readable status tag: `RED` (failed as expected),
`GREEN` (passed after fix), `NOT_RUN` (probe exited non-zero — quote it), or `ERROR`. The red
phase is **mandatory for every confirmed bug**, even with no fix patch (then
`green_phase: "skipped"`). To execute a guarded test in the red/green phases, temporarily
remove the `it.skip` guard (use `it`), then restore it after recording.

To capture JUnit XML: add `--reporter mocha-junit-reporter --reporter-options
mochaFile=quality/results/tdd-red-BUG-NNN.xml`. If unavailable, set `junit_available:false`.

## Sidecar JSON → `quality/results/tdd-results.json` (copy verbatim, fill values)

```json
{
  "schema_version": "1.1",
  "skill_version": "1.5.8",
  "date": "YYYY-MM-DD",
  "project": "express",
  "bugs": [
    {
      "id": "BUG-001",
      "requirement": "REQ-001",
      "red_phase": "fail",
      "green_phase": "pass",
      "verdict": "TDD verified",
      "regression_patch": "quality/patches/BUG-001-regression-test.patch",
      "fix_patch": "quality/patches/BUG-001-fix.patch",
      "fix_patch_present": true,
      "patch_gate_passed": true,
      "writeup_path": "quality/writeups/BUG-001.md",
      "junit_red": "tdd-red-BUG-001.xml",
      "junit_green": "tdd-green-BUG-001.xml",
      "junit_available": true,
      "notes": ""
    }
  ],
  "summary": { "total": 0, "verified": 0, "confirmed_open": 0, "red_failed": 0, "green_failed": 0 }
}
```

Required top-level: `schema_version`, `skill_version`, `date`, `project`, `bugs`, `summary`.
Required per-bug: `id`, `requirement`, `red_phase`, `green_phase`, `verdict`,
`fix_patch_present`, `writeup_path`. Required summary keys (all five): `total`, `verified`,
`confirmed_open`, `red_failed`, `green_failed`. Valid verdicts: `TDD verified`, `red failed`,
`green failed`, `confirmed open` (with `red_phase:"fail"`, `green_phase:"skipped"`),
`deferred`. **Never** use `"skipped"` as a verdict. Use the real session date, not the
placeholder. **Post-write:** reopen and verify all required fields, legal enums, no extra root
keys.

## Bug writeups → `quality/writeups/BUG-NNN.md` (every confirmed bug)

Sections 1–4, 6, 7 required (add 5 on depth-judgment trigger, 8 when related bugs exist):
Summary · Spec reference · The code · Observable consequence · [Depth judgment] · The fix
(**always an inline ```diff``` block — gate-enforced**) · The test · [Related issues]. Include
the version stamp. A writeup that says "see patch file" instead of an inline diff fails the
gate.

## Execution UX

(1) plan: numbered table of bugs to verify; (2) progress: `FAIL ✓ → PASS ✓` per cycle;
(3) summary: verified/failed/rewritten counts.

## Closure gate

If `quality/BUGS.md` has any confirmed bug, `quality/results/tdd-results.json` is mandatory and
every confirmed bug needs a `quality/results/BUG-NNN.red.log`. Zero-bug runs may omit both.
