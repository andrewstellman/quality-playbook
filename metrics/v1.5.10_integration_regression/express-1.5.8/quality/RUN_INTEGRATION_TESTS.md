# Integration Test Protocol: Express v5.2.1

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.8 — Andrew Stellman
> Date: 2026-06-19 · Project: Express (v5.2.1)

## Working Directory

All commands run from the project root using **relative paths**. Never `cd` to an absolute
path. Test runner: `npx mocha` (the project's idiom). The harness: supertest drives the
`app` request handler end-to-end through the real `node:http` server.

## Safety Constraints

- Read-only against the source tree. The protocol creates apps in-process and issues HTTP
  requests via supertest — no external services, no databases, no network egress.
- **Dependency pre-flight:** this checkout has **no `node_modules`**. Run `npm install` first;
  Express's runtime deps (`router`, `finalhandler`, `send`, `accepts`, `cookie`, …) and the
  test deps (`mocha`, `supertest`) must be present or every group errors at load. If
  `npm install` fails on network restrictions, retry once online before recording any group as
  `error` with `"pre_flight_error": "environment"`.

## Pre-Flight Check

```bash
node --version
test -d node_modules || npm install
npx mocha --dry-run quality/test_functional.js   # must list tests, not "0 passing"
```

If `--dry-run` reports "0 tests" or a load error, fix the selector / install before recording
any group. A load error (missing dependency) is `"pre_flight_error": "environment"`, not a
selector bug.

## Test Matrix

Each group maps to ≤2 use cases (per-UC splitting). Mocha selectors use `--grep` against the
test display names in `quality/test_functional.js`.

| Group | Name | Use case(s) | Command (relative) | Pass criteria |
|-------|------|-------------|--------------------|---------------|
| 1 | Trust-proxy protocol | UC-01 | `npx mocha quality/test_functional.js --grep "Scenario 1"` | `req.protocol` ∈ {http,https}; clean `https` → `secure:true` |
| 2 | Cookie lifetime | UC-02 | `npx mocha quality/test_functional.js --grep "maxage"` | sub-second maxAge does not emit `Max-Age=0` |
| 3 | Redirect body | UC-03 | `npx mocha quality/test_functional.js --grep "redirect"` | unknown-status body has no literal `undefined` |
| 4 | JSONP safety | UC-04 | `npx mocha quality/test_functional.js --grep "jsonp"` | `nosniff` set; `alert(1)` sanitized |
| 5 | Content negotiation | UC-05 | `npx mocha quality/test_functional.js --grep "acceptparams"` | quoted `;` does not break negotiation |
| 6 | Charset parity | UC-06.a, UC-06.b | `npx mocha quality/test_functional.js --grep "charset"` | string and Buffer both declare a charset; type→send injects utf-8 |
| 7 | Forwarded-host resolution | UC-07.a, UC-07.b | `npx mocha quality/test_functional.js --grep "X-Forwarded-Host"` | leading-comma XFH → non-undefined hostname; clean authority resolves |
| 8 | Forwarded-host port/IPv6 | UC-07.c | `npx mocha quality/test_functional.js --grep "port_stripped"` | port stripped to clean hostname |

Group 9 is `[Infrastructure]` — it validates that the quality artifacts and any patches do not
regress Express's own suite. It does not count toward use-case coverage.

## Execution UX (How to Present When Running This Protocol)

1. **Plan:** print the matrix above as a numbered table before running anything.
2. **Progress:** one line per group as it runs — `✓`/`✗`/`⧗` with the group name.
3. **Summary:** a pass/fail table plus a `recommendation` (SHIP / FIX BEFORE MERGE / BLOCK).

## Structured Output (mandatory)

Run each group with the JUnit reporter and write `quality/results/integration-group-N.xml`:

```bash
npx mocha quality/test_functional.js --grep "Scenario 1" \
  --reporter mocha-junit-reporter \
  --reporter-options mochaFile=quality/results/integration-group-1.xml
```

If `mocha-junit-reporter` is unavailable, set `"junit_available": false` in the sidecar and
skip XML for that group.

Write `quality/results/integration-results.json` using this schema verbatim (fill values
only; do not rename keys). Every use case from `REQUIREMENTS.md` must appear in `uc_coverage`.

```json
{
  "schema_version": "1.1",
  "skill_version": "1.5.8",
  "date": "YYYY-MM-DD",
  "project": "express",
  "recommendation": "SHIP",
  "groups": [
    { "group": 1, "name": "Trust-proxy protocol", "use_cases": ["UC-01"], "result": "pass", "tests_passed": 0, "tests_failed": 0, "junit_file": "integration-group-1.xml", "junit_available": true, "notes": "" }
  ],
  "summary": { "total_groups": 9, "passed": 0, "failed": 0, "skipped": 0 },
  "uc_coverage": {
    "UC-01": "covered_pass", "UC-02": "covered_pass", "UC-03": "covered_pass",
    "UC-04": "covered_pass", "UC-05": "covered_pass",
    "UC-06.a": "covered_pass", "UC-06.b": "covered_pass", "UC-06.c": "covered_pass",
    "UC-07.a": "covered_pass", "UC-07.b": "covered_pass", "UC-07.c": "covered_pass"
  }
}
```

Valid `result`: `pass`/`fail`/`skipped`/`error`. Valid `recommendation`: `SHIP`/`FIX BEFORE
MERGE`/`BLOCK`. Valid `uc_coverage`: `covered_pass`/`covered_fail`/`not_mapped`.

**Post-write validation:** reopen `integration-results.json` and verify all required top-level
fields, every `groups[]` entry has `group`/`name`/`use_cases`/`result`/`notes`, all enums are
legal, `uc_coverage` covers every UC, and there are no extra root keys.

## Design Notes

These are end-to-end tests: they exercise the actual user outcome (a request behind a proxy
resolving the right scheme; a redirect page free of `undefined`), not just unit calls that
touch the same code. Group 6 must run **both** the string and Buffer variants — the asymmetry
is the point. Group 7 must include the leading-comma case, not just the clean authority.
