## Pass 1: Structural Review

Read function bodies (not signatures) and report anything incorrect. Line numbers mandatory.
If unsure, flag QUESTION not BUG. Grep before claiming missing. No style changes.

### Minimum required Pass 1 scrutiny areas

**1. Input validation and boundary handling.** The trust boundary here is the device-offered
feature bitmap and the driver-requested queue size. Check: does `vring_create_virtqueue`
(virtio_ring.c ~3505) bound the requested size against the device max (REQ-009)? Does the
negotiation path reject a feature set the device cannot honor?

**2. Resource lifecycle.** Reset is the lifecycle operation. For each transport's `*_reset`,
confirm the device status is driven to 0 and (for non-legacy) the driver waits for read-back-0
before any reinit can proceed (REQ-003). MMIO `vm_reset` (virtio_mmio.c:251-257) is the suspect.

**3. Concurrency and state management.** Interrupt handlers run concurrently with the device.
Check that `vp_interrupt` (virtio_pci_common.c:106-124) and `vm_interrupt` (virtio_mmio.c:285-307)
each return IRQ_HANDLED for every event they actually service (REQ-004). Check the packed-ring
wrap site (virtio_ring.c ~1580-1583): the wrap counter and avail/used flags must be modified as a
single read-modify-write that preserves bits outside the intended toggle (REQ-007). Confirm every
`avail`/`used` index update in both split and packed paths is preceded by the correct barrier
(REQ-008).

**4. Unit and encoding correctness.** Feature bits are read by ordinal position in
`[VIRTIO_TRANSPORT_F_START(28), VIRTIO_TRANSPORT_F_END(42))`. Confirm the whitelist loop iterates
the correct range (virtio_config.h:54-55) and that legacy's 32-bit boundary (BUG_ON in
vp_finalize_features legacy) correctly excludes bits 37-41.

**5. Enumeration and whitelist completeness — MECHANICAL CHECK (mandatory).**
The function is `vring_transport_features` (virtio_ring.c:3505-3532). A
`quality/mechanical/vring_transport_features_cases.txt` artifact EXISTS — use it as List A. Do NOT
re-extract manually and do NOT copy from REQUIREMENTS.md.

   (a) **List A (code extraction, from the receipt):** the 8 case labels — INDIRECT_DESC,
       EVENT_IDX, VERSION_1, ACCESS_PLATFORM, RING_PACKED, ORDER_PLATFORM, NOTIFICATION_DATA,
       IN_ORDER. Cite line numbers from the source (3511-3525) when reporting.
   (b) **List B (spec extraction):** the authoritative transport bits from virtio_config.h:
       VERSION_1(32), ACCESS_PLATFORM(33), RING_PACKED(34), IN_ORDER(35), ORDER_PLATFORM(36),
       SR_IOV(37), NOTIFICATION_DATA(38), NOTIF_CONFIG_DATA(39), RING_RESET(40), ADMIN_VQ(41),
       plus INDIRECT_DESC(28)/EVENT_IDX(29).
   (c) **Diff:** SR_IOV(37) — NOT IN CODE (cleared by default: at virtio_ring.c:3527-3529).
       NOTIF_CONFIG_DATA(39) — NOT IN CODE. RING_RESET(40) — NOT IN CODE. ADMIN_VQ(41) — NOT IN
       CODE. Then check each transport's compensator: vp_transport_features re-adds 37/40/41 (NOT
       39); vm_finalize_features and virtio_vdpa_finalize_features re-add NONE.

   Do NOT assert the whitelist "covers all values" without this two-list diff. The v1.3.16/v1.3.17
   virtio incidents were exactly this hallucination — a reviewer claimed RING_RESET was preserved
   while line 3527 was the `default:` branch. The mechanical receipt makes the diff falsifiable.

These five areas must appear as labeled subsections in the Pass 1 report.

## Pass 2: Requirement Verification

For each REQ in `quality/REQUIREMENTS.md`, report SATISFIED / VIOLATED / PARTIALLY SATISFIED /
NOT ASSESSABLE with at least one file:line citation per requirement. Do not blanket-range
requirements.

**Enumeration completeness claims require mechanical proof.** REQ-002 and REQ-005 involve the
whitelist/compensation grid. For these, re-run the List A / List B diff from Pass 1 area 5 — do
NOT mark them SATISFIED by reading the function and believing it handles everything. The
code-side list must come from the mechanical receipt, not from REQUIREMENTS.md.

Focus Pass 2 on the negotiation/reset/interrupt requirements (REQ-001..009); the artifact-location
requirements (REQ-010..017) are verified structurally by the Phase 6 gate and need only a presence
check here.

## Pass 3: Cross-Requirement Consistency

Compare pairs sharing a concept:
- **Shared concept: transport bit 39 (NOTIF_CONFIG_DATA).** REQ-002 (whitelist compensation) and
  REQ-005 (validator/compensator agreement). Does `vp_check_common_size` validating bit 39 agree
  with `vp_transport_features` never re-adding it? (Expected: INCONSISTENT — the bug.)
- **Shared concept: the compensation set.** REQ-001 (per-transport re-add) and REQ-002 (whitelist
  closed set). Does the union of all transport compensators cover every un-enumerated bit? (MMIO
  and vDPA compensate nothing; bit 39 compensated by nobody.)
- **Shared concept: reset wait semantics.** REQ-003 across PCI-modern (poll) / MMIO (none) /
  legacy (single read). Do the three reset paths agree on the spec §5 contract, or is the
  divergence intentional and documented?

## Phase 2: Regression Tests for Confirmed Bugs

For each confirmed BUG, write an executable test in `quality/test_regression.py` (same framework
as `quality/test_functional.py` — pytest, source-inspection style). Because this is kernel C with
no userspace harness, regression tests read the source and assert on the presence/absence of the
specific pattern the finding cites.

**Skip guard (mandatory):** decorate each regression test with
`@pytest.mark.xfail(strict=True, reason="BUG-NNN: <description> — unskip after applying quality/patches/BUG-NNN-fix.patch")`.
The test asserts the DESIRED correct behavior, so it fails (XFAIL) on the current buggy source and
XPASSes (strict failure → remove the guard) once the fix lands.

**Source-inspection tests must execute (no `run=False`).** These tests read repository files and
string-match — safe, deterministic, fast. Do NOT mark them `run=False`; an inert test is the worst
state (v1.3.18 BUG-004 regression: the correct assertion existed but never ran).

**Test-finding alignment:** each regression test must exercise the exact function and condition the
finding cites — e.g., the MMIO RING_RESET test must slice `vm_finalize_features` and check the
text after the `vring_transport_features` call, not some other function.

Report results as a confirmation table (BUG CONFIRMED / FALSE POSITIVE / NEEDS INVESTIGATION).

### Closure mandate

Every confirmed BUG row in the combined summary must have either a `REGRESSION TEST:` line citing
the test function or an `EXEMPTION:` line. Run the post-review closure checklist (count BUGs vs
test functions) before declaring the review complete.
