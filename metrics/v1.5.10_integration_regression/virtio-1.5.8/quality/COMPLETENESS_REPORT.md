## Testability audit

All conditions of satisfaction reference concrete code locations (file:line, function name) and
assert observable behavior (a bit survives/does-not-survive negotiation; a poll loop is present/
absent; an interrupt handler returns IRQ_HANDLED/IRQ_NONE). No condition is vague or untestable.
Because the target is kernel C with no in-tree userspace harness, the functional tests are
source-inspection tests (they read source files and assert on the presence/absence of specific
case labels and code patterns) — a deterministic, fast, executable form appropriate for this
target.

## Consistency issues

No internal inconsistencies detected at baseline. The one cross-requirement tension is intentional
and documented in REQUIREMENTS.md "Cross-cutting concerns": REQ-002 (whitelist closed set) and
REQ-001/REQ-005 (per-transport compensation) must be read together — a bit can be "compensatable"
in principle (REQ-002) yet still dropped by a specific transport (REQ-001) or by every transport
(REQ-005, bit 39).

## Candidate findings carried from Phase 1 (NOT yet confirmed)

Phase 1 EXPLORATION.md identified six candidate bugs. They are NOT confirmed here — Phase 3/4 will
confirm or reject them. Listed so the reconciliation step has the carry-forward set:

1. MMIO/vDPA finalize_features strip transport bits 37/39/40/41 (REQ-001).
2. NOTIF_CONFIG_DATA(39) never re-added even on modern PCI (REQ-005, REQ-002).
3. vm_reset omits the spec-mandated post-write status poll (REQ-003).
4. vp_interrupt returns IRQ_NONE for config-change-only interrupts (REQ-004).
5. Memory-barrier presence between descriptor writes and index updates (REQ-008).
6. Driver-requested queue size validation against device max (REQ-009).
