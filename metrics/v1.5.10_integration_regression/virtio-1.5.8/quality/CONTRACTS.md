## drivers/virtio/virtio_ring.c (8 contracts)

1. [INVARIANT] `vring_transport_features()` (virtio_ring.c:3505-3532): the switch is a closed
   whitelist over the transport feature-bit range; any bit `i` in
   `[VIRTIO_TRANSPORT_F_START, VIRTIO_TRANSPORT_F_END)` that is NOT an explicit `case` label
   hits `default:` (line 3527) and is cleared via `__virtio_clear_bit(vdev, i)` (line 3529).
2. [INVARIANT] [should exist] `vring_transport_features()` must enumerate (as a `case` label) or
   the calling transport must compensate for every transport bit any transport supports. The
   switch handles only 8 of the 12 defined transport bits — INDIRECT_DESC(28), EVENT_IDX(29),
   VERSION_1(32), ACCESS_PLATFORM(33), RING_PACKED(34), IN_ORDER(35), ORDER_PLATFORM(36),
   NOTIFICATION_DATA(38). Missing: SR_IOV(37), NOTIF_CONFIG_DATA(39), RING_RESET(40),
   ADMIN_VQ(41).
3. [INVARIANT] Packed-ring ownership encoding: `avail_wrap_counter` and `avail_used_flags` must
   toggle together when the ring wraps (virtio_ring.c packed wrap site ~1580-1583). Toggling one
   without the other gives descriptors the wrong AVAIL/USED ownership bit.
4. [ORDER] Split and packed paths must issue a memory barrier (`virtio_wmb`/`virtio_store_mb`)
   between every descriptor write and the index update that publishes it (barrier sites in
   virtio_ring.c include 756, 802, 939, 964, 1111, 1569, 1743, 1901, 2085, 2125, 2184). On
   weakly-ordered arches a missing barrier corrupts the ring.
5. [LIFECYCLE] [should exist] The virtqueue-creation path (`vring_create_virtqueue` family near
   virtio_ring.c:3505) should reject a driver-requested queue size larger than the
   device-advertised maximum (spec §9 "Queue Size Negotiation").
6. [METHOD] `vring_transport_features()` returns void and mutates `vdev->features` in place — the
   caller's view of negotiated features is whatever survives the switch.
7. [COMPAT] The whitelist preserves legacy ring features (INDIRECT_DESC, EVENT_IDX) so pre-1.0
   devices negotiate correctly.
8. [INVARIANT] The function operates over `vdev->features` only; it has no knowledge of which
   transport is calling it, so it cannot itself re-add transport-specific bits — that
   responsibility is delegated entirely to the per-transport `finalize_features`.

## drivers/virtio/virtio.c (4 contracts)

9. [LIFECYCLE] `virtio_finalize_features()` preserve loop (virtio.c:319-321): for every bit in
   `[VIRTIO_TRANSPORT_F_START, VIRTIO_TRANSPORT_F_END)` the device offered, the core re-adds it
   to `vdev->features` via `__virtio_set_bit` BEFORE calling the per-transport finalize. Comment:
   "Transport features always preserved to pass to finalize_features."
10. [LIFECYCLE] `virtio_finalize_features()` then calls `dev->config->finalize_features(dev)`
    (virtio.c:323). Whatever transport bits the per-transport finalize fails to re-preserve after
    `vring_transport_features` are destroyed even though both device and driver wanted them.
11. [METHOD] `virtio_features_ok()` (virtio.c:204-235): sets `VIRTIO_CONFIG_S_FEATURES_OK`
    (line 227), re-reads status (line 228), and returns -ENODEV if the bit did not stick
    (lines 229-232) — the spec §1 MUST for modern devices.
12. [COMPAT] `virtio_features_ok()` early-returns 0 for non-VERSION_1 (legacy) devices
    (lines 224-225) before touching FEATURES_OK — legacy devices have no safe failure mechanism,
    so the negotiation-acceptance confirmation is intentionally absent on that path.

## drivers/virtio/virtio_pci_modern.c (6 contracts)

13. [LIFECYCLE] `vp_finalize_features()` (virtio_pci_modern.c:420-443) calls
    `vring_transport_features(vdev)` (line 426) THEN `vp_transport_features(vdev, features)`
    (line 429) — the compensation step runs after the whitelist clears bits.
14. [INVARIANT] `vp_transport_features()` (virtio_pci_modern.c:367-381) re-adds exactly three
    transport bits cleared by the whitelist: SR_IOV(37) guarded by
    `pci_find_ext_capability(..., PCI_EXT_CAP_ID_SRIOV)` (line ~374), RING_RESET(40) (line ~377),
    ADMIN_VQ(41) (line ~380). It does NOT re-add NOTIF_CONFIG_DATA(39).
15. [INVARIANT] [should exist] `vp_check_common_size()` (virtio_pci_modern.c:405-417) validates
    config-space sizing for NOTIF_CONFIG_DATA(39), RING_RESET(40), ADMIN_VQ(41). The
    NOTIF_CONFIG_DATA(39) check is unreachable because `vp_transport_features` never re-adds
    bit 39, so it is always cleared before this check runs.
16. [LIFECYCLE] `vp_reset()` (virtio_pci_modern.c:546-565): writes 0 to status (line 552) THEN
    polls `while (vp_modern_get_status(mdev)) msleep(1);` (lines 558-559) — spec §5 MUST
    "wait for status read 0 before reinit." CONFORMANT.
17. [METHOD] `vp_finalize_features()` writes the negotiated feature set to the device via
    `vp_modern_set_extended_features` (line ~440) after compensation.
18. [INVARIANT] [should exist] The set of bits `vp_transport_features` re-adds (37/40/41) and the
    set `vp_check_common_size` validates (39/40/41) must agree about which bits can survive
    negotiation. They disagree on bit 39.

    (lines 120-121) but DISCARDS its return value; returns `vp_vring_interrupt(irq, opaque)`

20. [INVARIANT] `vp_config_changed()` (virtio_pci_common.c:73-80) returns IRQ_HANDLED
    unconditionally (line 79).
21. [INVARIANT] `vp_vring_interrupt()` (virtio_pci_common.c:83-98) returns IRQ_NONE when no vring
    callback fires (line 97).
22. [INVARIANT] [should exist] `vp_interrupt()` must return IRQ_HANDLED whenever it serviced a

    (isr == VIRTIO_PCI_ISR_CONFIG, no vring work) returns IRQ_NONE — the genuine interrupt is
    reported to the kernel as spurious.

## drivers/virtio/virtio_mmio.c (5 contracts)

23. [LIFECYCLE] `vm_finalize_features()` (virtio_mmio.c:109-132) calls
    `vring_transport_features(vdev)` (line 114) then writes `vdev->features` to the
    `VIRTIO_MMIO_DRIVER_FEATURES` registers (lines 123-129). There is NO transport-bit
    re-preservation step.
24. [INVARIANT] [should exist] `vm_finalize_features()` must re-preserve every device-offered
    transport bit the whitelist cannot enumerate. As written it strips RING_RESET(40),
    ADMIN_VQ(41), NOTIF_CONFIG_DATA(39), SR_IOV(37) — MMIO devices legitimately support per-queue
    reset.
25. [LIFECYCLE] `vm_reset()` (virtio_mmio.c:251-257): writes 0 to `VIRTIO_MMIO_STATUS` (line 256)
    and returns immediately — NO status poll loop.
26. [INVARIANT] [should exist] `vm_reset()` must satisfy spec §5: "Driver MUST wait for
    device_status read to return 0 before reinitializing." It does not, so reset can race
    reinitialization on a slow backend.
27. [METHOD] `vm_interrupt()` (virtio_mmio.c:285-307): sets `ret = IRQ_HANDLED` on the CONFIG bit
    (lines 296-299) and `ret |= IRQ_HANDLED` on the VRING bit (lines 301-304); returns `ret`
    (line 306). CONFIG-only interrupts return IRQ_HANDLED — CONFORMANT and the cross-transport
    reference for contract 22.

## drivers/virtio/virtio_vdpa.c (3 contracts)

    `vring_transport_features(vdev)` (line 394) then `vdpa_set_features(vdpa, vdev->features)`

29. [INVARIANT] [should exist] `virtio_vdpa_finalize_features()` must re-preserve device-offered

30. [LIFECYCLE] `virtio_vdpa_reset()` (virtio_vdpa.c:86-91) delegates reset to `vdpa_reset`; the
