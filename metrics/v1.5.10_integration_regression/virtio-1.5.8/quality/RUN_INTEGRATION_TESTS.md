## Working Directory

All commands in this protocol use **relative paths from the project root** (the directory
containing `drivers/` and `quality/`). Do not `cd` to an absolute path. Use `./quality/`,
`./drivers/virtio/`, etc.

## Safety Constraints

- DO NOT modify source code under `drivers/` or `include/`.
- DO NOT delete files.
- ONLY create files under `quality/results/`.
- If a check fails, record it and move on — DO NOT fix source from this protocol.

## Environment reality (read before planning)

This is a **sparse kernel-subsystem checkout** with NO kernel build tree (Makefile/Kbuild and the
rest of the kernel are stripped — see `.clean_checkout`: `type: kernel_subsystem`). There is no
in-tree way to compile or boot these drivers. True end-to-end integration (boot a guest, attach a
virtio MMIO device advertising RING_RESET, assert the bit survives negotiation) requires
virtme/QEMU/KVM that does not ship here. Therefore the "integration" surface available in this
environment is **source-level cross-transport consistency**: run the functional source-inspection
suite as the integration check, grouped per use case. The protocol documents the QEMU/KVM matrix
that *would* run end-to-end so a maintainer with a full tree can execute it; in this checkout those
groups are recorded as `skipped` with `pre_flight_error: environment`.

### Per-group commands (relative paths)

```bash
# Group 1
python3 -m pytest -q "quality/test_functional.py" -k "scenario_1 or test_pci_modern_compensator" \
  --junitxml=quality/results/integration-group-1.xml
# Group 3 (mechanical receipt first, then the diff assertion)
python3 quality/mechanical/verify.py > quality/results/integration-group-3.verify.log 2>&1
python3 -m pytest -q "quality/test_functional.py" -k "scenario_6" \
  --junitxml=quality/results/integration-group-3.xml
# ... (remaining groups follow the same shape with their -k selector)
```

### Pre-flight command validation

Before recording any group, confirm its selector discovers tests:
`python3 -m pytest quality/test_functional.py -k "<selector>" --collect-only -q` must list ≥1 test.
If it lists zero, fix the selector (do not record a group whose command fails discovery).

## End-to-end matrix (documented; requires a full kernel + QEMU tree — NOT runnable here)

For a maintainer with a buildable tree, the real integration matrix is a **transport × feature**
grid run under virtme/QEMU/KVM:

| Transport | Feature under test | End-to-end assertion |
|-----------|-------------------|----------------------|
| MMIO | RING_RESET(40) | guest negotiates RING_RESET; `cat /sys/.../features` shows bit 40 set |
| vDPA | RING_RESET(40) | vhost-vdpa backend sees bit 40 in set_features |
| PCI-modern | NOTIF_CONFIG_DATA(39) | `queue_notify_data` config path reachable |
| MMIO | reset timing | reset under load does not race reinit (status reads 0 first) |
| PCI | config interrupt | config-only IRQ not counted as spurious (`/proc/interrupts`) |

In this checkout these are recorded `result: "skipped"`, `notes: {"pre_flight_error": "environment"}`
— no kernel build tree.

## Execution UX

**Phase 1 — Plan:** show the numbered table above before running anything.
**Phase 2 — Progress:** one line per group: `✓ Group 1: transport-bit preservation — PASS (0.1s)`
(use `✓`/`✗`/`⧗`; for an xfail group, report `✓ (xfail — candidate bug detected)`).
**Phase 3 — Results:** summary table with pass/fail/skipped counts and a recommendation. Save the
detailed report to `quality/results/YYYY-MM-DD-integration.md`.

## Structured output (mandatory)

Run each group with `--junitxml=quality/results/integration-group-N.xml`. If the JUnit reporter is
unavailable, set `"junit_available": false` in the sidecar.

Write `quality/results/integration-results.json` using the grouped schema (copy verbatim, fill
values). Required top-level fields: `schema_version`, `skill_version`, `date`, `project`,
`recommendation`, `groups`, `summary`, `uc_coverage`. Every group needs `group`, `name`,
`use_cases`, `result`, `notes`. `uc_coverage` must map every UC (UC-1.a/b/c, UC-2, UC-3.a/b/c,
UC-4.a/b/c, UC-5). Valid `result`: `pass`/`fail`/`skipped`/`error`. Valid `recommendation`:
`SHIP`/`FIX BEFORE MERGE`/`BLOCK`. Map each UC to `covered_pass`/`covered_fail`/`not_mapped`.

**Post-write validation:** reopen `integration-results.json` and verify all required fields are
present, every group has the required keys, all enum values are legal, `uc_coverage` covers all 11
UCs, and no undocumented root keys exist.
