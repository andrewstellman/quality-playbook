# Spec Audit Protocol: go-chi/chi v1.5.8 — Council of Three

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.3 — Andrew Stellman
> Date: 2026-06-19 · Project: go-chi/chi v1.5.8

Three independent AI models audit chi against its specifications. Each model performs a full
independent audit; cross-referencing catches what any single model misses. Minority findings
(one of three) get a mandatory re-investigation, not a default discard.

**Specification reality for chi.** There is NO `reference_docs/cite/` subdirectory — zero
citable formal-spec files in this tree. The authoritative specs for the parsing REQs are
**external standards**: RFC 7231 §5.3.4 (Accept-Encoding/q-value), RFC 7230 §3.2.6
(token/comma-list/OWS), RFC 2046 (charset parameter quoting), RFC 7239 (Forwarded/XFF).
chi's own `reference_docs/` (18 Tier-4 context files) and package doc comments are the
internal sources. Findings grounded in an RFC are **spec violations**; findings grounded only
in chi's own comments/README are **code inconsistencies** — note the distinction per finding.

## The Definitive Audit Prompt

> *(Give this identical prompt to each of the three models.)*
>
> **Context files to read:** `quality/QUALITY.md`, `quality/REQUIREMENTS.md`,
> `quality/CONTRACTS.md`, `quality/EXPLORATION.md`, and the source files `mux.go`, `tree.go`,
> `context.go`, and the middleware in `middleware/` named by the REQs. Also read
> `quality/mechanical/verify_receipt.txt` for the method-map enumeration result.
>
> **Task:** Act as the Tester. For each requirement and contract, determine whether the code
> matches the documented/specified behavior. You are auditing for divergence between intent
> and implementation, not judging whether the code is "good."
>
> **Requirement confidence tiers:** `formal` (cites an external RFC), `user-confirmed`,
> `inferred` (derived from chi's own structure/comments). Tag every finding with its tier.
>
> **Rules:**
> - Line numbers mandatory on every finding.
> - Read function bodies, not signatures.
> - Grep before claiming something is missing.
> - For any whitelist/enumeration claim, extract the code-side list FRESH (or cite the
>   mechanical `*_cases.txt` receipt) — never copy from REQUIREMENTS.md/CONTRACTS.md.
> - A code-path trace showing a behavioral violation is sufficient to confirm — do NOT defer
>   pending runtime evidence.
>
> **Defect classifications:** `MISSING` / `DIVERGENT` / `UNDOCUMENTED` / `PHANTOM`
> (+ `NEEDS REVIEW` for inferred-tier findings).
>
> **Project-specific scrutiny areas (answer each as a question):**
> 1. Does `matchAcceptEncoding` (`compress.go:240-246`) honor `q=0` and reject substring
>    false-positives like `xgzip`, or does it `strings.Contains`?
> 2. Does `realIP` (`realip.go:50-55`) `TrimSpace` the leftmost XFF element before `ParseIP`?
> 3. Does `contentEncoding` (`content_charset.go:29-45`) match a quoted `charset="utf-8"`?
> 4. Do `SupressNotFound`/`PageRoute`/`PathRewrite` read/write `rctx.RoutePath` or raw `r.URL.Path`?
> 5. Does `Mux.Find` (`mux.go:368-393`) perform the wildcard-URLParam reset the live mount
>    closure does (`mux.go:309-322`)?
> 6. Does `replaceWildcards` (`context.go:136-144`) erase a legitimate interior `*` segment?
> 7. Do `methodMap`/`reverseMethodMap`/`mALL` enumerate the same set? (cite mechanical receipt)
> 8. Does `isCompressible` (`compress.go:274-288`) gate on the documented closed set only?
> 9. Does `findRoute` keep `routeParams.Keys`/`Values` length-consistent across both unwind
>    sites (`tree.go:457-490`, `534-539`)?
>
> **Output format:**
> ```
> ### [filename.go]
> - **Line NNN:** [MISSING / DIVERGENT / UNDOCUMENTED / PHANTOM] [Req: tier — source] Description.
>   Spec says: [quote, e.g. RFC 7231 §5.3.4 "a qvalue of 0 means not acceptable"].
>   Code does: [what happens].
> ```

## Pre-audit docs validation (required triage section — fires in EVERY triage)

Even though chi has no `reference_docs/cite/`, the triage MUST record:
- That zero citable formal-spec files exist; therefore every RFC citation is an external
  standard, not a repo file.
- That `quality/mechanical/verify_receipt.txt` is the authoritative enumeration evidence for
  REQ-003 — auditors must not re-assert method-map consistency from memory.

## Running the Audit

Save each model's report to `quality/spec_audits/2026-06-19-auditor-1.md`,
`-auditor-2.md`, `-auditor-3.md` (filenames MUST contain `auditor` — the gate globs `*auditor*`).
Assign secondary emphasis lenses without restricting coverage: auditor-1 → input/parser
validation, auditor-2 → composition/mount-context, auditor-3 → enumeration/state. Each still
performs a full independent audit.

## Triage Process

Merge findings into `quality/spec_audits/2026-06-19-triage.md`.

| Confidence | Found By | Action |
|------------|----------|--------|
| Highest | All three | Confirm |
| High | Two of three | Confirm after a verification probe |
| Needs verification | One only (minority) | **Mandatory re-investigation** — read the code, write an executable assertion, CONFIRM or reject |

Include a `## Council Status` block logging effective council size (e.g. "Effective council:
3/3") and an auditor-agreement column per finding.

### The Verification Probe (executable evidence — mandatory)
Probe assertions MUST be written to `quality/spec_audits/triage_probes.sh` (an executable
file), not merely narrated. For chi these are source-inspection assertions:
- **Confirm** (expected-FAIL assertion): e.g.
  `grep -q 'strings.TrimSpace' <(sed -n "42,56p" middleware/realip.go) || echo "REQ-002: realIP does NOT TrimSpace leftmost XFF (line 50) — CONFIRMED"`
- **Reject** (PASS assertion): if rejecting a finding, write an assertion that passes proving
  the finding wrong (e.g. the case label IS present). If you cannot write a passing assertion,
  do NOT reject — escalate.
- Every assertion cites an exact line number with the literal line contents. No majority-vote
  resolutions; no prose-only probes.

### Spot-check format (extract, don't assert)
```
Claim: "realIP trims whitespace before parsing"
Actual line 50: `ip, _, _ = strings.Cut(xff, ",")`   (no TrimSpace)
Result: CLAIM IS FALSE — leftmost element is not trimmed; REQ-002 CONFIRMED.
```

### Categorize each confirmed finding (6 categories)
Spec bug / Design decision / Real code bug / Documentation gap / Missing test / Inferred
requirement wrong. The RealIP trust-model direction (leftmost vs rightmost) is a **Design
decision** flagged by the doc comment — only the *whitespace trim* is a Real code bug.

### Cross-artifact consistency check
Confirm the triage's enumeration claims match `quality/mechanical/*_cases.txt`. A triage that
disagrees with the mechanical receipt without re-running it is non-conformant.

## Detecting partial sessions and carried-over artifacts

If an auditor file or triage is carried over from a prior run, prepend the mandatory provenance
header:
```
<!-- PROVENANCE: This file was carried over from a previous run ([date]).
     It was NOT regenerated by the current v1.5.8 run.
     Treat findings as potentially stale — verify against current source before acting. -->
```
A `spec_audits/` with no triage summary, or auditor files with no real findings, is a gate
failure (spec audit did not run), not a clean run.

## Fix Execution Rules

Group fixes by subsystem (parsers; composition/mount; enumeration) — never one mega-prompt.
Each fix batch needs ≥2 auditors confirming. All source changes are expressed as patches under
`quality/patches/` (the playbook never edits source directly).

## Output

- `quality/spec_audits/2026-06-19-auditor-1.md`, `-2.md`, `-3.md` (mandatory individual reports)
- `quality/spec_audits/2026-06-19-triage.md` (merged, with Council Status + categorization)
- `quality/spec_audits/triage_probes.sh` (executable probe assertions)
