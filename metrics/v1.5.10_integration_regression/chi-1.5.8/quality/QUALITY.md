# Quality Constitution: go-chi/chi v1.5.8

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.3 — Andrew Stellman
> Date: 2026-06-19 · Project: go-chi/chi v1.5.8

## Purpose

chi is an HTTP request router: its single job is to take a request path, match it against
registered patterns in a radix trie, capture URL params, and dispatch to the correct handler
through a middleware chain. For a router, **fitness for use** (Juran) is not "the tests pass"
— it is "every request reaches the handler the application author intended, and every
middleware decision (compress, reject, rewrite, real-IP) reflects what the client actually
asked for." A router that misroutes one in a thousand requests under composition, or
compresses a body the client rejected with `q=0`, is unfit even at 95% line coverage.

**Quality must be built in, not inspected in** (Deming). chi's largest risk is structural:
two representations of the request path (`r.URL.Path` raw vs `rctx.RoutePath` canonical) and
three representations of the method set (`methodMap`/`reverseMethodMap`/`mALL`) that must stay
in lock-step. These invariants cannot be inspected at the end — they must be encoded as
requirements and tests that fail the moment a representation drifts.

**Quality is free** (Crosby): the cost of the substring Accept-Encoding match or the
raw-`URL.Path` middleware cohort is paid not by chi's CI (which is green) but by every
downstream operator whose proxy pads an XFF header, or who mounts a sub-router and watches
`SupressNotFound` return spurious 404s. Catching these here is cheaper than the support load
they generate in production.

- **Deming** — defects are designed out by encoding the path/method invariants as tests, not caught by a final review pass.
- **Juran** — fitness = correct routing + spec-faithful middleware decisions under composition, not coverage percentage.
- **Crosby** — the price of nonconformance is silent misrouting and wrong wire behavior in deployments, not visible CI failures.

## Coverage Theater Prevention

These are fake-test patterns specific to this codebase. A test that does any of the
following inflates the count without catching a real chi bug:

- **Canonical-input-only testing.** Calling `selectEncoder` with `Accept-Encoding: gzip` and asserting it returns `"gzip"` proves nothing — the bug is in `gzip;q=0` and `xgzip`. The existing `compress_test.go` (217 lines) does exactly this and misses both defects. A real test feeds the spec-valid edge input.
- **Top-level-only middleware testing.** Exercising `PageRoute`/`PathRewrite`/`SupressNotFound` only at the router root (where `RoutePath == URL.Path`) hides the entire bug, which only appears under `Mount()`. A real test mounts a sub-router and asserts the mounted behavior.
- **Asserting the map exists.** `assert methodMap != nil` or `len(methodMap) == 9` is theater. The real invariant is cross-map consistency: every `methodMap` key has a `reverseMethodMap` value and `mALL` ORs every bit.
- **Round-tripping the buggy code against itself.** Asserting `matchAcceptEncoding([]string{"xgzip"}, "gzip") == true` documents the bug as if it were intended. Regression tests must assert the *desired correct* behavior (xfail/skip-guarded), never the current buggy output.
- **Pattern-string equality on canonical patterns only.** Asserting `RoutePattern()` returns `/files/*` for a route `/files/*` is fine but insufficient — the bug is an *interior* literal `*` being collapsed. A real test registers a pattern that renders with an interior `/*/`.

## Fitness-to-Purpose Scenarios

### Scenario 1: SupressNotFound returns spurious 404 under Mount
**Requirement tag:** [Req: inferred — REQ-001; external: chi composition contract]
**What happened:** Because `SupressNotFound` calls `rctx.Routes.Match(rctx, r.Method, r.URL.Path)` (`middleware/supress_notfound.go:19`) reading the *raw* outer URL, when `child` is mounted at `/api` and a client requests `/api/ping`, `Match` probes the child trie (keyed on `/ping`) with the string `/api/ping`. The probe fails, `SupressNotFound` short-circuits to a 404, and a perfectly valid `/api/ping` route is never served. There is no `supress_notfound_test.go`, so the defect is invisible to CI — every mounted deployment that puts `SupressNotFound` at the top of a sub-router's stack silently 404s its own routes.
**The requirement:** Path-manipulation middleware must match against the canonical mounted path `rctx.RoutePath`, not raw `r.URL.Path`.
**How to verify:** `TestSupressNotFound_MountedMisroutes` — mount a child with a `/ping` route and `SupressNotFound`, request `/api/ping`, assert status 200, not 404.

### Scenario 2: Accept-Encoding `gzip;q=0` is compressed anyway
**Requirement tag:** [Req: formal — RFC 7231 §5.3.4; REQ-002]
**What happened:** `matchAcceptEncoding` decides a coding is accepted iff `strings.Contains(v, encoding)` for any comma element (`middleware/compress.go:240-246`). `Accept-Encoding: gzip;q=0` is an explicit *rejection* of gzip per RFC 7231, yet the element `"gzip;q=0"` contains the substring `"gzip"`, so the match succeeds and chi compresses the response — doing the exact opposite of what the client asked. Worse, `WriteHeader` then sets `Content-Encoding: gzip` (`compress.go:308-315`), so the wire carries a compression claim the client refused. `compress_test.go` has zero `q=0` cases.
**The requirement:** Accept-Encoding must be tokenized; a `q=0` coding must NOT be selected.
**How to verify:** `TestAcceptEncoding_QZeroSuppresses` — call `selectEncoder` (via a `Compressor`) with `Accept-Encoding: gzip;q=0`, assert no gzip encoder is selected.

### Scenario 3: Bogus token `xgzip` falsely selects gzip
**Requirement tag:** [Req: formal — RFC 7230 token grammar; REQ-002, REQ-007]
**What happened:** Same substring match: `Accept-Encoding: xgzip` (not a registered coding) contains `"gzip"`, so `matchAcceptEncoding` returns true. chi then declares `Content-Encoding: gzip` on a body it streams through the gzip writer — but a client that sent `xgzip` does not expect gzip and may not decode it. The substring shortcut turns a nonsense token into a wire-level mis-encoding.
**The requirement:** Only an exact, registered coding name (whitespace-trimmed) may select an encoder.
**How to verify:** `TestAcceptEncoding_BogusTokenRejected` + `TestCompress_NoEncodingHeaderForBogusToken` — assert `xgzip` does not select gzip and no `Content-Encoding: gzip` header is emitted.

### Scenario 4: Method maps drift, corrupting the Allow header
**Requirement tag:** [Req: inferred — REQ-003]
**What happened:** The recognized method set lives in three structures — `methodMap` (string→bit), `reverseMethodMap` (bit→string), and `mALL` (OR of bits) (`tree.go:32-57`). `RegisterMethod` (`tree.go:61-77`) updates all three, but any future edit that touches one without the others silently desyncs them. If a bit is in `methodMap` but missing from `reverseMethodMap`, the 405 handler's `Allow` header (`mux.go:518-526`) omits the method; if `mALL` misses a bit, wildcard registration (`tree.go:355-365`) skips it. Both fail with no error.
**The requirement:** The three structures must enumerate identical method sets; `mALL` must equal the OR of all `methodMap` bits.
**How to verify:** `TestMethodMaps_AreConsistent` + `TestRegisterMethod_UpdatesAllThree` — assert every `methodMap` key↔`reverseMethodMap` value bijection and `mALL == OR(methodMap values)`, then register a custom method and re-assert.

### Scenario 5: RealIP silently drops a space-padded XFF first element
**Requirement tag:** [Req: formal — RFC 7239 / RFC 7230 OWS; REQ-002]
**What happened:** `realIP` takes the leftmost comma segment of X-Forwarded-For via `strings.Cut(xff, ",")` with NO `TrimSpace` (`middleware/realip.go:50`), then requires `net.ParseIP != nil` (`realip.go:52`). A proxy that emits `X-Forwarded-For: 203.0.113.1, 10.0.0.1` is fine, but one that pads the first element (`" 203.0.113.1, ..."` — legal OWS per RFC 7230) yields `" 203.0.113.1"`, which `ParseIP` rejects → `realIP` returns `""` → `RemoteAddr` is left as the proxy address. Operators relying on `RemoteAddr` for rate-limiting or audit silently get the wrong client IP, with no log line.
**The requirement:** The leftmost XFF element must be `TrimSpace`d before parsing.
**How to verify:** `TestRealIP_LeadingSpaceXFF` — set `X-Forwarded-For: " 203.0.113.1"`, run `RealIP`, assert `RemoteAddr == "203.0.113.1"`.

### Scenario 6: ContentCharset rejects a quoted `charset="utf-8"`
**Requirement tag:** [Req: formal — RFC 2046 quoted-string parameter; REQ-002]
**What happened:** `contentEncoding` (mislabeled — it parses charset, not encoding) chains `split` on `;`, `charset=`, `;` and `TrimSpace`s but never strips quotes (`middleware/content_charset.go:29-45`). A request with `Content-Type: text/plain; charset="utf-8"` yields the token `"utf-8"` (with literal quotes), which is not in the lowered allow-set `{utf-8}`, so `ContentCharset("utf-8")` returns a 415 Unsupported Media Type for a perfectly valid quoted charset.
**The requirement:** A quoted parameter value (`charset="utf-8"`) must match the same as the unquoted form.
**How to verify:** `TestContentCharset_QuotedCharset` — wrap a handler in `ContentCharset("utf-8")`, send `Content-Type: text/plain; charset="utf-8"`, assert status 200, not 415.

### Scenario 7: RoutePattern collapses a literal interior wildcard segment
**Requirement tag:** [Req: inferred — REQ-005]
**What happened:** `replaceWildcards` loops `strings.ReplaceAll(p, "/*/", "/")` until no `/*/` remains (`context.go:136-144`), and `walk()` does the same on full routes (`tree.go:862`). The collapse is purely textual: a route whose joined pattern legitimately contains an interior `/*/` has that segment rewritten away. Instrumentation middleware reading `RoutePattern()` then reports a pattern that was never registered, mislabeling metrics and traces for that route.
**The requirement:** Only synthesized mount wildcards may be collapsed; a literal interior `*` segment must survive.
**How to verify:** `TestReplaceWildcards_DoesNotEraseInterior` + `TestRoutePattern_PreservesTrailingWildcard` — assert a trailing `/*` survives and document the interior-collapse behavior as an xfail regression case.

### Scenario 8: Mux.Find leaves a stale `*` URLParam the live path clears
**Requirement tag:** [Req: inferred — REQ-004]
**What happened:** The live mount closure shifts `RoutePath` AND zeroes the connecting `*` URLParam (`mux.go:309-322`), but `Find` performs only the shift (`mux.go:383`), omitting the URLParam reset. `Find`/`Match` are documented to mirror real routing "without executing the handler" (`mux.go:353-368`), yet a `Find` against a mounted route leaves a stale `*` value the live dispatch would have cleared — so code that uses `Find` to introspect routing observes a context the real request never would.
**The requirement:** `Find`'s observable context effects on a mounted route must match the live dispatch closure (including the URLParam reset), or the divergence must be documented.
**How to verify:** `TestFind_VsLive_MountedURLParamReset` — register `root.Mount("/api", child)`, run a live request and a `Find` for the same path, compare the resulting `*` URLParam state.

### Scenario 9: PathRewrite is invisible to routing under Mount
**Requirement tag:** [Req: inferred — REQ-001]
**What happened:** `PathRewrite` rewrites and writes back `r.URL.Path` only (`middleware/path_rewrite.go:11-12`). Under `Mount()`, chi's subsequent route walk reads `rctx.RoutePath` first (`mux.go:441-456`), so the rewrite never reaches the router — the rewrite "succeeds" on `r.URL.Path` but chi routes the un-rewritten canonical path. The middleware appears to work (the field changed) while having zero effect on routing.
**The requirement:** `PathRewrite` must update `rctx.RoutePath` so the rewrite affects routing under composition.
**How to verify:** `TestPathRewrite_MountedInvisible` — mount a child, install `PathRewrite("/old", "/new")`, request `/svc/old`, assert the `/new` handler runs (xfail under current code).

## AI Session Quality Discipline

Every AI session working on chi must:

1. Read this `QUALITY.md` and `REQUIREMENTS.md` before writing or modifying router/middleware code.
2. Run the full test suite (`go test ./...`) before declaring any change complete — not just the package touched.
3. When adding a middleware that reads the request path, use `chi.RouteContext(r.Context()).RoutePath` (canonical), never raw `r.URL.Path`, unless the middleware is explicitly documented as top-level-only.
4. When editing the method maps, update `methodMap`, `reverseMethodMap`, AND `mALL` together, and add/extend `TestMethodMaps_AreConsistent`.
5. Never assert the current buggy behavior in a test as if it were correct — regression tests assert the desired correct behavior under a skip/xfail guard citing the BUG id.
6. Never delete a fitness scenario or its test to make the suite pass; fix the code or escalate to the Human Gate.

## The Human Gate

These require human judgment and must not be auto-resolved by an AI session:

- **Whether to fix RealIP's leftmost-element trust model** vs only the whitespace trim — the leftmost-vs-rightmost XFF choice is a deployment trust decision (RFC 7239 leaves direction to the operator), flagged in the doc comment (`realip.go:24-30`). Only the *whitespace trim* defect is unambiguous; changing the trust model is a human call.
- **Whether `Mux.Find` should mirror the URLParam reset or be documented as not doing so** — both are valid resolutions of REQ-004; pick the one matching chi's intended introspection contract.
- **Whether to expand `defaultCompressibleContentTypes`** to include `application/ld+json`, `text/csv`, etc. — adding entries changes default wire behavior for existing deployments; a maintainer decision.
- **Any change to the public `Router`/`Routes` interface surface** in `chi.go` — API-compatibility decisions belong to the maintainers.
