# Integration Test Protocol: go-chi/chi v1.5.8

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.3 — Andrew Stellman
> Date: 2026-06-19 · Project: go-chi/chi v1.5.8

## Working Directory

All commands run **from the project root** (the directory containing `go.mod`/`tree.go`) using
**relative paths**. Never `cd` to an absolute path — the protocol must run on any machine.
chi has no external services, databases, or API keys; integration here means end-to-end
routing through a real `httptest.Server` exercising each use case's user-observable outcome.

## Safety Constraints

- Tests spin up in-process `httptest.NewServer` instances on ephemeral ports — no privileged
  ports, no network egress, no persistent state.
- The playbook NEVER modifies source outside `quality/`. New tests proving a bug are expressed
  as patches under `quality/patches/` or run from `quality/test_*.go` copied to the repo root
  only for the duration of a run.
- `go test` resolves dependencies via the standard module proxy in online mode (chi has no
  third-party deps beyond the stdlib, so the suite runs offline too).

## Pre-Flight Check

- [ ] `go version` succeeds (Go ≥ 1.23 per `go.mod`).
- [ ] `go build ./...` succeeds from the repo root.
- [ ] `go vet ./...` succeeds.

## Test Matrix

Each group maps to **≤2 use cases**. Groups are split with `-run` selectors so a failure
isolates which use case broke. Existing chi tests are reused where they already exercise the
end-to-end behavior; new behavioral tests come from `quality/test_functional.go`.

| Group | Use cases | Method | Pass Criteria |
|-------|-----------|--------|---------------|
| 1 | UC-1.a, UC-1.c | Mount a sub-router with `SupressNotFound`/`PathRewrite`; request the mounted path | Valid mounted route served (not 404); rewrite affects routing — *expected to FAIL on current code, exposing REQ-001* |
| 2 | UC-1.b | Mount a sub-router with `PageRoute`; request the mounted path | PageRoute fires for the mounted path — *expected FAIL, REQ-001* |
| 3 | UC-2 | Send `gzip;q=0`, `xgzip`, quoted charset, padded XFF | q=0 not compressed; xgzip not selected; quoted charset matched; padded XFF parsed — *expected FAIL, REQ-002* |
| 4 | UC-3 | Register methods + 405 on unsupported method | `Allow` lists registered methods; mechanical receipt confirms map consistency — *expected PASS* |
| 5 | UC-4.a, UC-4.b | `Find` vs live walk on top-level and mounted routes | Pattern + context effects match live walk — top-level PASS, mounted URLParam-reset *expected FAIL, REQ-004* |
| 6 | UC-5.a, UC-5.b | `RoutePattern()` / `Walk()` with trailing + interior wildcard | Trailing `*` preserved (PASS); interior literal `*` survives — *expected FAIL, REQ-005* |
| 7 | UC-6, UC-7 | Compress whitelisted vs non-whitelisted; bogus-token encoding header | Only whitelisted compressed; no `Content-Encoding` on uncompressed body — UC-6 PASS, UC-7 *expected FAIL, REQ-007* |
| 8 | UC-8 | Deep tree with mixed param/regexp/catch-all siblings forcing backtracking | `URLParam` values align by index — *PASS unless skew reproduced* |
| 9 | [Infrastructure] | `go build ./...`, `go vet ./...`, `go test -race ./...` (existing suite) | Build, vet, and the existing ~90-test suite pass with `-race` — validates toolchain + no regressions; does NOT count toward UC coverage |

### Design Principles for Integration Checks
- Each behavioral group exercises the **end-to-end user outcome** (a real request through a
  real router), not just a unit call.
- "Expected FAIL" groups document the Phase-1 candidate bugs; they become the regression
  evidence in Phase 3/5. A `covered_fail` for these is the *correct* state pre-fix.
- Group 9 is the only `[Infrastructure]` group and is the guard against breaking chi's own suite.

## Automated Integration Tests

Run from the repo root. To execute `quality/test_functional.go`, copy it in as a `_test.go`
file for the run (Go requires `*_test.go` naming) or maintain it as `quality_functional_test.go`:

```
cp quality/test_functional.go ./quality_functional_test.go   # one-time per run
go test -run 'Quality' .                                     # functional groups
go test -race ./...                                          # group 9 infra (existing suite)
python quality/mechanical/verify.py                          # group 4 mechanical receipt
rm -f ./quality_functional_test.go                           # cleanup
```

## Pre-flight command validation (mandatory)

Confirm each group's selector discovers tests before recording results:
```
go test -run 'Quality' -list '.' .        # must list the functional tests
go test -list '.' .                       # must list the existing suite
```
If a selector lists zero tests, fix the `-run` pattern before recording the group (a zero-test
discovery would mask a selector bug as a code bug). A *build* failure during discovery is an
`"pre_flight_error": "environment"` — do not retune the selector.

## Manual Verification Steps

- After group 3, inspect the response headers for the `gzip;q=0` request: `Content-Encoding`
  must be absent once REQ-002 is fixed.
- After group 4, read `quality/mechanical/verify_receipt.txt` — it must show all three method
  structures enumerating the identical 9-method set.

Valid `recommendation`: `SHIP`/`FIX BEFORE MERGE`/`BLOCK`. Valid `uc_coverage`:
`covered_pass`/`covered_fail`/`not_mapped`.
