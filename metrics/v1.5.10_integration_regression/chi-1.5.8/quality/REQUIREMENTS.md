## Functional Section: Composition and Mount-Context Awareness

chi's defining feature is sub-router composition via `Mount`/`Route`. Under `Mount()`, chi
maintains a canonical mount-relative path in `rctx.RoutePath` (set in `mux.go:309-322` and
`mux.go:383`) that diverges from the raw `r.URL.Path` (which always carries the full outer
URL). Middleware and lookup paths that read the wrong representation silently misbehave once
a sub-router is mounted. This section captures the requirements that keep composition correct.

### REQ-001: Path-manipulation middleware must operate on chi's canonical mounted path (`rctx.RoutePath`), not raw `r.URL.Path`, so behavior is correct under `Mount()`.
- Conditions of satisfaction:
  - `SupressNotFound` (`middleware/supress_notfound.go:18-19`) must match against `rctx.RoutePath`, not `r.URL.Path`, when a sub-router is mounted, so a request to `/api/ping` under `root.Mount("/api", child)` consults the child trie key `/ping`.
  - `PageRoute` (`middleware/page_route.go:13`) must compare its configured path against `rctx.RoutePath` (the mount-relative path), not `r.URL.Path`, so `PageRoute("/status", h)` inside a `child` mounted at `/admin` fires for `/admin/status`.
  - `PathRewrite` (`middleware/path_rewrite.go:11-12`) must update the canonical routing path (`rctx.RoutePath`) it intends chi to route on, not only `r.URL.Path`, so the subsequent chi walk (which reads `rctx.RoutePath` first at `mux.go:441-456`) observes the rewrite.
  - Contrast (already correct): `StripSlashes` (`middleware/strip.go:17-29`), `GetHead` (`middleware/get_head.go:13-21`), `URLFormat` (`middleware/url_format.go:54-67`) read/write `rctx.RoutePath`.
- References: middleware/supress_notfound.go, middleware/page_route.go, middleware/path_rewrite.go
- Pattern: parity
- Asymmetry-promotion: Finding 7 prose asymmetry "canonical-aware cohort reads `rctx.RoutePath`; raw cohort relies entirely on `r.URL.Path`" is promoted here to a multi-site parity REQ.
- Use cases: UC-1.a, UC-1.b, UC-1.c

### REQ-004: `Mux.Find`/`Mux.Match` must mirror live routing's observable context effects (including the mount wildcard-URLParam reset) when traversing mounted routes.
- Conditions of satisfaction:
  - On a top-level (non-mounted) route, `Find` (`mux.go:368-393`) returns the matched pattern and leaves context state equivalent to a live walk through `routeHTTP` (`mux.go:460-484`).
  - On a mounted route, the live dispatch closure shifts `rctx.RoutePath = mx.nextRoutePath(rctx)` AND zeroes the connecting `*` URLParam (`mux.go:309-322`). `Find` performs the same `RoutePath` shift (`mux.go:383`) but does NOT perform the wildcard-URLParam reset — so a `Find` against a mounted route leaves a stale `*` URLParam that the live path would have cleared. The two paths must agree on observable context effects, or `Find` must be documented as not mirroring URLParam side-effects.
- References: mux.go (mux.go:383 vs mux.go:309-322)
- Pattern: parity
- Use cases: UC-4.a, UC-4.b

### REQ-005: `RoutePattern()` reconstruction must not corrupt patterns that contain a literal interior wildcard segment.
- Conditions of satisfaction:
  - `Context.RoutePattern()` (`context.go:123-134`) joins `RoutePatterns` and calls `replaceWildcards`, which loops `strings.ReplaceAll(p, "/*/", "/")` until no `/*/` remains (`context.go:136-144`). A route legitimately containing an interior `*` segment must not have that segment textually erased; the reported pattern must faithfully represent the registered pattern.
  - `walk()` performs the same collapse on full routes (`tree.go:862`) and must preserve a literal interior `*` segment identically.
  - The trailing-`//`/`/` `TrimSuffix` order (`context.go:129-132`) must not strip a legitimate trailing component.
- References: context.go, tree.go
- Pattern: parity
- Use cases: UC-5.a, UC-5.b

## Functional Section: Spec-Structured Request-Header Parsing

Several middleware parse RFC-defined request headers (Accept-Encoding, Content-Type charset,
X-Forwarded-For) with substring/`Cut` shortcuts rather than grammar-faithful tokenization.
These pass the existing suite because the suite uses canonical inputs; spec-valid edge cases
produce wrong behavior.

### REQ-002: RFC-defined request-header parsing must follow the grammar (tokenize on the list separator, honor `q=0`, trim whitespace, parse parameters, match exact coding names), not substring/`Cut` shortcuts.
- Conditions of satisfaction:
  - **Accept-Encoding (`middleware/compress.go:212-246`):** `matchAcceptEncoding` must accept a coding iff it appears as an exact comma-list token (after whitespace trim) with a non-zero q-value. `Accept-Encoding: gzip;q=0` (explicit rejection per RFC 7231 §5.3.4) must NOT select gzip; a bogus token like `xgzip` or `notgzip` (which `strings.Contains` falsely matches) must NOT select gzip. Comma elements must be `TrimSpace`d.
  - **Content-Type charset (`middleware/content_charset.go:29-34`):** `contentEncoding` must match a quoted charset such as `charset="utf-8"` and must not be fooled by a `charset` substring appearing inside another parameter value.
  - **X-Forwarded-For (`middleware/realip.go:42-56`):** `realIP` must `TrimSpace` the leftmost comma segment before `net.ParseIP`, so a producer that pads the first element with a leading space (`" 203.0.113.1"`) does not silently leave `RemoteAddr` unchanged. Parse failures must not be masked beyond what RFC 7239 / the doc comment (`middleware/realip.go:24-30`) intend.
- References: middleware/compress.go, middleware/content_charset.go, middleware/realip.go
- Pattern: parity
- Use cases: UC-2

## Functional Section: Enumeration and Representation Completeness

chi maintains hand-maintained closed sets that must stay in lock-step across multiple data
structures and every consumer. Drift between them is silent.

### REQ-003: The HTTP-method closed set must stay consistent across all three structures (`methodMap`, `reverseMethodMap`, `mALL`) and every consumer.
- Conditions of satisfaction:
  - `methodMap` (`tree.go:35-45`), `reverseMethodMap` (`tree.go:47-57`), and `mALL` (`tree.go:32-33`) must enumerate exactly the same method set. Every key in `methodMap` must have a matching value in `reverseMethodMap` (and vice versa), and `mALL` must equal the bitwise OR of every `methodMap` bit.
  - `RegisterMethod` (`tree.go:61-77`) must update all three structures together (it does: `methodMap[method]=mt`, `reverseMethodMap[mt]=method`, `mALL |= mt`).
  - Consumers must observe a consistent set: `routeHTTP` 405s when `RouteMethod` is absent from `methodMap` (`mux.go:462-466`); `methodNotAllowedHandler` builds `Allow` from `reverseMethodMap` (`mux.go:518-526`); the wildcard registration fans across `methodMap` entries (`tree.go:355-365`).
- References: tree.go, mux.go
- Pattern: whitelist
- Use cases: UC-3

### REQ-006: The compressible content-type whitelist must gate compression consistently with its membership check, and its closed set must be the single source of truth for eligibility.
- Conditions of satisfaction:
  - `defaultCompressibleContentTypes` (`middleware/compress.go:16-27`) is the closed set; `isCompressible` (`middleware/compress.go:274-288`) must decide eligibility by exact membership after stripping `;`-parameters, plus the wildcard set (`allowedWildcards`) only when configured.
  - A content type NOT in the set (and not matched by a configured wildcard) must not be compressed; a content type in the set must be eligible. The set membership must not be bypassed or duplicated elsewhere.
- References: middleware/compress.go
- Pattern: whitelist
- Use cases: UC-6

## Functional Section: Compression Header/State Coupling

The compression writer couples `selectEncoder`, `WriteHeader`, and `writer()` so that a
substring-induced false-accept turns into a wire-level `Content-Encoding` claim.

### REQ-007: `compressResponseWriter` must not declare `Content-Encoding` for a body it does not actually compress.
- Conditions of satisfaction:
  - `WriteHeader` (`middleware/compress.go:298-316`) sets `Content-Encoding: <cw.encoding>` and deletes `Content-Length` only when the content is compressible and an encoder was selected; `writer()` (`middleware/compress.go:326-331`) must return the encoding writer iff `cw.compressible`. The declared `Content-Encoding` must match the bytes actually written.
  - Because `cw.encoding` is populated by `selectEncoder` purely from the (substring-matched) Accept-Encoding header (REQ-002), a false-accept (`xgzip`) must not result in `Content-Encoding: gzip` over uncompressed bytes — fixing REQ-002 closes this surface.
- References: middleware/compress.go
- Pattern: parity
- Use cases: UC-7

## Functional Section: Routing Param Backtracking Integrity

### REQ-008: `findRoute` param backtracking must keep `routeParams.Keys` and `routeParams.Values` length-consistent across both unwind sites, so `URLParam` index reads never misalign.
- Conditions of satisfaction:
  - `findRoute` (`tree.go:457-490`, `tree.go:534-539`) pushes a candidate param value and unwinds on failure via two structurally similar cleanup sites; both must keep Keys/Values length-consistent.
  - `FindRoute` appends `paramKeys` to `URLParams` assuming exact Keys↔Values correspondence (`tree.go:386-394`); `Context.URLParam` reads by reverse-index match (`context.go:100-107`). No backtracking path through mixed param/regexp/catch-all siblings may leave a Keys/Values length skew.
- References: tree.go, context.go
- Pattern: parity
- Use cases: UC-8

## Use Cases

Use cases describe end-to-end user-observable outcomes. They render `formal_doc_refs` (none
here — no citable formal docs) but do NOT list `requirements[]` (traceability is REQ → UC).

### UC-1.a: `SupressNotFound` under a mounted sub-router
- Actors: chi `Mux`, an operator mounting a sub-router, an HTTP client
- Preconditions: `root.Mount("/api", child)`; `child` uses `SupressNotFound`
- Flow: request `/api/ping`; middleware must `Match` against the canonical `rctx.RoutePath` (`/ping`), not `r.URL.Path` (`/api/ping`), using a throwaway context
- Postconditions: a defined `/ping` route is found; no spurious 404; live `rctx` unmutated
- formal_doc_refs: (none)

### UC-1.b: `PageRoute` under a mounted sub-router
- Actors: chi `Mux`, operator, client
- Preconditions: `root.Mount("/admin", child)`; `child` uses `PageRoute("/status", h)`
- Flow: request `/admin/status`; the match must compare against `rctx.RoutePath` (`/status`)
- Postconditions: `PageRoute` fires for the mounted path
- formal_doc_refs: (none)

### UC-1.c: `PathRewrite` under a mounted sub-router
- Actors: chi `Mux`, operator, client
- Preconditions: `root.Mount("/svc", child)`; `child` uses `PathRewrite(old,new)`
- Flow: rewrite must update the canonical routing path so chi's subsequent walk (which reads `rctx.RoutePath`) observes the rewrite
- Postconditions: chi routes the rewritten path, not the original
- formal_doc_refs: (none)

### UC-2: RFC-correct request-header parsing (umbrella) <!-- cluster: heterogeneous -->
- Actors: compression/content-negotiation/real-IP middleware, HTTP client behind a proxy
- Preconditions: client sends `Accept-Encoding: gzip;q=0` / `Content-Type: text/plain; charset="utf-8"` / padded or ported `X-Forwarded-For`
- Flow: each parser tokenizes per its RFC (q-value honored, quoted params handled, whitespace trimmed) before deciding
- Postconditions: `q=0` suppresses compression; quoted charset matched; valid XFF entries accepted
- formal_doc_refs: (none — external RFC 7231/7230/7239/2046)

### UC-3: HTTP-method closed-set consistency (umbrella)
- Actors: chi `Mux`, application calling `RegisterMethod`
- Preconditions: a custom method is registered, or a request uses an unsupported method
- Flow: `methodMap`, `reverseMethodMap`, and `mALL` are updated together; `routeHTTP` and the 405 `Allow` builder read a consistent set
- Postconditions: `Allow` header lists exactly the registered methods; wildcard registration covers the new method
- formal_doc_refs: (none)

### UC-4.a: `Find` mirrors live routing on a top-level route
- Actors: code calling `Mux.Find`
- Preconditions: a registered non-mounted route
- Flow: `Find` returns the pattern with the same context effects as a live walk
- Postconditions: pattern returned; context state consistent
- formal_doc_refs: (none)

### UC-4.b: `Find` mirrors live routing on a mounted route
- Actors: code calling `Mux.Find` against a mounted sub-router
- Preconditions: `root.Mount("/api", child)`
- Flow: `Find` shifts `RoutePath` AND performs the wildcard-URLParam reset the live closure does
- Postconditions: returned pattern and resulting context match the live path exactly
- formal_doc_refs: (none)

### UC-5.a: `RoutePattern()` for a route with a trailing wildcard
- Actors: instrumentation middleware reading `RoutePattern()`
- Preconditions: route `/files/*`
- Flow: `replaceWildcards` collapses only synthesized mount wildcards
- Postconditions: reported pattern preserves a legitimate trailing `*`
- formal_doc_refs: (none)

### UC-5.b: `walk()` full-route reconstruction with an interior literal `*`
- Actors: `Walk` consumers (docgen, route listing)
- Preconditions: a route whose pattern legitimately contains an interior `*` segment
- Flow: the `/*/`→`/` collapse must not erase a literal interior segment
- Postconditions: the walked full route is faithful to the registered pattern
- formal_doc_refs: (none)

### UC-6: Compressible content-type whitelist completeness
- Actors: chi `Compress` middleware, an HTTP client requesting compression
- Preconditions: a response with a content type in `defaultCompressibleContentTypes` vs one not in it
- Flow: `isCompressible` decides eligibility by exact membership (plus configured wildcards)
- Postconditions: only whitelisted (or wildcard-configured) types are compressed
- formal_doc_refs: (none)

### UC-7: Compression writer does not over-declare `Content-Encoding`
- Actors: chi `Compress` middleware, an HTTP client
- Preconditions: a request whose Accept-Encoding falsely selects an encoder (REQ-002 surface)
- Flow: `WriteHeader`/`writer()` couple so the declared `Content-Encoding` matches the bytes written
- Postconditions: no `Content-Encoding` header on a body that was not actually compressed
- formal_doc_refs: (none)

### UC-8: Param backtracking keeps Keys/Values aligned
- Actors: chi router walking a deep tree with mixed param/regexp/catch-all siblings
- Preconditions: a registration set that forces backtracking across sibling node types
- Flow: `findRoute` unwinds candidate values without skewing Keys vs Values length
- Postconditions: `URLParam` returns the correct value by index; no param misalignment
- formal_doc_refs: (none)
