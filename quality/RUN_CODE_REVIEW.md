## Pass 1 — Structural Review

Address each scrutiny area as a labeled subsection:

1. **Input validation / boundaries** — manifest entries, config JSON, `started_at` parsing (`inflight_registry._parse_iso_utc`), git porcelain parsing (`run_state_lib.validate_no_source_edits`).
2. **Resource lifecycle** — slot reserve→`update_pid`→`release_run_slot` symmetry across BOTH launch paths; `pid=0` placeholder age-out; worktree teardown in `_collect_one_run_detached`.
3. **Concurrency / state management** — the `manifest.json ⇄ inflight_registry ⇄ status.json` triangle; lock scope (`_locked_registry` covers the registry only); the run `state` machine (PENDING→RUNNING→DONE) and its missing PENDING→RUNNING edge.
4. **Unit / encoding correctness** — timestamp formats (`%Y-%m-%dT%H:%M:%SZ` vs ISO with offset), deadline arithmetic (`time.monotonic` vs wall clock).
5. **Enumeration / whitelist completeness** — mechanical two-list check of `status._PHASE_ARTIFACTS` (List A: the map's entries with line numbers) against `bin/run_playbook.py:1522-1523` + SKILL.md artifact contract (List B: each phase's true exclusive boundary marker). Extract List A from the code, not from REQUIREMENTS.md.
