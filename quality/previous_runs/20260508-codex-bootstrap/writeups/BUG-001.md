## Summary
docs_present() ignores cite-only `reference_docs/cite/` trees and still drives code-only startup behavior.

## Spec reference
- Requirement: REQ-001
- Spec basis: `quality/REQUIREMENTS.md:13-24`
- Behavioral contract quote: "treat plaintext files under `reference_docs/cite/` as valid documentation input"

## The code
At `bin/run_playbook.py:1568-1574`, `bin/run_playbook.py:1583-1595`, `bin/run_playbook.py:1661-1669` At `bin/run_playbook.py:1568-1574`, `docs_present()` scans only the immediate entries under `reference_docs/` and `docs_gathered/` and returns `True` for any non-dot file. The sibling helpers at `bin/run_playbook.py:1583-1595` and `bin/run_playbook.py:1661-1669` recurse into `reference_docs/cite/` and filter to recognized plaintext docs, so the startup-warning predicate diverges from the stored documentation-state logic.

## Observable consequence
When a repository contains only `reference_docs/cite/spec.md`, the run should be treated as docs-backed and should not emit a code-only warning. Instead, `docs_present()` returns `False`, so startup warning paths still classify the repo as code-only even though the canonical documentation-state helpers treat the same tree as docs-backed.

## The fix
Routing `docs_present()` through the same recognized-plaintext rules used by the other documentation-state helpers restores parity for cite-only trees and stops README-only or binary-only files from being misclassified as documentation.
