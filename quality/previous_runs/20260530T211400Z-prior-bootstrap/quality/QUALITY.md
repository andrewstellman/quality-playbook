## Purpose

Quality for the Quality Playbook is not merely "the repository tests still pass." For this project, fitness for use means that the skill, the Python runner, the bootstrap helpers, and the archive/gate tooling all present the same behavioral contract to a downstream operator or AI agent. If one surface says "docs-backed" while another says "code-only," or the skill requires an exploration gate that the code does not actually enforce, the playbook can generate authoritative-looking artifacts from a contradictory foundation.

Deming applies here because the quality bar has to be built into the artifacts before any later review begins: `quality/EXPLORATION.md`, `QUALITY.md`, `REQUIREMENTS.md`, and the review protocols are the control plane that future sessions inherit. Juran's fitness-for-use lens means a self-audit or installed-target run must classify documentation accurately, preserve the evidence tiers it claims to use, block shallow exploration from proceeding, and archive its findings without format drift. Crosby applies because every one of these mismatches is cheaper to catch as a Phase 2 requirement than to rediscover during a later spec-audit or release regression.

## Coverage Targets

| Subsystem | Target | Why |
|-----------|--------|-----|
| `bin/run_playbook.py` documentation-state helpers and phase gates | 95% | This file decides whether the run is docs-backed, whether Phase 2 may begin, and what operators are told before the rest of the playbook even starts. |
| `bin/reference_docs_ingest.py` and `bin/bootstrap_self_audit_docs.py` | 90% | Evidence-tier drift here silently changes the factual basis of self-audit and docs-backed runs without producing a hard crash. |
| `bin/run_state_lib.py` Phase 1 validation | 90% | A shallow `EXPLORATION.md` can poison every later phase if the validator allows it through. |
| `bin/archive_lib.py` summary extraction | 85% | Archive metrics drive replay and longitudinal comparisons; dropped BUG headings turn real findings into false zero-bug histories. |
| `bin/role_map.py` normalization and accounting helpers | 85% | Historical `quality/` output dominates this repo by file count, so the role-map math must keep intrinsic surface accounting honest. |
| `SKILL.md` / `references/` / `phase_prompts/` parity surfaces | 80% | QPB is partly prose-as-product. When prose and code disagree, the skill teaches downstream agents the wrong workflow. |

## Coverage Theater Prevention

1. A test that only checks that a helper returns any value is theater for this repo; the important property is whether multiple surfaces agree on the same classification.
2. A mirroring test that copies one top-level file but never checks `cite/` placement is theater; the bug class here is silent loss of the formal-doc bucket.
3. A gate test that asserts "file exists and is long enough" is theater; the Phase 1 risk is missing exact sections and analytical depth.
4. An archive test that only asserts `BUGS.md` exists is theater; the live risk is losing counts because the parser and canonical heading form diverge.
5. A role-map test that checks only file count is theater; the risk is historical playbook output inflating `code_share` or `skill_share`.

## Fitness-to-Purpose Scenarios

### Scenario 1: Cite-only installs are warned as code-only

**Requirement tag:** [Req: inferred — REQ-001]

**What happened:** Because `docs_present()` and `_evaluate_documentation_state()` in `bin/run_playbook.py` use different predicates, a repository with only `reference_docs/cite/spec.md` can be treated as docs-backed for state recording while still receiving a code-only warning. The operator sees contradictory startup messaging before any exploration begins, and later artifact confidence is weakened even when formal docs are actually present.

**The requirement:** Cite-only plaintext documentation must count as docs-backed input on every startup surface.

**How to verify:** Run `python3 -m unittest quality.test_functional.SpecRequirementTests.test_req_001_treats_cite_only_docs_as_docs_backed_input`.

### Scenario 2: README-only or binary-only trees suppress the wrong warning

**Requirement tag:** [Req: inferred — REQ-002]

**What happened:** `README.md` and binary files like PDFs are operator-local clutter for this workflow, not recognized Phase 1 evidence. If one helper treats them as docs while another does not, the repository flips between docs-backed and code-only interpretations depending on which path was called. That is especially dangerous in installed targets where the operator only sees the warning path.

**The requirement:** Warning helpers, state evaluators, and banners must share one recognized-docs predicate.

**How to verify:** Run `python3 -m unittest quality.test_functional.SpecRequirementTests.test_req_002_uses_one_recognized_docs_predicate`.

### Scenario 3: Nested archival notes silently enter Tier 4 context

**Requirement tag:** [Req: inferred — REQ-003]

**What happened:** `reference_docs/` is supposed to expose a small curated Tier 4 surface, but recursive ingest means a parked `reference_docs/nested/archive/notes.md` can join the Phase 1 prompt budget without any explicit opt-in. The failure is subtle: the run does not crash, but the factual baseline becomes polluted by historical or raw notes that the documented contract never promised to load.

**The requirement:** Tier 4 context must remain limited to the documented top-level plaintext surface unless the contract is explicitly widened.

**How to verify:** Run `python3 -m unittest quality.test_functional.SpecRequirementTests.test_req_003_limits_tier4_ingest_to_top_level_plaintext`.

### Scenario 4: Bootstrap mirroring keeps context docs but drops the citable bucket

**Requirement tag:** [Req: inferred — REQ-004]

**What happened:** `bin/bootstrap_self_audit_docs.py` currently creates `reference_docs/cite/` scaffolding but mirrors only top-level plaintext source files. In a self-audit, the repo can therefore look docs-backed while silently losing the strongest citable evidence surface. Later requirements still read as authoritative, but the proof tier beneath them has been downgraded.

**The requirement:** Bootstrap mirroring must preserve both top-level and `cite/` placement.

**How to verify:** Run `python3 -m unittest quality.test_functional.SpecRequirementTests.test_req_004_preserves_citable_vs_context_placement`.

### Scenario 5: A shallow exploration artifact still unlocks Phase 2

**Requirement tag:** [Req: inferred — REQ-005]

**What happened:** The written skill contract requires exact exploration headings, pattern depth, and candidate-bug balance, but a weaker validator can still certify a long placeholder file. Once that happens, every generated artifact downstream looks complete while resting on an exploration artifact that never carried the promised analysis. The cost is not one bad warning; it is an entire low-recall run that passes the mechanical boundary.

**The requirement:** The mechanical Phase 1 validator must enforce the same mandatory structure the skill says it enforces.

**How to verify:** Run `python3 -m unittest quality.test_functional.SpecRequirementTests.test_req_005_enforces_the_full_phase1_gate_mechanically`.

### Scenario 6: Canonical BUG headings disappear from archived metrics

**Requirement tag:** [Req: inferred — REQ-006]

**What happened:** If archive counting accepts only bare `### BUG-NNN` headings while the rest of the playbook emits `### BUG-NNN: Title`, the run's bug totals collapse to zero even though the bug report itself is canonical. This kind of drift contaminates historical replay metrics and can make a regression look like an improvement.

**The requirement:** Archive counting must parse the same titled BUG heading form that BUGS.md is required to use.

**How to verify:** Run `python3 -m unittest quality.test_functional.SpecRequirementTests.test_req_006_parses_canonical_titled_bug_headings`.

### Scenario 7: Direct role-map output depends on a runner-only repair step

**Requirement tag:** [Req: inferred — REQ-007]

**What happened:** The repo advertises both direct skill execution and runner-driven execution, but the raw Phase 1 role-map writeout can be invalid until a later runner-specific normalization pass happens. That means the same analytical content is valid in one execution shape and invalid in another. For a hybrid project whose orchestration itself is part of the product, that path-dependent validity is a real defect surface.

**The requirement:** Direct and runner-driven paths must converge on the same valid role-map schema before the gate depends on it.

**How to verify:** Run `python3 -m unittest quality.test_functional.SpecRequirementTests.test_req_007_normalizes_direct_phase1_role_maps`.

### Scenario 8: Historical `quality/` output inflates the intrinsic surface

**Requirement tag:** [Req: inferred — REQ-008]

**What happened:** This repository's tracked tree is dominated by prior playbook output. If `compute_breakdown()` lets `playbook-output` leak into `code_share` or `skill_share`, every later scoping decision becomes distorted: the repo looks like it has more intrinsic code or prose than it really does. That mis-sizing propagates into exploration prioritization, project classification, and archive metadata.

**The requirement:** Historical `quality/` artifacts must remain segregated inside `other_share`.

**How to verify:** Run `python3 -m unittest quality.test_functional.SpecRequirementTests.test_req_008_keeps_playbook_output_out_of_intrinsic_surface_accounting`.

## AI Session Quality Discipline

1. Read `quality/EXPLORATION.md`, `QUALITY.md`, and `REQUIREMENTS.md` before changing any documentation-state, gate, archive, or role-map code.
2. Treat `SKILL.md`, `phase_prompts/`, and `references/` as product code when they define operator-visible workflow.
3. Prefer executable evidence over prose claims whenever a requirement depends on exact line content, copied files, or parser coverage.
4. When a contract names a closed set or exact heading list, preserve it mechanically rather than by memory.
5. Update this constitution when a new cross-surface drift mode is discovered.

## The Human Gate

- Deciding whether legacy `docs_gathered/` fallback behavior should remain operator-visible at all.
- Deciding whether direct skill-mode should validate raw role maps or always normalize them first.
- Choosing the long-term product stance for historical archive compatibility if heading formats ever need expansion beyond the canonical form.
- Any intentional broadening of the Tier 4 reference-doc surface beyond top-level plaintext files.
