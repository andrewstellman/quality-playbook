## Summary
load_tier4_context() pulls nested non-`cite/` archives into Phase 1 context instead of limiting Tier 4 to top-level plaintext files.

## Spec reference
- Requirement: REQ-003
- Spec basis: `quality/REQUIREMENTS.md:40-51`
- Behavioral contract quote: "Only top-level plaintext files under `reference_docs/` may be treated as Tier 4 context"

## The code
At `bin/reference_docs_ingest.py:90-93`, `bin/reference_docs_ingest.py:194-227`, `bin/reference_docs_ingest.py:263-276` At `bin/reference_docs_ingest.py:90-93`, `_iter_candidates()` recursively walks the full `reference_docs/` tree. `_collect()` at `bin/reference_docs_ingest.py:194-227` marks every non-`cite/` plaintext file as Tier 4, and `load_tier4_context()` at `bin/reference_docs_ingest.py:263-276` returns all non-cite records directly. That implementation silently widens Tier 4 to nested archival folders that the requirement does not permit.

## Observable consequence
If `reference_docs/` contains a legitimate top-level file such as `top.md` and an archival note such as `reference_docs/nested/archive/notes.md`, Phase 1 receives both documents as Tier 4 context. The nested archive then consumes prompt budget and changes the reviewed evidence set even though the documented ingest surface is top-level-only.

## The fix
The fix keeps formal-doc ingest behavior intact but narrows `load_tier4_context()` to direct children of `reference_docs/`, which is the actual documented Tier 4 surface.
