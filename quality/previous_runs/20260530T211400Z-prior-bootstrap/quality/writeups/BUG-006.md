# BUG-006 Writeup

> Date: 2026-05-08 · Project: QPB

## Summary
_extract_bug_counts() ignores canonical `### BUG-NNN: Title` headings, so archive severity totals undercount real bugs.

## Spec reference
- Requirement: REQ-006
- Spec basis: `quality/REQUIREMENTS.md:119-129`
- Behavioral contract quote: "count bugs from the canonical heading form `### BUG-NNN: Title`"

## The code
At `bin/archive_lib.py:69`, `bin/archive_lib.py:321-338` At `bin/archive_lib.py:69`, `_BUG_HEADING_PATTERN` matches only bare `### BUG-NNN` lines. `_extract_bug_counts()` at `bin/archive_lib.py:321-338` uses that pattern to split `BUGS.md` into segments before it counts severities, so canonical titled headings are skipped before the severity parser ever runs.

## Observable consequence
If an archived run contains a canonical heading such as `### BUG-001: Cite-only docs trigger false code-only warning`, `_extract_bug_counts()` reports zero HIGH bugs even though the bug section and severity line are present. Archive indexes and summaries then under-report the defect count for the run.

## The fix
Allowing an optional `: Title` suffix in `_BUG_HEADING_PATTERN` makes the archive parser accept the same canonical heading form that the rest of the playbook already requires.
```diff
--- a/bin/archive_lib.py
+++ b/bin/archive_lib.py
@@ -66,7 +66,7 @@
 PARTIAL_SENTINEL_NAME = ".partial"
 
 _VERSION_HEADER_PATTERN = re.compile(r"Quality Playbook v([0-9]+(?:\.[0-9]+)+)", re.IGNORECASE)
-_BUG_HEADING_PATTERN = re.compile(r"^###\s+BUG-([A-Za-z0-9]+)\s*$", re.MULTILINE)
+_BUG_HEADING_PATTERN = re.compile(r"^###\s+BUG-([A-Za-z0-9]+)(?::\s+.+)?\s*$", re.MULTILINE)
 _REQ_HEADING_PATTERN = re.compile(r"^###\s+REQ-([A-Za-z0-9]+)", re.MULTILINE)
 _SEVERITY_PATTERN = re.compile(r"\*\*Severity\*\*\s*[:.-]\s*(HIGH|MEDIUM|LOW)", re.IGNORECASE)
 _PHASE_CHECK_PATTERN = re.compile(r"^-\s*\[x\]\s*Phase\s*([0-9a-zA-Z]+)", re.MULTILINE)
```
