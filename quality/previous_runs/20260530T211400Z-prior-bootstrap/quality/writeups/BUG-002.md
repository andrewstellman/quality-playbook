## Summary
docs_present() misclassifies README-only and binary-only docs trees, so startup messaging disagrees with the stored documentation state.

## Spec reference
- Requirement: REQ-002
- Spec basis: `quality/REQUIREMENTS.md:26-38`
- Behavioral contract quote: "share the same recognized-plaintext rules"

## The code
At `bin/run_playbook.py:1568-1574`, `bin/run_playbook.py:1583-1595`, `bin/run_playbook.py:1661-1669` At `bin/run_playbook.py:1568-1574`, `docs_present()` treats any non-dot top-level file as documentation. The recognized-docs helper at `bin/run_playbook.py:1583-1595` skips `README.md`, filters to `.md`/`.txt`, and recurses into `reference_docs/cite/`, while `_evaluate_documentation_state()` at `bin/run_playbook.py:1661-1669` depends on that narrower helper. The warning path therefore uses a broader and inconsistent predicate.

## Observable consequence
With a README-only tree or a binary-only tree such as `reference_docs/spec.pdf`, startup warning logic reports that documentation is present even though the formal-doc banner and stored documentation state classify the same repo as code-only. Cite-only trees fail in the opposite direction, so the operator sees one inconsistent classification surface instead of a single documented rule.

## The fix
Using `_reference_docs_plaintext()` inside `docs_present()` makes the warning helper share the same README/binary/cite/plaintext rules as the other documentation-state surfaces.

--- a/bin/run_playbook.py
+++ b/bin/run_playbook.py
