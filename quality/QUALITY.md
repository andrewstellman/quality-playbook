# Quality Constitution

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.7 — Andrew Stellman
> Date: 2026-05-30 · Project: quality-playbook

## 1. Purpose

QPB's job is to make *other* projects' quality explicit. That makes its own quality unusually load-bearing: a bug in the harness doesn't crash a screen — it silently mis-grades a benchmark run, over-admits paid API concurrency, or reports a wedged run as healthy, and the error is invisible because the output still *looks* like a normal run. Fitness-for-use here (Juran) is not "the tests pass" — it is "every benchmark run reaches a terminal state that matches what actually happened, and the operator is never told more progress or less cost than is real." Quality is built into the run-lifecycle accounting (Deming), not inspected afterward — because by the time a SUMMARY.md is wrong, the AI-CLI subprocesses are gone and the truth is unrecoverable. Avoidable mis-grading is the most expensive defect class (Crosby): it corrupts the benchmark numbers QPB exists to produce.

## 2. Coverage Targets

| Subsystem | Target | Why |
|-----------|--------|-----|
| `plan_runner.py` collector (`collect_harness_run`, `_collect_one_run_detached`, `_retry_pending_runs_once`) | Every state×pid combination has an explicit, tested outcome | A missing combination (PENDING ∧ pid=None) silently grades a waiting run FAILED — REQ-001. This is where the freshest defects live. |
| `inflight_registry.py` slot accounting | Every spawn path reserves→updates→releases symmetrically | An un-updated `pid=0` reservation ages out mid-run and over-admits paid concurrency — REQ-002, REQ-005, REQ-006. |
| `status.py` phase inference | The `_PHASE_ARTIFACTS` map matches the runner's authoritative phase-gate artifact lists exactly | A misattributed artifact over-reports progress and hides a wedged run — REQ-004. |
| `qpb_validate.py` install gate | Block ambiguous installs; never green-light a stale `quality/` | A skipped/fabricated validation is the documented httpx/install-path root cause — REQ-009. |
| `archive_lib.py` / `validate_no_source_edits` | Lossless archival; zero non-`quality/` mutation at run end | Data-loss and source-drift are unrecoverable run failures — REQ-011, REQ-012. |

## 3. Coverage Theater Prevention

Project-specific fake-test patterns to refuse (seen in harness test suites that pass while the integrated behavior is broken):

- **Unit-isolation theater.** Testing `_retry_pending_runs_once` in isolation (as `test_collector_retry_165.py` does) while never running it *through* `collect_harness_run` — the exact gap that hides REQ-001. A test that exercises a helper but never the integrated caller is not coverage of the behavior.
- **Asserting the happy path of a dispatcher.** Verifying `_collect_one_run_detached` grades a COMPLETED run correctly while never feeding it the `pid=None`/PENDING edge combination. Dispatchers must be tested on every input combination, not just the primary case.
- **Comment-as-contract.** Trusting a code comment ("newly-spawned entries have RUNNING state + a pid") instead of asserting the actual returned dict. The comment at `plan_runner.py:2600` is false; a test that quoted it would inherit the bug.
- **Mock-returns-what-it-was-told.** Stubbing `acquire_run_slot` to a no-op and asserting the run launched — proves nothing about the cap (REQ-006).

## 4. Fitness-to-Purpose Scenarios

Each scenario's "How to verify" maps to a `test_functional.py` test.

1. **Starved run graded FAILED on first sweep.** Because `collect_harness_run` submits `_collect_one_run_detached` for *every* entry (`plan_runner.py:2606`) with no PENDING filter, and `_collect_one_run_detached` treats `pid is None` as "process gone → FAILED" (`:2123-2146`), a run that is legitimately waiting for a provider slot is graded FAILED within seconds of the collector starting — defeating the 3600s `ABANDONED_STARVED` deadline that exists to give it an hour. Detection difficulty: high — the run's grading.json says `N/A`/FAILED, indistinguishable at a glance from a real failure. *How to verify:* the orphan-poll dispatch must not produce FAILED for a PENDING/pid=None entry (REQ-001).
2. **Provider cap exceeded after 5 minutes.** Because the retry-launch path omits `update_pid` (`plan_runner.py:2530` vs the compliant `:3078`), a retry-spawned run's slot stays at `pid=0` and ages out after `_PID_ZERO_MAX_AGE_S = 300s` (`inflight_registry.py:341-348`). Real runs take 30–90 min, so ~5 min in the slot frees and another run is admitted — on a metered API this is a silent cost/rate-limit incident. *How to verify:* the registry entry carries the real PID after a retry relaunch (REQ-002).
3. **Status overstates progress by three phases.** Because `_PHASE_ARTIFACTS` maps `QUALITY.md`→Phase 5 and `COMPLETENESS_REPORT.md`→Phase 4 (`status.py:285-316`) although both are Phase-2 outputs (`run_playbook.py:1522-1523`), and `_infer_phase_from_artifacts` returns the highest phase with evidence, a run wedged right after Generate displays as "P5 reconciliation" — so the operator never intervenes. *How to verify:* a Phase-2-only fixture resolves to phase 2 (REQ-004).
4. **Phantom slot from a malformed timestamp.** A `pid=0` registry entry whose `started_at` fails to parse returns active forever (`inflight_registry.py:343-345`) — a permanent phantom that reduces the provider cap by one indefinitely. *How to verify:* such an entry is not perpetually active (REQ-005).
5. **Stale `quality/` green-lit.** If `check_stale_quality_dir` failed to require a fresh `run_start` marker, an adopter could resume a months-old partial run as if active — the documented 2026-05-18 codex failure. *How to verify:* populated `quality/` without a recent marker → blocked (REQ-009).
6. **Supervisor abort clobbered by collector inference.** If `_write_terminal_status` overwrote an existing `terminal_state`, the supervisor's richer ABORTED_PHASE record (real exit_code, phase_aborted) would be replaced by the collector's `FAILED`/exit=-1 inference — the 2026-05-30 retest gap that commit 166 closed. *How to verify:* an existing `terminal_state` is preserved (REQ-008).
7. **Same-second archival abort.** Two runs (or a fast re-run) started in the same UTC second collide on the `YYYYMMDDTHHMMSSZ` archive name, and the second aborts with `ArchiveError` (`archive_lib.py:821-826`). *How to verify:* a collision disambiguates rather than aborting (REQ-011).
8. **Source drift at run end.** A Phase-5 patch left applied (the 2026-05-02 off-rails class) leaves a non-`quality/` file dirty; `validate_no_source_edits` must catch it. *How to verify:* a dirty non-`quality/` path → violation; rename destination-first parsing correct (REQ-012).

## 5. AI Session Quality Discipline

- Read function bodies and cite file:line — no line number, no finding.
- Test the dispatcher on every state×pid combination, not just the primary case.
- Trust the authoritative source (the runner's phase-gate at `run_playbook.py:1522`, the actual returned dict) over a code comment.
- Never modify a file outside `quality/`. Patches go to `quality/patches/` and are reverted after the TDD cycle.
- Probe the test runner (`python3 -c "import pytest"`) before claiming it is unavailable — this is the operator's real machine.

## 6. The Human Gate

- Whether REQ-005 (`pid=0` + malformed `started_at` → active forever) is a deliberate "never mass-reap on parse failure" design choice or a latent phantom-slot risk — needs maintainer judgment (challenge-gated in Phase 5).
- Whether `council_members()` *should* hard-enforce exactly three members or deliberately tolerate operator-chosen rosters (REQ-010).
- Severity calibration on the concurrency-cap breach (REQ-006/REQ-002): a paid-API over-admission is a cost incident, but its severity depends on the operator's budget posture.
