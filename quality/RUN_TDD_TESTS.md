# TDD Verification Protocol: QPB
> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.6 — Andrew Stellman
> Date: 2026-05-08 · Project: QPB

This protocol applies after Phase 3 or Phase 4 confirms a bug. A confirmed bug is not closed until the repo has durable red-phase evidence and, when a fix patch exists, durable green-phase evidence.

## Core rule

Every confirmed bug must produce:

1. an executable regression test in `quality/test_regression.py`
2. a red-phase log showing the test fail against unpatched code
3. a green-phase log showing the test pass after the fix patch, or an explicit `confirmed open` outcome when no fix patch exists
4. a `quality/writeups/BUG-NNN.md` writeup

## Regression test conventions

- Framework: `unittest`
- Red-phase guard: use `@unittest.expectedFailure` on the test method
- Test naming: `test_reg_bug_NNN_<slug>`
- Docstring must include:
  - `BUG-NNN`
  - primary `REQ-NNN`
  - exact `file:line` path under test
  - expected correct behavior

## Red phase

For each confirmed bug:

1. Write the regression test first in `quality/test_regression.py`.
2. Decorate it with `@unittest.expectedFailure`.
3. Run:

```bash
python3 -m unittest quality.test_regression -v > quality/results/BUG-NNN.red.log 2>&1
```

4. Confirm the target test appears as `expected failure`.
5. Record the bug in `quality/results/tdd-results.json`.

## Green phase

If a fix patch exists:

1. Apply `quality/patches/BUG-NNN-fix.patch`.
2. Remove the `@unittest.expectedFailure` decorator from the corresponding test.
3. Run:

```bash
python3 -m unittest quality.test_regression -v > quality/results/BUG-NNN.green.log 2>&1
```

4. Confirm the target test reports `ok`.
5. Update `quality/results/tdd-results.json`.

If no fix patch exists:

- leave the regression test guarded
- record `green_phase: "skipped"`
- set verdict to `confirmed open`

## `tdd-results.json` shape

Write `quality/results/tdd-results.json` with schema version `1.1`.

Root keys:

- `schema_version`
- `skill_version`
- `date`
- `project`
- `bugs`
- `summary`

Each bug record must contain:

- `id`
- `requirement`
- `red_phase`
- `green_phase`
- `verdict`
- `fix_patch_present`
- `writeup_path`

`summary` must include:

- `verified`
- `confirmed_open`
- `red_failed`
- `green_failed`

## Allowed verdicts

- `TDD verified`
- `confirmed open`
- `red failed`
- `green failed`

## Post-write validation

Immediately after writing `tdd-results.json`, reopen it and verify:

1. the required root keys exist
2. every bug record has the required fields
3. enum values are canonical
4. `schema_version` is exactly `1.1`
5. `skill_version` is exactly `1.5.6`

## Writeups

For every bug with red-phase evidence, create `quality/writeups/BUG-NNN.md` containing:

1. Summary
2. Requirement / spec basis
3. Code path and evidence
4. Regression test path
5. Red-phase result
6. Proposed fix with inline diff block
7. Green-phase result or open-status note

## Exit criteria

- No confirmed bug is missing a regression test or an explicit exemption.
- Every bug in `quality/BUGS.md` appears in `tdd-results.json`.
- Every red/green log referenced by the sidecar exists on disk.
