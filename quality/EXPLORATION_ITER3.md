## Finding 1 (CONFIRMED → BUG-007): `capture_phase_yn` reports P3–P6 complete from Phase-2 artifacts

Following the grading data flow: `_collect_one_run_detached` (`plan_runner.py:2238`) calls `capture_phase_yn(transcript, target_dir/"quality")`; the result feeds `RunOutcome.phase_yn`, which `render_summary` prints as the per-run phase grid in `SUMMARY.md`. So `capture_phase_yn` is grading-adjacent, not just cosmetic.

Reading `capture_phase_yn` (`:582-610`): a phase is `Y` if the transcript matches a marker OR the phase's "canonical artifact" exists under `quality/`. The artifact map (`:599-606`):
```
P3 → RUN_CODE_REVIEW.md   P4 → RUN_SPEC_AUDIT.md
P5 → RUN_TDD_TESTS.md     P6 → COMPLETENESS_REPORT.md
```
All four are **Phase-2 Generate outputs** (SKILL artifact contract: the RUN_*.md protocols and the baseline COMPLETENESS_REPORT.md are written in Phase 2). So once Phase 2 finishes, the artifact-presence branch marks P3–P6 `Y` regardless of whether those phases ran. Worse: the non-COMPLETED post-processing at `:2240-2243` only flips `N`→`-`; it never demotes a false `Y`. So a run that wedged after Generate keeps P3–P6 = Y.

**Executed confirmation:** `capture_phase_yn("", phase2_only_quality_dir)` returns `P3=P4=P5=P6=Y` (see `quality/results/BUG-007.red.log`); the fix re-keys to phase-exclusive markers (P3→BUGS.md, P5→results/tdd-results.json, P6→results/gate-report-latest.json, P4→transcript-only) and the test passes (`BUG-007.green.log`).

This is the **same root cause as BUG-004** (`status._PHASE_ARTIFACTS`) but in a *second, independent* function on the grading/summary path — a textbook "the bug has a sibling" finding that unfiltered following-the-data-flow surfaces. Promoted: BUG-007 (MEDIUM, REQ-004), TDD-verified.

## Domain-knowledge questions (answered inline)

- *API-surface inconsistencies between similar methods?* — Yes: two functions (`status._infer_phase_from_artifacts` and `plan_runner.capture_phase_yn`) independently maintain a phase→artifact map, and **both** got the P3–P6 mapping wrong the same way (BUG-004, BUG-007). A shared helper would have prevented the duplicated defect — a design observation for the maintainer.
- *Ad-hoc string parsing of structured formats?* — `council_semantic_check._extract_first_json_array` (BUG-006, found in gap) is the prime example.
- *Inputs a domain expert would try that a developer might not?* — a terse Mode-B transcript (no per-phase prose) against a Phase-2-only `quality/` — the exact trigger for BUG-007.
- *Metadata/config values silently wrong?* — `RunOutcome.phase_yn` (BUG-007) and the live phase number (BUG-004): both can silently overstate progress.
