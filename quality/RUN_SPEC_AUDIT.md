## The Definitive Audit Prompt

Give this prompt identically to three independent AI tools.

---

**Context files to read:**
1. `quality/QUALITY.md`
2. `quality/REQUIREMENTS.md`
3. `quality/EXPLORATION.md`
4. `SKILL.md`
5. `references/review_protocols.md`
6. `references/spec_audit.md`

**Task:** Act as the Tester. Read the actual code in:

- `bin/run_playbook.py`
- `bin/reference_docs_ingest.py`
- `bin/bootstrap_self_audit_docs.py`
- `bin/run_state_lib.py`
- `bin/archive_lib.py`
- `bin/role_map.py`

Compare those implementations against the requirements and quality scenarios.

**Requirement confidence tiers:**

Requirements in this baseline are Tier 3 and should be treated as authoritative code-and-contract expectations for this run. If you find a divergence, classify it directly; do not downgrade it merely because the current baseline has no Tier 1/2 citation.

**Rules:**

- ONLY list defects.
- For EVERY defect, cite file and line number(s).
- Before claiming missing, grep the codebase.
- Before claiming a behavior exists, read the function body.
- Classify each finding as `MISSING`, `DIVERGENT`, `UNDOCUMENTED`, or `PHANTOM`.

**Project-specific scrutiny areas:**

1. Read `docs_present()`, `_reference_docs_plaintext()`, `_evaluate_documentation_state()`, and `formal_docs_guard_banner()` in `bin/run_playbook.py`. Do they describe the same repo state the same way?
2. Read `load_tier4_context()` and the `_collect()` walk in `bin/reference_docs_ingest.py`. Can nested archival folders join Tier 4 context despite the documented top-level-only surface?
3. Read `bin/bootstrap_self_audit_docs.py:main()`. Does bootstrap mirroring preserve `docs_gathered/cite/` material?
4. Read `validate_phase_artifacts(..., 1)` in `bin/run_state_lib.py`. Does the mechanical validator enforce the exploration shape that Phase 2 says it requires?
5. Read `_BUG_HEADING_PATTERN` and `_extract_bug_counts()` in `bin/archive_lib.py`. Can canonical titled BUG headings disappear from archive summaries?
6. Read `normalize_role_map_for_gate()` and `compute_breakdown()` in `bin/role_map.py`. Do direct-mode and runner-driven role-map paths converge before the gate depends on them?
7. Compare the role taxonomy in `bin/role_map.py` with the inventory expectations captured in `quality/EXPLORATION.md`. Does historical `quality/` output remain isolated from intrinsic surface accounting?
8. Use the QUALITY.md scenarios as prosecution evidence. If code behavior undercuts a scenario, treat that as a defect, not as a reason to lower the standard.

**Output format:**

### `path/to/file.py`
- **Line NNN:** `MISSING` / `DIVERGENT` / `UNDOCUMENTED` / `PHANTOM` [Req: inferred — `REQ-NNN`] Description. Spec says: ... Code does: ...

## Pre-audit docs validation (required triage section)

The triage summary produced after the three reports must always include a `## Pre-audit docs validation` section.

For this run, start with this expectation:

- `reference_docs/cite/` is empty beyond `.gitkeep`, so the audit baseline is the in-repo playbook contract plus explored code behavior.
- If any auditor consults populated `reference_docs/` content beyond that scaffold, they must record which files they used and spot-check 2 to 3 factual claims against the code.

If a claim is spot-checked, write it in this format:

```text
Claim: "..."
Actual line NNN: `...`
Result: CLAIM IS TRUE / CLAIM IS FALSE
```

## Council status

The triage header must record all three participants and note any timeout or unusable report. Do not substitute stale results from prior runs.

## Verification probes

When auditors disagree on a factual claim:

1. Write a read-only verification probe.
2. Make the probe executable evidence, not prose.
3. Save the probe assertions to `quality/spec_audits/triage_probes.sh` or another executable file in `quality/spec_audits/`.

Example shape:

```bash
python3 - <<'PY'
from pathlib import Path
text = Path('bin/archive_lib.py').read_text(encoding='utf-8')
assert 'BUG-001:' in '### BUG-001: Example'
assert 'BUG-([A-Za-z0-9]+)\\s*$' not in text
PY
```

## Triage categories

Each confirmed finding must be categorized as one of:

- `Spec bug`
- `Design decision`
- `Real code bug`
- `Documentation gap`
- `Missing test`
- `Inferred requirement wrong`

Any finding categorized as `Real code bug` must flow into:

- `quality/BUGS.md`
- `quality/patches/BUG-NNN-regression-test.patch`
- `quality/patches/BUG-NNN-fix.patch` if a fix is proposed
- `quality/test_regression.py`

## Output locations

- Individual auditor reports: `quality/spec_audits/YYYY-MM-DD-<model>.md`
- Triage summary: `quality/spec_audits/YYYY-MM-DD-triage.md`
- Verification probes: `quality/spec_audits/triage_probes.sh`
