# Spec Audit Protocol — Council of Three

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.7 — Andrew Stellman
> Date: 2026-05-30 · Project: quality-playbook

Three independent AI auditors review the harness run-lifecycle code against `quality/REQUIREMENTS.md`. Default roster (`bin/council_config.DEFAULT_COUNCIL_MEMBERS`): `claude-opus-4.7`, `gpt-5.5`, `claude-sonnet-4.6`. Each runs a full independent audit; cross-reference catches what any one misses.

## Audit prompt (copy-pasteable)

> You are auditing the QPB Test Harness run-lifecycle code against the requirements in `quality/REQUIREMENTS.md`. For each requirement, read the cited code (file:line) and record SATISFIED / VIOLATED / UNCLEAR with a code-path trace. Guardrails: line numbers mandatory; read function bodies; a code-path trace showing a behavioral violation IS sufficient to confirm — do NOT demand runtime evidence. Pay special attention to the `manifest.json ⇄ inflight_registry ⇄ status.json` triangle and the two run-launch paths (orchestrator `_wrapped` vs collector `_retry_pending_runs_once`). Output a per-REQ verdict table + a findings list.

## Secondary emphasis lenses

- Auditor 1 — concurrency / resource lifecycle (registry slot accounting, REQ-002/005/006).
- Auditor 2 — dispatcher return-value correctness (terminal-state classification, REQ-001/008).
- Auditor 3 — enumeration completeness + cross-file consistency (REQ-004, REQ-002×006).

## Pre-audit docs validation

`reference_docs/cite/` is empty → **0 Tier 1/2 formal docs** (Spec-Gap run). Auditors use the source tree (Tier 3) + Tier-4 `reference_docs/` context (esp. `22_council_of_three.md`, `32`/`33` v1.5.7 chronicles) as the baseline. There are no Tier 1/2 citation excerpts to spot-check; spot-checks instead extract from code at the cited lines (e.g., "confirm `_retry_pending_runs_once` contains no `update_pid` call").

## Triage

Merge findings by confidence. **Minority-finding rule:** any finding flagged by only one auditor gets a re-investigation with an explicit CONFIRMED/FALSE-POSITIVE determination. **Triage must not raise the bar above code-path analysis** — a trace with file:line confirms. Every probe writes an executable assertion to `quality/spec_audits/triage_probes.sh` citing exact line contents (e.g., `grep -q "update_pid" <(awk '/_retry_pending_runs_once/,/^def /' bin/harness/plan_runner.py) || echo "CONFIRMED REQ-002: no update_pid in retry path"`).

## Effective-council gating

If fewer than 3 auditors return usable reports AND the audit includes the enumeration check (REQ-004) or any carried-forward seed, do not conclude "no defect" for those without executed mechanical proof — escalate to NEEDS VERIFICATION and run the mechanical check.

## Layer-2 semantic citation check

No Tier 1/2 REQs exist → `quality/citation_semantic_check.json` is written with an empty `reviews[]` (valid no-op for a Spec-Gap run).

## Output

Per-auditor reports at `quality/spec_audits/2026-05-30-auditor-{1,2,3}.md`; triage synthesis at `quality/spec_audits/2026-05-30-triage.md` (with the mandatory `## Pre-audit docs validation` section). Confirmed code bugs are added to the PROGRESS.md cumulative BUG tracker with source "Spec Audit".
