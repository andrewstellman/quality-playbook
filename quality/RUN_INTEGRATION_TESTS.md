# Integration Test Protocol

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.7 — Andrew Stellman
> Date: 2026-05-30 · Project: quality-playbook

## Working directory

All commands run from the QPB repo root using **relative paths**. Never `cd` to an absolute path. Real pytest must be used — the repo's local `pytest/` shim (stdlib-only compat, no `pytest.mark`) shadows real pytest when cwd is the repo root, so invoke integration commands with the console script `pytest` (which does not add cwd to `sys.path`) or run from a scratch dir passing the absolute test path: `(cd /tmp && python3 -m pytest <abs-path>)`.

## Safety constraints

- These tests exercise the harness end-to-end against **fake/stub AI-CLIs**, never real metered APIs. Set `QPB_HARNESS_PENDING_DEADLINE_S` and `QPB_HARNESS_PID0_MAX_AGE_S` low so timing paths run fast.
- No test may spawn a real `claude`/`codex`/`copilot` subprocess. Use the harness's existing test doubles in `bin/tests/harness/`.
- No source mutation outside `quality/`.

## Pre-flight

For each group, confirm discovery before recording: `(cd /tmp && python3 -m pytest <abs-path-to-test> --collect-only -q)` must list ≥1 test. If discovery fails with a build/import error, record `"pre_flight_error": "environment"` and stop — do not edit selectors.

## Execution UX

(1) Print the matrix as a numbered table before running. (2) Emit `✓`/`✗`/`⧗` per group. (3) Print a summary table + a SHIP / FIX BEFORE MERGE / BLOCK recommendation.
