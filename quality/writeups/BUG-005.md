## Summary
validate_phase_artifacts(..., 1) accepts structurally shallow exploration files that the Phase 2 gate says must be rejected.

## Spec reference
- Requirement: REQ-005
- Spec basis: `quality/REQUIREMENTS.md:66-79`
- Behavioral contract quote: "reject `quality/EXPLORATION.md` files that omit the exact mandatory sections"

## The code
At `bin/run_state_lib.py:171-198`, `SKILL.md:1260-1273` At `bin/run_state_lib.py:171-198`, the Phase 1 validator checks only file existence, a 120-line minimum, and the presence of any findings-style heading. The stronger contract in `SKILL.md:1260-1273` requires exact sections and analytical minima, so the runtime validator is materially weaker than the gate it is supposed to enforce.

## Observable consequence
A placeholder `quality/EXPLORATION.md` with 120 lines and a single findings heading passes mechanical validation even though it omits required sections such as `## Quality Risks`, `## Pattern Applicability Matrix`, and the deep-dive quota. Later phases can therefore proceed on an exploration artifact that the written Phase 2 gate explicitly says is incomplete.

## Depth judgment
This defect is easy to miss because the immediate validator call returns success and the shallow file looks mechanically complete. The impact only becomes obvious when later phases trust the artifact shape: generation, review, and audit all inherit a structurally weak exploration baseline, and the run can look "Phase 1 complete" even though the documented gate criteria were never satisfied.

## The fix
The fix adds the missing heading checks, enforces a minimum number of pattern deep dives, and requires `PROGRESS.md` to mark Phase 1 complete before the validator returns success.
