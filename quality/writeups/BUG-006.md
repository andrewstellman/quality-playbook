# BUG-006 — Greedy JSON-array extraction drops a valid Council response with trailing bracketed prose

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.7 — Andrew Stellman
> Date: 2026-05-30 · Project: quality-playbook

## 1. Summary
`council_semantic_check._extract_first_json_array` (`bin/council_semantic_check.py:319-343`) uses a **greedy** regex `\[[\s\S]*\]` (first `[` to *last* `]`) but its docstring promises the "first balanced block / outermost that parses." A valid Council member response whose trailing prose contains any `]` (e.g. "see item [2]") fails to parse, so `parse_member_response` raises `SemanticCheckError` and that reviewer's verdicts are dropped.

## 2. Spec reference
Tier-3. The function's own docstring ("find the first `[...]` balanced block", "outermost `[...]` that parses") + REQ-010 (Council resolution must keep the Layer-2 majority well-defined). Dropping a reviewer breaks the ≥3-reviews-per-Tier-1/2-REQ rule (schemas.md §9.4).

## 3. The code
`_JSON_ARRAY_PATTERN = re.compile(r"\[[\s\S]*\]")` is greedy. The fallback does a single `json.loads(match.group(0))`; when a `]` appears after the array, the match runs past the array's closing bracket, `json.loads` fails, and the function returns `None`. `parse_member_response` (`:268-272`) treats `None` as a fatal "response does not contain a JSON array."

## 4. Observable consequence
Real AI Council members routinely append explanatory prose. On a **with-docs adopter run** (Tier 1/2 REQs present), a model response like `[{...}]\nNote: see [2].` is rejected → that reviewer contributes zero verdicts → the gate's "<3 reviews for a Tier 1/2 REQ → FAIL" rule (schemas.md §9.4 / §10 invariant #17) fails the whole run. That is a **false audit failure** — the run is blocked by a parser bug, not by anything wrong in the audited code. (No-op on Spec-Gap runs like this self-audit: zero Tier 1/2 REQs, the semantic check is skipped — which is exactly why the baseline didn't surface it.)

## 5. Depth judgment
The fast path (`stripped.startswith("[")` + whole-text parse) masks the bug for responses that are *pure* JSON arrays with no trailing text. The bug only bites prose-wrapped responses with a trailing `]` — common from chatty models, invisible in fixture tests that feed clean arrays.

## 6. The fix
```diff
--- a/bin/council_semantic_check.py
+++ b/bin/council_semantic_check.py
@@ _extract_first_json_array fallback
-    # Fallback: find the outermost `[...]` that parses.
-    match = _JSON_ARRAY_PATTERN.search(text)
-    if not match:
-        return None
-    try:
-        return json.loads(match.group(0))
-    except json.JSONDecodeError:
-        return None
+    # Fallback (BUG-006 fix): find the FIRST balanced `[...]` substring
+    # that parses as JSON, scanning bracket depth (string-aware) instead
+    # of greedily matching to the last `]`.
+    start = text.find("[")
+    while start != -1:
+        depth = 0; in_str = False; esc = False
+        for i in range(start, len(text)):
+            c = text[i]
+            if in_str:
+                if esc: esc = False
+                elif c == "\\": esc = True
+                elif c == '"': in_str = False
+            elif c == '"': in_str = True
+            elif c == "[": depth += 1
+            elif c == "]":
+                depth -= 1
+                if depth == 0:
+                    try: return json.loads(text[start:i + 1])
+                    except json.JSONDecodeError: break
+        start = text.find("[", start + 1)
+    return None
```
