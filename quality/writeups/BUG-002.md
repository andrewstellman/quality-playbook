# BUG-002 — Collector retry-launch omits update_pid (phantom pid=0 slot → cap breach)

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.7 — Andrew Stellman
> Date: 2026-05-30 · Project: quality-playbook

## 1. Summary
`_retry_pending_runs_once` (`bin/harness/plan_runner.py:2509-2545`) acquires a `pid=0` slot reservation and spawns the run but never calls `update_pid`. The reservation ages out after `_PID_ZERO_MAX_AGE_S = 300s` (`inflight_registry.py:341-348`) while the real run (30–90 min) is still alive, so the per-provider concurrency cap silently over-admits.

## 2. Spec reference
Tier-3. `CONTRACTS.md` C-06/C-09 + REQ-002: *"any code that calls acquire_run_slot then spawns a run must call update_pid with the launched PID before returning."* The orchestrator path is the authoritative sibling.

## 3. The code
The orchestrator launch path records the PID (`plan_runner.py:3078`, comment "Update the registry with the real PID now that we have it from launch"). The retry path merges the spawned entry (`:2538`) and logs, but has no `update_pid` call anywhere in the function body.

## 4. Observable consequence
Under sustained starvation — the exact condition the retry loop exists for — each retry-spawned run's slot frees ~5 min in. With a per-provider cap of N, the harness can run more than N concurrent AI-CLIs against a metered provider: a cost and rate-limit incident that is invisible until the bill or the 429s arrive.

## 5. Depth judgment
The orchestrator path masks the bug entirely (it calls update_pid), so any test that exercises only the happy launch path passes. The defect lives exclusively on the retry path, which only activates when a provider slot was unavailable at first launch.

## 6. The fix
```diff
--- a/bin/harness/plan_runner.py
+++ b/bin/harness/plan_runner.py
@@ _retry_pending_runs_once, after the manifest merge
             _update_manifest_entry_atomic(
                 manifest_path, pr.index, entry)
+            # BUG-002 fix: record the real PID so the pid=0 reservation made
+            # by acquire_run_slot is converted before it ages out at 300s.
+            _retry_pid = entry.get("pid")

+                _inflight.update_pid(
+                    harness_run_dir=harness_run_dir,
+                    run_index=pr.index, pid=int(_retry_pid))
             if log is not None:
                 log.log(
                     f"retried starved run: "
```
