# BUG-004 — _PHASE_ARTIFACTS misattributes Phase-2 outputs to Phases 4/5

> Generated by [Quality Playbook](https://github.com/andrewstellman/quality-playbook) v1.5.7 — Andrew Stellman
> Date: 2026-05-30 · Project: quality-playbook

## 1. Summary
`status._PHASE_ARTIFACTS` (`bin/harness/status.py:285-316`) maps `QUALITY.md`→Phase 5 and `COMPLETENESS_REPORT.md`→Phase 4, but both are Phase-2 Generate outputs. Because `_infer_phase_from_artifacts` returns the highest phase with evidence, a run that finished only Phase 2 is reported as **Phase 5**.

## 2. Spec reference
Tier-3. The authority is the runner's own Phase-4 prerequisite gate `run_playbook.py:1522-1523` (lists QUALITY.md + COMPLETENESS_REPORT.md among the artifacts that must exist *before Phase 4 starts* — "run Phase 2 first") + the SKILL artifact contract. REQ-004: *"phase inference must never report a higher phase than the one actually completed."*

## 3. The code
`_PHASE_ARTIFACTS` line 304 maps `4: ("COMPLETENESS_REPORT.md",)` and line 306 maps `5: ("QUALITY.md",)`; `_infer_phase_from_artifacts` (`:388`) iterates `sorted(..., reverse=True)` and returns the first hit. The status.py comments even cite wrong source lines (3307-3309 is the INDEX payload stub, unrelated).

## 4. Observable consequence
An operator watching `qpb_harness status` for a run wedged right after Generate sees "P5 reconciliation" and does not intervene (UC-04). Observability-only (no run-outcome corruption) but it actively misleads the human-in-the-loop decision.

## 6. The fix
```diff
--- a/bin/harness/status.py
+++ b/bin/harness/status.py
@@ _PHASE_ARTIFACTS
-    2: ("REQUIREMENTS.md", "CONTRACTS.md", "COVERAGE_MATRIX.md"),
+    2: ("REQUIREMENTS.md", "CONTRACTS.md", "COVERAGE_MATRIX.md",
+        "QUALITY.md", "COMPLETENESS_REPORT.md"),
-    3: ("RUN_CODE_REVIEW.md", "BUGS.md"),
+    3: ("BUGS.md",),
-    4: ("COMPLETENESS_REPORT.md",),
+    4: (),  # spec audit has no fixed-path single-file marker; not artifact-inferable
-    5: ("QUALITY.md",),
+    5: ("results/tdd-results.json",),
```
Full patch: `quality/patches/BUG-004-fix.patch` (applies cleanly). Rationale: under-report beats over-report — REQ-004 forbids reporting *higher* than completed.

`test_bug_004_phase2_artifacts_resolve_to_phase2` builds a Phase-2-only `quality/` and asserts `_infer_phase_from_artifacts → phase 2`. Unpatched: FAIL (returns 5; `BUG-004.red.log`). Patched: PASS (`BUG-004.green.log`).
