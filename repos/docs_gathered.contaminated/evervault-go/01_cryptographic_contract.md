## Context

Evervault Encryption (EES) is a **hybrid** scheme: per-payload AES-256-GCM data encryption, with the per-payload AES key derived via ECDH from an **ephemeral** P-256 keypair (generated by the SDK) and the App's static P-256 public key (fetched from Evervault's API).

### 1. Key fetch (`client.go`)

On `MakeClient(appUUID, apiKey)`, `Client.initClient` calls `GET <EvAPIURL>/cages/key` and parses the JSON response:

```go
type KeysResponse struct {
    TeamUUID                string
    Key                     string
    EcdhKey                 string
    EcdhP256Key             string  // base64, compressed (33 bytes)
    EcdhP256KeyUncompressed string  // base64, uncompressed (65 bytes, 0x04 || X || Y)
}
```

The compressed and uncompressed P-256 public keys are stored on the `Client`. The compressed form is used as part of the per-message AAD; the uncompressed form is used as the ECDH peer in `ecdh.P256().NewPublicKey(...)`.

**Trust root for the key fetch:** standard TLS PKI to `https://api.evervault.com` (the default `EvAPIURL`). There is no certificate pinning. There is no signed key bundle. The API key is sent in headers (per `client.go`).

### 2. Per-message encryption (`evervault.go` → `internal/crypto/crypto.go`)

For each `Encrypt*` call:

1. Generate fresh ephemeral P-256 keypair: `ephemeralECDHKey, err := ecdh.P256().GenerateKey(rand.Reader)`.
2. Load App's public key: `appPubKey, err := ecdh.P256().NewPublicKey(c.p256PublicKeyUncompressed)`.
3. Perform ECDH: `shared, err := ephemeralECDHKey.ECDH(appPubKey)`.
4. Derive AES key (`DeriveKDFAESKey`): SHA-256 over `sharedECDHSecret || 0x00000001 || ANS1EncodedEphemeralPublicKey`. The ANS1 prefix is a hard-coded SubjectPublicKeyInfo OID/params prefix for `prime256v1` followed by the uncompressed ephemeral public key. **No HKDF, no salt, no info parameter — just a single SHA-256 hash with the NIST SP 800-56A "Concatenation KDF" counter constant `0x00000001`.**
5. Compress the ephemeral public key (`CompressPublicKey`): 1 prefix byte (`0x02` or `0x03` by Y-parity) + 32-byte X coordinate.
6. Build metadata (MsgPack-ish hand-encoded): a 2- or 3-item map of `{eo: 9 (Go SDK origin), et: uint32 unix-seconds timestamp, dr?: role string}`.
7. Build the AAD (`CreateV2Aad`): 1 version-byte (`(datatype << 4) | 1`) || ephemeralPublicKey || appPublicKey. This binds the ciphertext to both peers and to the declared datatype.
8. Generate 12-byte nonce from `crypto/rand`.
9. AES-256-GCM seal: `aesgcm.Seal(nil, nonce, metadataLen||metadata||value, v2Aad)`.
10. Emit "ev format" string: `ev:QkTC:[number:|boolean:]Base64(nonce):Base64(compressedEphemeralPubKey):Base64(ciphertext||tag):$`.

### 3. Per-message format details

Wire format from `evFormat()`:
```
ev:QkTC:[number:|boolean:]<base64 IV>:<base64 ephemeral pubkey>:<base64 ciphertext>:$
```
- Version tag `QkTC` is hard-coded; corresponds to v2 of the Evervault Encryption Scheme.
- Base64 is **stripped of padding** via `base64EncodeStripped`.
- Datatype-specific prefixes `number:` and `boolean:` are present only for non-string types.

### 4. Decryption

The SDK does NOT decrypt locally. `Client.DecryptString/Int/Float64/Bool/ByteArray` calls a private `decrypt(encryptedData string)` that POSTs the token to Evervault's API. E3 inside an AWS Nitro Enclave reconstructs the AMK from Shamir shares, decrypts the App's AES-wrapped ECDH private key, redoes the ECDH, redoes the KDF, and AES-GCM opens the ciphertext under the same AAD. The plaintext comes back over TLS.

### 5. Cage / Enclave attestation crypto (separate channel)

Connection establishment for `EnclaveClient`:
1. TCP dial the enclave host.
2. Run a TLS handshake with `InsecureSkipVerify: false`, `MinVersion: TLS 1.2`, `ServerName: <enclave-hostname>`.
3. Extract `cert := tlsConn.ConnectionState().PeerCertificates[0]`.
4. Fetch (or read from cache) a Nitro attestation document. The document is parsed by `nitrite.Verify` with `nitrite.VerifyOptions{CurrentTime: time.Now()}` and the `SignatureOK` flag is checked.
5. Compute `pubKeyBytes := x509.MarshalPKIXPublicKey(cert.PublicKey)`.
6. Compare `bytes.Equal(pubKeyBytes, remoteAttestationDoc.UserData)` — the enclave is expected to embed its TLS public key in the `UserData` field of the attestation document.
7. Verify PCRs against caller-supplied expected PCR sets.

The cache (`internal/attestation/attestation_cache.go`) polls `https://<enclave-domain>/.well-known/attestation` on `AttestationPollingInterval` (default 120s, env `EV_ATTESTATION_POLLING_INTERVAL` or legacy `EV_CAGES_POLLING_INTERVAL`).

### 6. Outbound Relay TLS

`relay.go` builds an `http.Client` whose `Transport` proxies to `RelayURL` (default `https://relay.evervault.com`), with `Proxy-Authorization: <api-key>`. TLS to the proxy uses the system cert pool plus a custom CA cert fetched from `EvervaultCaURL` (`https://ca.evervault.com`). `InsecureSkipVerify: false`, `MinVersion: TLS 1.2`. No attestation at this layer.

## Cryptographic guarantees the SDK is claiming

| Property | Claim | Mechanism |
| --- | --- | --- |
| Confidentiality of plaintext | YES | AES-256-GCM under a key derived from ECDH(ephemeralSecret, AppPublicKey). |
| Integrity of plaintext | YES | AES-GCM auth tag (16 bytes). Any tampering with ciphertext, nonce, or AAD causes E3 to reject the open. |
| Non-malleability | YES (via AES-GCM). |
| Forward secrecy w.r.t. the ephemeral key | YES per-payload. The ephemeral private key is generated fresh per `Encrypt*` call inside `getAesKeyAndCompressedEphemeralPublicKey` and discarded after the call returns. |
| Binding to declared datatype | YES via v2 AAD: the datatype byte is in the AAD, so a `boolean`-tagged ciphertext cannot be re-parsed as a `string`-tagged ciphertext without breaking the tag. |
| Binding to App public key | YES via v2 AAD: the App's compressed public key is included in the AAD. |
| Binding to ephemeral public key | YES via v2 AAD AND in the wire format. |
| Binding to metadata (origin, timestamp, role) | YES — the metadata bytes are part of the **plaintext** input to AES-GCM (not the AAD), so they are encrypted AND authenticated. |
| Origin (SDK identity) | The metadata contains `eo: 9` for the Go SDK (compare: other SDKs use different origin codes). Visible only after decrypt. |
| Key isolation in client memory | The AES key, the shared secret, and the ephemeral private key are local Go variables and go out of scope after `EncryptStringWithDataRole` returns. There is no explicit zeroing — Go does not provide `mlock` / `explicit_bzero` semantics in the standard library. |
| Server-side key isolation | App private key never leaves the Nitro Enclave (E3). Documented at https://docs.evervault.com/developers/evervault-encryption. |
| Attested channel to Cages / Enclaves | YES, via Nitro attestation document signature verification AND PCR comparison AND TLS-cert-pubkey-in-UserData check. |
| TLS to api.evervault.com | Standard PKI. No pinning. |
| Replay protection | NONE provided by the SDK itself. The encryption timestamp is in the metadata (visible to E3 after decrypt) but the SDK does not consult or enforce it. Replay protection, if needed, is the caller's responsibility (e.g. via Data Roles + dashboard policies). |

## Cryptographic choices summary

- **Curve:** P-256 (`crypto/ecdh` package, hard-coded in `getAesKeyAndCompressedEphemeralPublicKey`).
- **KDF:** SP 800-56A "Concatenation KDF" — single SHA-256 over `sharedSecret || 0x00000001 || ans1EphemeralPubKey`. **No HKDF; no caller-controlled info field.**
- **Symmetric cipher:** AES-256-GCM with random 12-byte nonce from `crypto/rand`.
- **Auth tag:** 16 bytes (default for Go's `cipher.NewGCM`).
- **AAD (v2):** `version_byte || ephemeralPubKey || appPubKey` where `version_byte = (datatype_number << 4) | 1` and `datatype_number ∈ {0=String, 1=Number, 2=Boolean}`.
- **Encoding:** Base64-stripped (no padding).
- **Ephemeral key lifetime:** one `Encrypt*` call.

## Invariants

### Encryption-side

- INV-CRYPTO-1: Every call to `EncryptString*/EncryptInt*/EncryptFloat64*/EncryptBool*/EncryptByteArray*` MUST generate a **fresh** ephemeral P-256 keypair. (Verified in `getAesKeyAndCompressedEphemeralPublicKey`: `ecdh.P256().GenerateKey(rand.Reader)` is called unconditionally inside every encrypt path.)
- INV-CRYPTO-2: The GCM nonce MUST be 12 random bytes from `crypto/rand`. (`nonceSize = 12`, `io.ReadFull(rand.Reader, nonce)` in `EncryptValue`.)
- INV-CRYPTO-3: The same (key, nonce) pair MUST NEVER be reused. With INV-CRYPTO-1 holding (fresh key per call), the (key, nonce) pair is unique by construction even if `rand.Reader` returned a known nonce, because the key is also fresh.
- INV-CRYPTO-4: The AAD passed to GCM MUST be exactly `version_byte || ephemeralPubKey || appPubKey` per `CreateV2Aad`. The AAD MUST NOT be empty.
- INV-CRYPTO-5: The AES key length MUST be 32 bytes (SHA-256 output). `aes.NewCipher(aesKey)` will reject any other length.
- INV-CRYPTO-6: The ephemeral private key MUST go out of scope by the end of the `EncryptString*` etc. call. (No persistence is implemented; relies on Go GC. Not zeroed.)
- INV-CRYPTO-7: The compressed ephemeral public key embedded in the wire format MUST match the public key used in the AAD. (Both come from the same `ephemeralECDHKey.PublicKey().Bytes()` in `getAesKeyAndCompressedEphemeralPublicKey`.)
- INV-CRYPTO-8: The App public key included in the AAD MUST be the compressed form `c.p256PublicKeyCompressed`. The ECDH peer used for shared-secret derivation MUST be the uncompressed form `c.p256PublicKeyUncompressed`. (Both come from the same `KeysResponse` fetched at client init.)
- INV-CRYPTO-9: The `eo` (encryption origin) metadata byte MUST be `0x09` for every value encrypted by this SDK. (`encryptionOrigin = 0x09`.)

### Attestation-side

- INV-ATT-1: The attestation document MUST be verified by `nitrite.Verify` AND `validatedDoc.SignatureOK` MUST be true before any PCR comparison is performed. (Enforced in `[REDACTED]`.)
- INV-ATT-2: The attestation document stored in the cache MUST contain PCR0, PCR1, AND PCR2 (non-nil entries in the `PCRs` map). PCR3+ are not required. (Enforced in `[REDACTED]` since v1.3.2.)
- INV-ATT-3: When verifying PCRs at TLS-dial time, the **received** attestation document's PCR0, PCR1, and PCR2 entries MUST be present, even if the **expected** PCR set only constrains PCR8. (Enforced in `mapAttestationPCRs` via the explicit `if !ok` checks since v1.3.2 — this is the **post-[REDACTED] invariant**.)
- INV-ATT-4: A non-empty expected PCR value MUST equal the corresponding received PCR value. An empty expected PCR value is treated as "don't care" (intentional [REDACTED].PCRs.[REDACTED]`.)
- INV-ATT-5: The TLS peer certificate's public key MUST bytewise equal the attestation document's `UserData` field. (Enforced in `attestCert`.)
- INV-ATT-6: At least one expected PCR set MUST be supplied with at least one non-empty PCR. `ErrNoPCRs` is returned otherwise. (Enforced in `createCagesClient` via `filterEmptyPCRs`.)
- INV-ATT-7: TLS to a Cage/Enclave MUST use `InsecureSkipVerify: false`, `MinVersion: TLS 1.2`, and `ServerName: <cage-or-enclave-hostname>`. (Enforced in `cagesClient` and `enclave.go`.)
- INV-ATT-8: Only TCP is supported as the network type for the attested dial. `ErrUnsupportedNetworkType` is returned for anything else. (Enforced in `createDial`.)

### Key-handling

- INV-KEY-1: The App's private ECDH key MUST never appear in the SDK process. The SDK only ever holds the App's **public** key. (No code path reads any "private" field from `KeysResponse`.)
- INV-KEY-2: The API key (`apiKey`) is stored on the `Client` struct and forwarded as a header (`API-KEY` or `Proxy-Authorization`). It is not used as cryptographic key material directly by the SDK.

## Threat model gaps the SDK does NOT cover

- **No anti-replay.** Identical plaintexts encrypt to different ciphertexts (fresh ephemeral key + fresh nonce), but the SDK does not stop an attacker from replaying a captured ciphertext to E3 for decryption — that defense lives in Evervault's Data Role policies and dashboard config, not in the SDK.
- **No key pinning** for `api.evervault.com`. Compromise of the WebPKI for that hostname compromises the trust path to the App public key.
- **No memory zeroing.** Plaintext, AES key, and shared secret are subject to standard Go GC timing.
- **Attestation cache TOCTOU.** The cache stores a verified document. If the cache's `LoadDoc` is racing with the TLS dial, the dial may use the previous (still-valid) document. This is by design — the document has a validity window enforced by nitrite — but is worth noting.
