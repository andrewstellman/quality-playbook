# URL Builder

The URL Builder subsystem provides a type-safe API for generating URLs from registered route names or patterns, with optional query string support and cryptographic URL signing. It is split between a client-side module (for server-side rendering helpers and Edge templates) and a server-side module (integrated into `Router`).

## Package locations

| File | Role |
|---|---|
| `src/client/url_builder.ts` | `createUrlBuilder` factory — server-side and client-side URL generation |
| `src/client/helpers.ts` | `createURL`, `findRoute` — core URL construction utilities |
| `src/client/types.ts` | `UrlFor`, `LookupList`, `URLOptions`, `ClientRouteJSON` types |
| `src/router/signed_url_builder.ts` | `createSignedUrlBuilder` factory — signed URL generation |
| `src/router/legacy/url_builder.ts` | `UrlBuilder` — deprecated builder class |

The `createUrlBuilder` factory is exported from the sub-path `@adonisjs/http-server/client/url_builder` for use in edge (template) contexts.

## Type-safe route lookup

The URL builder is parameterised by a `LookupList` type representing all registered routes. When `router.generateTypes()` is used in a build step to generate a `RoutesList` type declaration, the builder becomes fully typed:

```ts
type UrlFor<Routes extends LookupList, Options = URLOptions> = {
  (identifier: keyof Routes & string, params?: ..., options?: Options): string
  get(identifier, params?, options?): { url: string; method: string; form: { action, method } }
  post(identifier, params?, options?): { url: string; method: string; form: { action, method } }
  put(identifier, params?, options?): { url: string; method: string; form: { action, method } }
  patch(identifier, params?, options?): { url: string; method: string; form: { action, method } }
  delete(identifier, params?, options?): { url: string; method: string; form: { action, method } }
  method(method: string, identifier, params?, options?): { url: string; method: string; form: { action, method } }
}
```

All verb methods return an object with `url`, `method`, and `form` properties. The `form` property is a convenience object with `action` and `method` fields ready for use in HTML `<form>` elements.

## createUrlBuilder

```ts
const urlFor = createUrlBuilder<RoutesList>(
  routesLoader,           // object or function returning { [domain]: RouteJSON[] }
  searchParamsStringifier // (qs: Record<string, any>) => string
)
```

`routesLoader` is evaluated lazily on first use, so the routes map need not be populated at the time the builder is created. In the `Router` class, it is bound to `() => this.toJSON()`.

Internally, `createUrlForRoute` calls `findRoute(domainsRoutes, routeIdentifier, domain?, method?, disableLegacyLookup=true)` to locate the route, then passes the route's `tokens` to `createURL`. Route lookup in the URL builder always uses `disableLegacyLookup = true` — meaning only route names (not patterns or controller references) are accepted as identifiers.

## createURL (core logic)

```ts
function createURL(
  identifier: string,
  tokens: MatchItRouteToken[],
  stringify: (qs: Record<string, any>) => string,
  params?: any[] | Record<string, any>,
  options?: URLOptions
): string
```

`createURL` iterates the route's `tokens` (produced by `@poppinss/matchit`) and fills in dynamic segments from `params`. Required segments not found in `params` cause an error. The optional `options.qs` is serialized and appended as a query string. The optional `options.prefixUrl` is prepended to the path.

## Router-integrated URL builder

The `Router` instance exposes a `urlBuilder` property set during construction:

```ts
router.urlBuilder.urlFor('users.show', { id: 1 })
// => '/users/1'

router.urlBuilder.signedUrlFor('verify.email', { token: 'abc' }, { expiresIn: '24h' })
// => '/verify/email?token=abc&signature=...'
```

`urlBuilder.urlFor` delegates to `createUrlBuilder`. `urlBuilder.signedUrlFor` delegates to `createSignedUrlBuilder`.

## Signed URLs

`createSignedUrlBuilder` produces URLs with a cryptographic signature appended as a query parameter. Signed URLs can optionally carry an expiry timestamp:

```ts
type SignedURLOptions = URLOptions & {
  expiresIn?: string | number   // human-readable string ('1h', '7d') or milliseconds
  purpose?: string              // scopes the signature to a specific purpose
}
```

The signature is generated by `@boringnode/encryption`. On the receiving end, `request.hasValidSignature()` verifies the signature and, if an expiry is present, checks that the URL has not expired.

## Domain-prefixed identifiers

When two routes in different domains share the same name, the builder resolves ambiguity by prefixing the identifier with the domain:

```ts
router.urlBuilder.urlFor('admin.example.com@users.index')
// routes registered under the 'admin.example.com' domain
```

The `createUrlBuilder` implementation strips the domain prefix before looking up the route and passes the domain to `findRoute` for scoped lookup.

## Legacy builder (deprecated)

`Router.builder()` and `Router.builderForDomain(domain)` return instances of the legacy `UrlBuilder` class. `Router.makeUrl(...)` and `Router.makeSignedUrl(...)` are also retained for backwards compatibility. All legacy APIs are marked `@deprecated` and redirect developers to `@adonisjs/core/services/url_builder`.

## URLOptions

```ts
type URLOptions = {
  qs?: Record<string, any>   // additional query string parameters
  prefixUrl?: string         // prefix to prepend (e.g. 'https://example.com')
  disableRouteLookup?: boolean // skip route registry, treat identifier as raw pattern
}
```

When `disableRouteLookup` is `true`, the identifier is treated as a literal URL pattern string and parsed directly without registry lookup. This mode is available only through `router.makeUrl` and `router.makeSignedUrl` (the legacy API).

## Client-side export

The sub-path export `@adonisjs/http-server/client/url_builder` exposes `createUrlBuilder`, `createURL`, `findRoute`, and associated types. This allows Edge templates, frontend build tools, or other rendering contexts to construct URLs client-side using the same route registry that was serialized during the server build step.
