00_README.md — Project overview: evervault-go is the official Go SDK for Evervault's privacy-preserving compute platform (Cages/Enclaves/Functions/Relay), built around hybrid ECDH-P256 + AES-256-GCM encryption with a Nitro-attested transport layer for user workloads.
01_cryptographic_contract.md — The cryptographic contract: per-call ephemeral P-256 ECDH, SHA-256 concat-KDF to a 32-byte AES key, AES-256-GCM with random 12-byte nonce, v2 AAD binding (datatype || ephemeralPubKey || appPubKey), with decryption delegated to E3.
02_api_contract.md — The public SDK surface: MakeClient/MakeCustomClient, Encrypt/Decrypt per Go primitive, RunFunction, OutboundRelayClient, EnclaveClient/CagesClient, plus the PCRs struct and sentinel errors — and what each entry point guarantees.
03_attestation_and_trust.md — How Cage/Enclave attestation works: nitrite signature verification, PCR comparison via SatisfiedBy, TLS-cert-pubkey-in-UserData binding, fail-closed semantics, and the v1.3.2 changes that patched CVE-2025-64186.
04_invariants.md — The consolidated "MUST" / "MUST NOT" invariants a code review should be checking, named for cross-reference (FRESH-EPHEMERAL-PER-CALL, MISSING-PCR-PRESENCE-CHECK, AAD-BINDS-EPHEMERAL-AND-APP-PUBKEY, ...).
05_known_issues_and_advisories.md — CVE-2025-64186 / GHSA-88h9-77c7-p6w4 in full detail: root cause (pcrNotEqual short-circuit on empty strings), CVSS 8.7, CWE-347, the PR #48 patch, the advisory workarounds, and the disclosure timeline.
06_issue_tracker_themes.md — Six recurring themes from PRs #9-#49: attestation has been rebuilt 3-4 times, wire-format metadata is hand-rolled, type-specific encrypt replaced any-typed encrypt, Functions are not attested, attestation unit-test coverage was thin pre-CVE, and hf/nitrite is the load-bearing external crypto dep.
