# Database Layer

Persistence lives in `internal/db/`. The package is partway through a long-running migration from [XORM](https://xorm.io) to [GORM](https://gorm.io). Newer stores are GORM-based and expose `XxxStore` interface types; older tables continue to use the global `*xorm.Engine`. Both coexist against the same database.

## Supported backends

Selected by `[database] Type` in `getEngine()` in `models.go`:

- `postgres` — `pgx` driver; respects `[database] Schema`.
- `mysql` — TCP or Unix socket; sets `charset=utf8mb4&parseTime=true` and `rowFormat=DYNAMIC`.
- `mssql` — Microsoft SQL Server (deprecated but supported for upgrades).
- `sqlite3` — gated by the `sqlite` build tag; file path from `[database] Path`.

GORM is the canonical engine going forward. `dbutil.OpenDB` configures it with `SkipDefaultTransaction = true`, `SingularTable` naming, UTC time truncated to microseconds, and a dedicated `gorm.log` writer.

## Tables

GORM-native tables are listed in `db.Tables` at the top of `db.go`: `Access`, `AccessToken`, `Action`, `Follow`, `LFSObject`, `LoginSource`.

Legacy XORM tables listed in `models.go`'s `init()`: `User`, `PublicKey`, `TwoFactor`, `TwoFactorRecoveryCode`, `Repository`, `DeployKey`, `Collaboration`, `Upload`, `Watch`, `Star`, `Issue`, `PullRequest`, `Comment`, `Attachment`, `IssueUser`, `Label`, `IssueLabel`, `Milestone`, `Mirror`, `Release`, `Webhook`, `HookTask`, `ProtectBranch`, `ProtectBranchWhitelist`, `Team`, `OrgUser`, `TeamUser`, `TeamRepo`, `Notice`, `EmailAddress`.

`docs/dev/database_schema.md` is generated by `internal/db/schemadoc/` and documents every column, type, primary key, and index for the three primary backends.

## Store interfaces

Each store is a self-contained interface over a `*gorm.DB`:

- `UsersStore` — `Authenticate`, `Create`, `GetByID`, `GetByEmail`, `GetByUsername`, `GetByKeyID`, `GetMailableEmailsByUsernames`, `SearchByName`, `IsUsernameUsed`.
- `AccessTokensStore` — `Create`, `DeleteByID`, `GetBySHA1`, `List`, `Touch`.
- `PermsStore` — `AccessMode`, `Authorize`, `SetRepoPerms`.
- `ReposStore`, `LoginSourcesStore`, `TwoFactorsStore`, `EmailAddressesStore`, `PublicKeysStore`, `LFSStore` follow the same shape.

Package-level singletons (`db.Users`, `db.Repos`, `db.AccessTokens`, …) are wired in `db.go::Init`. Tests substitute mocks generated by `go-mockgen`.

## GORM hooks

Time fields are stored as Unix seconds. Each store type defines:

- `BeforeCreate(tx *gorm.DB) error` — populates `CreatedUnix` from `tx.NowFunc()` when zero.
- `AfterFind(tx *gorm.DB) error` — translates Unix fields back to `time.Time` and computes derived flags like `HasRecentActivity` (7-day window).

## Migrations

`internal/db/migrations/migrations.go` defines a `Migration` interface (`Description()` and `Migrate(*gorm.DB) error`) and an ordered list of `NewMigration("description", fn)` entries. State lives in a single-row `version` table. On startup the runner reads the stored version and replays each registered migration with a higher ordinal. `minDBVersion = 19` at this revision is the floor.

## Error types

Domain errors are defined in `internal/db/errors/` and `error.go`. The convention pairs a typed struct (e.g., `ErrAccessTokenNotExist`) with an `IsErrXxx(err) bool` predicate that unwraps via `github.com/pkg/errors`. Many error types implement the `errutil.NotFound` marker interface so HTTP handlers can translate them into 404s.

## On-disk repositories, backup, and tests

The bare Git repository lives at `<RepositoryRoot>/<owner>/<name>.git`; `RepositoryRoot` defaults to `<APP_DATA_PATH>/repositories`. File operations route through `internal/sync.ExclusivePool` keyed on the repository identifier; helpers wrap `github.com/gogs/git-module`.

`cmd backup` and `cmd restore` operate at SQL + filesystem level: each table goes to JSON alongside compressed copies of the repository root, the avatar directory, the LFS object store, and the attachment directory.

Each store has a `_test.go` neighbor that uses `internal/dbtest/` helpers to spin up an in-memory SQLite database and exercise the store. Cross-store mocks live in `internal/mocks/` and are regenerated per `mockgen.yaml`.
